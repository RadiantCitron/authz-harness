## 1. 목적 및 배경

[ADR 0003](../../../adr/0003-차기-로드맵-범위-개정-비목표-조건부-해제.md) C-4에 따라 Refresh Token을 도입하지 않는 대신, 장기 세션 중 단기 자식 토큰(`T_child_1`)이 만료되었거나 만료가 임박했을 때 오케스트레이터가 아직 유효한 부모 토큰(`T_parent`)을 제시해 새 자식 토큰(`T_child_2`)으로 **재교환(re-exchange)** 하는 흐름을 검증한다.
이때 새 자식 토큰도 부모 토큰의 남은 수명(`exp_parent`), 권한(`scope_parent`), 잔여 예산(`budget_parent_rem`)을 절대 초과할 수 없으며, 부모 토큰 자체가 만료되거나 회수된 뒤에는 재교환이 즉시 차단됨을 증명한다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/authn/exchange/reexchange_test.go` [신규]: 시간 경과에 따른 재교환 성공·부모 잔여 수명 클램핑/초과 거부·부모 만료 후 재교환 거부·부모 없이 자식 토큰 단독 갱신 시도 거부 Table-Driven 테스트
- **무영향**:
  - `ExchangeService`에 부모 없는 우회 갱신 경로를 추가하지 않으므로 기존 보안 경계가 그대로 유지된다.

## 3. 세부 명세

1. **재교환 불변식 확인**:
   - 시각 $t_0$: 부모 토큰(`TTL=30m`), 자식 토큰 1(`TTL=5m`) 발급 → 호출 성공.
   - 시각 $t_1 = t_0 + 6\text{m}$: 자식 토큰 1 만료(`TOKEN_EXPIRED`). 오케스트레이터가 유효한 부모 토큰(잔여 24분)으로 자식 토큰 2(`TTL=5m`, 새 `jti`)를 재교환 발급 → 호출 재개 성공.
   - 시각 $t_2 = t_0 + 28\text{m}$: 부모 잔여 수명이 2분뿐일 때 자식 토큰 3을 `TTL=5m`으로 재교환 요청하면 `ReasonDelegationTTLExceeded`(`ExitAuthzDenied = 12`)로 거부됨. `TTL=2m` 이하로 요청해야만 발급 허용.
   - 시각 $t_3 = t_0 + 31\text{m}$: 부모 토큰 만료 후 재교환 요청 시 `ReasonTokenExpired`(`ExitTokenInvalid = 11`)로 즉시 거부됨.

## 4. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |
|:---:|---|---|
| **TC-030-01** | 자식 토큰 만료 후 유효한 부모 토큰으로 잔여 TTL 이내 재교환 | 새 `jti`를 가진 자식 토큰 2 발급 성공, 감사에 `token.exchanged` 기록 |
| **TC-030-02** | 부모 잔여 수명(2분)보다 긴 TTL(5분)로 재교환 요청 | `ReasonDelegationTTLExceeded`(`12`) 거부 |
| **TC-030-03** | 만료된 부모 토큰으로 재교환 요청 | `ReasonTokenExpired`(`11`) 거부 |
| **TC-030-04** | 만료된 자식 토큰 자신을 `ParentToken`으로 삼아 셀프 연장 시도 | `ReasonTokenExpired`(`11`) 및 `ReasonDelegationSelfLoop`(`12`)로 이중 차단 |
