## 1. 목적 및 배경

단일 장기 MCP 세션(`SessionDriver`) 안에서 연속으로 도구를 호출하는 도중 토큰 만료, Grant 회수·Epoch 증가, 서명 키 회전(`verify-only` 유지) 후 폐기(`retired`), 일회성 토큰 재사용, 만료 후 부모 토큰 기반 재교환이 일어나는 6대 시나리오(`G12`: `E2E-55`~`E2E-60`)를 카탈로그에 구현한다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/harness/catalog/g12_long_running_session.go` [신규]: `E2E-55`~`E2E-60` 6대 시나리오 구현
  - `internal/harness/catalog/catalog.go`: `AllScenarios()`에 `g12Scenarios()` 등록 (총 시나리오 54개 → 60개)
  - `internal/ui/pipeline.go` 및 `internal/ui/explain.go`: `G12` 그룹 관문 표시 및 초보자 해설 추가
  - `internal/cli/run_test.go` 및 `internal/harness/catalog/catalog_test.go`: 전체 시나리오 수(`54` → `60`) 갱신
- **무영향**:
  - 기존 `E2E-01`~`E2E-54` 시나리오 판정 불변.

## 3. 신규 시나리오 명세 (`G12`: 장기 실행 및 토큰 수명 검증)

| ID | 시나리오명 | 토큰 종류 | 세션 내 시계열 흐름 (`SessionDriver`) | 최종 기대 Exit | 기대 감사 (`ExpectedAction` / `ExpectedReason`) |
|:---:|---|---|---|---|---|
| `E2E-55` | 장기 세션 중 토큰 시간 만료 차단 | 세션 토큰 (`MaxCalls: 5`, TTL 5분) | 호출 1(`file_read`, 성공 `0`) → `AdvanceClock(+10m)` → 호출 2(`file_write` 시도) | `11` | `pep.deny` / `TOKEN_EXPIRED` |
| `E2E-56` | 장기 세션 중 실시간 Epoch 증가(킬스위치) 차단 | 세션 토큰 (`MaxCalls: 5`, TTL 10분) | 호출 1(`file_read`, 성공 `0`) → `BumpEpoch("worker-01")` → 호출 2(`file_write` 시도) | `12` | `pep.deny` / `SUBJECT_EPOCH_REVOKED` |
| `E2E-57` | 장기 세션 중 서명 키 회전(유지) 후 폐기(`retired`) 즉시 차단 | 세션 토큰 (`MaxCalls: 5`, `key-v1` 서명) | 호출 1(성공 `0`) → `RotateKey`(`key-v1` `verify-only`, 호출 2 성공 `0`) → `RevokeKey(key-v1)` → 호출 3(`file_write` 시도) | `11` | `pep.deny` / `TOKEN_KEY_RETIRED` |
| `E2E-58` | 장기 세션 내 일회성(`Budget == nil`) 토큰 2회차 재사용 차단 | 일회성 토큰 (`Budget == nil`) | 호출 1(`file_read`, 성공 `0`) → 동일 세션 내 호출 2(`file_write` 시도) | `11` | `pep.deny` / `TOKEN_REPLAY_DETECTED` |
| `E2E-59` | 자식 토큰 만료 후 유효한 부모 토큰 기반 재교환(Re-Exchange) 세션 재개 | 부모(TTL 30분) → 자식 1(TTL 5분) | 호출 1(성공 `0`) → `AdvanceClock(+6m)` → 자식 1 호출(만료 거부 `11`) → 부모 토큰으로 자식 2(TTL 5분) 재교환 → 자식 2로 `file_write` 호출 | `0` | `pep.allow` / `AUTHORIZED` |
| `E2E-60` | 부모 토큰 만료 후 재교환 시도 거부 (수명 상한 우회 차단) | 부모(TTL 10분) → 자식 1(TTL 5분) | 호출 1(성공 `0`) → `AdvanceClock(+15m)`(부모 `exp` 경과) → 부모 토큰으로 자식 2 재교환 시도 | `11` (또는 `12`) | `token.exchange.deny` / `TOKEN_EXPIRED` |

> **주의사항 1 (`E2E-55`~`E2E-57` 토큰 발급)**: 동일 토큰으로 1차 호출이 성공한 뒤 2차·3차 호출에서 만료(`TOKEN_EXPIRED`), Epoch(`SUBJECT_EPOCH_REVOKED`), 키 폐기(`TOKEN_KEY_RETIRED`)를 검증하려면 1차 호출 시 Gate 1 `ReplayLedger`에 소비되지 않도록 반드시 `Budget: &domain.Budget{MaxCalls: 5}`를 부여한 세션 토큰을 사용한다.
> **주의사항 2 (`E2E-60` 종료 코드)**: `ExchangeService.Exchange`는 부모 토큰이 만료되었을 때 `domain.NewError(domain.ReasonTokenExpired, ...)`(`ExitTokenInvalid = 11`)을 반환하고 `token.exchange.deny` 감사를 남기므로 `Expected.ExitCode = domain.ExitTokenInvalid(11)`, `ExpectedAction = "token.exchange.deny"`, `ExpectedReason = domain.ReasonTokenExpired`로 정확히 일치시킨다.
