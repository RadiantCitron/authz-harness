## 1. 목적 및 배경

장기 세션의 만료·회수·키 폐기를 `time.Sleep` 없이 결정론적으로 재현하려면 두 가지가 필요하다.

1. **서브프로세스 시계 오프셋 전파**: Gate 1 검증기는 이미 `VerifyOptions.ClockOffset`을 받고([`verifier.go`](../../../../internal/authn/token/verifier.go) 113~115행), PEP는 `pep.Request.ClockOffset`을 그대로 넘긴다([`gateway.go`](../../../../internal/authz/pep/gateway.go) 249행). 빠진 구간은 **워커 프레임 → `pep.Request`** 와 **하네스 헬퍼·인프로세스 브리지 → 워커 프레임/`pep.Request`** 다.
2. **코어 `time.Now()` 일원화 ([011번 보고서](../../../보고서/011-권한관리_본질_코어파이프라인_안티패턴_및_분산적응형_기본구조_전문가진단_보고서.md) 제안 3)**: 남은 호출은 인가 판정에 쓰이지 않지만(감사 시각·상태 `UpdatedAt`·스냅샷 시각) 결정론적 증거를 위해 주입 시계로 모으고 `TC-130-01`로 고정한다.

**음수 오프셋은 받지 않는다 (T-1)**. 발급자는 `nbf = iat = now`로 서명한다([`issuer.go`](../../../../internal/authn/token/issuer.go) 176~177행). 따라서 음수 오프셋이 하는 일은 「만료된 토큰을 아직 유효한 것으로 만드는 것」뿐이다. 운영 바이너리 `subagent worker`가 stdin 프레임의 음수 값을 받으면 만료 후 거부라는 로드맵 목표를 뒤집는 손잡이가 된다. 양수 오프셋은 `exp`를 앞당길 뿐 어떤 토큰도 더 유효하게 만들지 않는다.

**PDP·PIP에 평가 시각을 넘기는 컨텍스트 배선(`WithEvalTime` 등)은 만들지 않는다 (T-5)**. `Grant.IsActive`는 시각과 무관하고([`grant.go`](../../../../internal/domain/grant.go) 82~84행), PDP의 시계는 감사 타임스탬프에만 쓰인다. PDP에 시각이 필요해지는 15번은 `pdp.Request.Now` 필드로 따로 설계되어 있다.

## 2. 파급 범위와 무영향 근거

- **변경**:
  - [`internal/subagent/protocol.go`](../../../../internal/subagent/protocol.go): `SubagentRequest.ClockOffsetSeconds int64` (`json:"clock_offset_sec,omitempty"`).
  - [`internal/subagent/worker.go`](../../../../internal/subagent/worker.go) `Execute`: `ClockOffsetSeconds < 0`이면 PEP를 부르지 않고 `ExitBadInput(14)`, `Reason = INVALID_ARGUMENTS`로 응답한다. 0 이상이면 `pepReq.ClockOffset = time.Duration(req.ClockOffsetSeconds) * time.Second`.
  - [`internal/cli/pep.go`](../../../../internal/cli/pep.go) `-clock-offset`(149~155행): 파싱 결과가 음수면 `ExitBadInput(14)`와 오류 메시지로 끝낸다. 실제로 파일 작업을 집행하는 운영 CLI이므로 워커 프레임과 같은 규칙을 쓴다([022번](../../../보고서/022-13번로드맵_구조결함_및_진행가능성_검증보고서.md) §5 제안 3, 사용자 승인 2026-11-04). `token verify`·`token exchange`의 `-clock-offset`([`cli/token.go`](../../../../internal/cli/token.go) 204·275행)은 파일 작업을 하지 않고, 음수를 주면 시계 전체가 과거로 가서 이미 만료된 자식이 나올 뿐이므로 바꾸지 않는다.
  - [`internal/harness/catalog/helpers.go`](../../../../internal/harness/catalog/helpers.go): `ActionRequest.ClockOffset time.Duration` 추가. `executeHarnessAction`은 서브프로세스 경로에서 `SubagentRequest.ClockOffsetSeconds = int64(req.ClockOffset / time.Second)`, 인프로세스 경로에서 `pep.Request.ClockOffset = req.ClockOffset`로 넘긴다.
  - [`internal/harness/catalog/g8_mcp_adapter.go`](../../../../internal/harness/catalog/g8_mcp_adapter.go) `inProcSpawnerBridge.Spawn`(145행): 워커와 같은 규칙으로 음수는 `ExitBadInput(14)` 응답, 0 이상은 `ActionRequest.ClockOffset`으로 전달(모드에 따라 판정이 달라지지 않도록).
  - [`internal/orchestrator/spawner.go`](../../../../internal/orchestrator/spawner.go): `SpawnConfig.Clock domain.Clock`(nil이면 `RealClock{}`) 추가. 감사 시각(91·133·221행)은 이 시계를 쓴다. **프로세스 실행 시간 측정(168~170행)은 실제 시간이어야 하므로** 비공개 함수 `measureWall(fn func()) time.Duration` 하나로 옮기고 `TC-130-01` 허용 목록에 둔다.
  - [`internal/authz/pip/service.go`](../../../../internal/authz/pip/service.go): `NewService(store, opts ...Option)`와 `WithClock` 추가, 77행 스냅샷 시각은 주입 시계.
  - [`internal/authz/state/store.go`](../../../../internal/authz/state/store.go): `NewFileStore`에 Clock 옵션 추가(미주입 시 `RealClock{}`). `NewEmptyGrantsState`는 시각을 인자로 받고(27행), `Update`의 `UpdatedAt`(134행)은 저장소 시계를 쓴다. 호출부 `cli/pdp.go`·`cli/grant.go`는 옵션 없이 그대로 동작한다.
  - [`internal/audit/audit.go`](../../../../internal/audit/audit.go) `NormalizeEvent`(65행): 빈 시각 폴백을 `domain.RealClock{}.Now()`로 바꾼다(시계 구현을 통한 명시적 실제 시각).
  - [`internal/app/builder.go`](../../../../internal/app/builder.go): PIP·상태 저장소에 `cfg.Clock`, PDP에 `pdp.WithClock(cfg.Clock)`(현재 185행은 미전달) 주입.
  - [`internal/harness/architecture_test.go`](../../../../internal/harness/architecture_test.go): `TC-130-01` 추가. 대상 패키지 `internal/domain`, `internal/authn/...`, `internal/authz/...`, `internal/orchestrator`, `internal/audit`, `internal/jail`의 비시험 파일에서 `time.Now` 선택자 사용 0건. 허용 목록은 정확히 두 곳: `domain.RealClock.Now`, `orchestrator.measureWall`.
  - `internal/subagent/worker_clock_test.go` [신규]: 오프셋 판정 단위 시험.
- **무변경**: `internal/authn/token`(오프셋 지원이 이미 있음), `pep.Request.ClockOffset`의 음수 허용(인프로세스 시나리오 `E2E-15`가 `-10m`을 쓴다, [`g4_claims_replay.go`](../../../../internal/harness/catalog/g4_claims_replay.go) 151행. 음수 거부는 프로세스 경계인 워커 프레임에서만 한다).
- **무영향**: `ClockOffsetSeconds` 기본값 0과 Clock 미주입 시 `RealClock{}`은 기존 동작과 같으므로 `E2E-01`~`E2E-54` 판정 불변.

## 3. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |
|:---:|---|---|
| **TC-010-01** | TTL 5분 토큰으로 `ClockOffsetSeconds: 0` 워커 호출 | `ExitSuccess(0)` |
| **TC-010-02** | 같은 TTL 5분 토큰으로 `ClockOffsetSeconds: 301` 워커 호출 (`sleep` 0초) | `ExitTokenInvalid(11)` + `TOKEN_EXPIRED` |

| **TC-010-04** | 인프로세스 브리지에 `ClockOffsetSeconds: 301` / `-1` | 각각 `11`(`TOKEN_EXPIRED`) / `14` (서브프로세스 모드와 같은 판정) |
| **TC-010-05** | `go test -v ./internal/harness -run TestArchitectureGuardrails/TC-130-01` | 대상 패키지 비제어 `time.Now` 0건 `PASS` |
