## 1. 목적 및 배경

장기 실행되는 에이전트 세션에서 시간 경과에 따른 토큰 만료·권한 회수·키 폐기를 `time.Sleep` 없이 결정론적으로 재현하려면, 부모 프로세스(MCP 어댑터 또는 오케스트레이터)의 가상 시계 오프셋(`ClockOffset`)이 호출마다 기동되는 자식 서브프로세스 워커까지 정확히 전달되어야 한다 ([006번 보고서](../../../보고서/006-차기로드맵_10_16_타당성_및_단계분할_정밀검토_보고서.md) §3.4).
본 단계에서는 **호출 단위 재검증 원칙(무캐시 불변식)**과 **서브프로세스 간 가상 시계 전파 규약**을 확립한다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/subagent/protocol.go`: `SubagentRequest`에 선택적 `ClockOffsetSeconds int64` (`json:"clock_offset_sec,omitempty"`) 필드 추가
  - `internal/cli/subagent.go` 및 `internal/subagent/worker.go`: 요청 프레임 또는 플래그로 전달된 오프셋이 있을 때 워커 스택의 `Clock`에 반영하도록 배선
  - `internal/subagent/worker_clock_test.go` [신규]: `time.Sleep` 없이 `ClockOffsetSeconds` 주입만으로 자식 워커에서 토큰 만료(`TOKEN_EXPIRED`)가 즉시 발생하는지 검증하는 단위 테스트
- **무영향**:
  - `ClockOffsetSeconds == 0`인 기본 요청은 기존과 동일하게 현재 시각을 사용하므로 기존 시나리오에 영향을 주지 않는다.

---

## 3. 세부 명세

1. **호출 단위 재검증 원칙 (Zero Session Trust Cache)**:
   - `internal/mcp/server.go` 및 `internal/mcp/executor.go`는 이전 `tools/call`에서 성공한 토큰이나 PDP 판정 결과를 세션 필드에 캐시하지 않는다.
   - 모든 `tools/call`은 독립 서브프로세스를 통해 Gate 1(JWKS/Replay/TTL)과 Gate 2(PDP Grant/Epoch/Budget)를 매번 새로 평가한다.
2. **서브프로세스 시계 오프셋 전달**:
   - `SubagentRequest.ClockOffsetSeconds`가 지정된 경우, 워커는 `clock.NewOffsetClock(baseClock, time.Duration(offset)*time.Second)`를 사용하여 Gate 1 토큰 `exp`/`nbf` 검증을 수행한다.

| ID | 입력 | 기대 결과 |
|:---:|---|---|
| **TC-010-01** | TTL 5분 토큰으로 `ClockOffsetSeconds: 0` 워커 호출 | `ExitSuccess(0)` |
| **TC-010-02** | 동일 TTL 5분 토큰으로 `ClockOffsetSeconds: 301` 워커 호출 (`sleep` 0초) | 즉시 `ExitTokenInvalid(11)` + `ReasonTokenExpired` 반환 |
| **TC-010-03** | `ClockOffsetSeconds: -300` (미래 `nbf` 토큰 재현) 호출 | 즉시 `ExitTokenInvalid(11)` + `ReasonTokenNotYetValid` 반환 |
