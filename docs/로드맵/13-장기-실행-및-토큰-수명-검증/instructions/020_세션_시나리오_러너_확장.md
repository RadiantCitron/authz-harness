## 1. 목적 및 배경

단일 `stdio` MCP 세션 연결을 유지한 채 `Step 1(호출 허용) → Step 2(시각 전진 / 권한 회수 / 키 폐기) → Step 3(동일 세션 내 재호출 거부)`를 순차 실행하고 단계별 응답과 감사 로그를 검증할 수 있는 세션 테스트 헬퍼(`SessionHarness`)를 구축한다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/mcp/executor.go`: 테스트 시 가상 시계(`domain.Clock` 또는 오프셋 공급 함수)를 주입받아 `SubagentRequest.ClockOffsetSeconds`에 반영하는 옵션 추가
  - `internal/harness/catalog/session_helper.go` [신규]: 단일 MCP `Server` 스트림 위에서 복수의 `tools/call` 요청과 중간 상태 변이(시계 Advance, Grant Revoke, Epoch Bump, Key Revoke)를 스크립트처럼 실행하는 `SessionDriver` 구현
  - `internal/harness/catalog/session_helper_test.go` [신규]: 세션 내 연속 호출 및 시각 전진 단위 테스트
- **무영향**:
  - 기존 단발성 시나리오(`E2E-01`~`E2E-54`)의 러너 인터페이스는 전혀 변경하지 않는다.

---

## 3. 세부 명세

1. **`SessionDriver` 지원 연산**:
   - `CallTool(name, path, data, token) (*mcp.ToolExecutionResult, error)`: 열린 MCP 세션에 `tools/call` JSON-RPC 요청을 보내고 응답을 수신한다.
   - `AdvanceClock(d time.Duration)`: 세션 드라이버와 연동된 `SimulatedClock`을 `d`만큼 앞으로 감는다.
   - `RevokeGrant(grantID string)`, `BumpEpoch(subject string)`, `RevokeKey(kid string)`: 세션 도중 Zone B 상태를 실시간 변경한다.

---

## 4. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |
|:---:|---|---|
| **TC-020-01** | 한 MCP 세션에서 `CallTool`(성공) → `AdvanceClock(+10m)` → 동일 토큰 `CallTool` | 1차 호출 `IsError == false`, 2차 호출 `IsError == true` (`[TOKEN_EXPIRED]`, `exit code 11`) |
| **TC-020-02** | 한 MCP 세션에서 `CallTool`(성공) → `RevokeGrant` → 동일 토큰 `CallTool` | 1차 호출 `IsError == false`, 2차 호출 `IsError == true` (`[GRANT_REVOKED]`, `exit code 12`) |
