## 1. 목적 및 배경

기존 [`executeMCPCall`](../../../../internal/harness/catalog/g8_mcp_adapter.go)(52행)은 `bytes.NewReader`에 요청 1줄만 넣으므로 `server.Serve`가 1회 응답 후 `io.EOF`로 끝나는 단발 헬퍼다. [`mcp.Server.Serve`](../../../../internal/mcp/server.go)(76행)는 줄 단위로 EOF까지 읽으므로, 입력을 `io.Pipe()`로 열어 두기만 하면 **서버 코드를 바꾸지 않고** 다회 호출 세션이 된다.

이 단계는 `호출 1 → 상태 변화(시간 전진 / Grant 회수 / Epoch 증가 / 키 회전·폐기) → 같은 세션에서 호출 2`를 실행하는 `SessionDriver`를 만든다.

**시간이 흐르는 자리는 하나다 (T-2)**. 샌드박스 시계는 전진하지 않는다(`fixedClock`, 러너에서는 사실상 `RealClock`, [`sandbox.go`](../../../../internal/harness/sandbox.go) 36~42행·[`runner.go`](../../../../internal/harness/runner.go) 200행). 그래서 `SessionDriver`가 누적 오프셋 `offset`을 들고,
- 도구 호출에는 그 값을 프레임에 실어 보내고(아래 §3.2),
- 하네스 프로세스 안에서 일어나는 교환·발급은 `domain.NewOffsetClock(env.MockClock, offset)`을 시계로 한 스택으로 수행한다(아래 §3.3).

**`internal/mcp`는 바꾸지 않는다 (T-9)**. 시간 시뮬레이션은 하네스의 일이고, MCP 어댑터는 `TC-090-01`이 감시하는 운영 경계다. 오프셋은 `Spawner` 데코레이터로 주입하며, MCP 클라이언트의 `tools/call` 인자로는 넣을 수 없다.

## 3. 세부 명세

### 3.1 세션 스트림
1. `clientInR, clientInW := io.Pipe()`, `serverOutR, serverOutW := io.Pipe()`.
2. 고루틴에서 `mcp.NewServer(clientInR, serverOutW, errBuf, mcp.NewSubprocessExecutor(offsetSpawner), nil).Serve(ctx)`를 실행하고, 끝나면 `serverOutW.Close()`한다.
3. `CallTool(toolName string, args map[string]any, token string) (domain.ExitCode, *mcp.JSONRPCResponse, error)`: `clientInW`에 JSON-RPC 1줄을 쓰고 `bufio.Reader(serverOutR)`에서 응답 1줄을 읽는다. 종료 코드는 기존 `exitCodeFromResponse`(115행)를 재사용한다. 요청 `id`는 호출마다 다르게 붙인다.
4. `Close()`: `clientInW.Close()` → 서버가 `io.EOF`로 끝남 → 고루틴 종료를 기다린다.

### 3.2 오프셋 Spawner 데코레이터
- `offsetSpawner{next orchestrator.Spawner, offset func() time.Duration}`의 `Spawn`은 `req.ClockOffsetSeconds = int64(offset() / time.Second)`를 채운 뒤 `next.Spawn`을 부른다.
- `next`는 기존 `newMCPSpawner(env, stack)`(33행)이다. 바이너리가 있으면 서브프로세스 워커, 없으면 `inProcSpawnerBridge`이며, 둘 다 010에서 오프셋을 처리한다.

### 3.3 상태 변화 연산
| 연산 | 구현 |
|---|---|
| `AdvanceClock(d)` | `d < 0`이면 오류(음수 금지는 010과 같은 이유). `offset += d` |
| `RevokeGrant(id)` / `BumpEpoch(sub)` | `stack.PAP.RevokeGrant` / `stack.PAP.BumpEpoch`([`pap/service.go`](../../../../internal/authz/pap/service.go) 129·182행) |
| `RotateKey()` / `RevokeKey(kid)` | `stack.KeyManager.RotateKey` / `RevokeKey`([`keys/manager.go`](../../../../internal/authn/keys/manager.go) 188·256행) |
| `Stack()` | 현재 `offset`이 0이면 기본 스택, 아니면 `app.BuildStack`에 같은 `env` 경로와 `Clock: domain.NewOffsetClock(env.MockClock, offset)`을 준 스택. 재교환·발급은 이 스택의 `ExchangeService`·`TokenIssuer`로 한다. 만든 스택은 `Close()`에서 닫는다 |

- [`g11_budget_downscope.go`](../../../../internal/harness/catalog/g11_budget_downscope.go) 289행의 지역 타입 `offsetClock`은 복제하지 않고 `domain.NewOffsetClock`을 쓴다.

## 4. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |
|:---:|---|---|
| **TC-020-01** | 한 세션에서 예산 토큰(`MaxCalls: 5`, TTL 5분)으로 `CallTool`(1차) → `AdvanceClock(+6m)` → 같은 토큰 `CallTool`(2차) | 1차 `0`, 2차 `11` (`TOKEN_EXPIRED`) |
| **TC-020-02** | 한 세션에서 예산 토큰으로 `CallTool`(1차) → `RevokeGrant` → 같은 토큰 `CallTool`(2차) | 1차 `0`, 2차 `12` (`GRANT_REVOKED`) |
| **TC-020-03** | `AdvanceClock(+6m)` 후 `Stack().TokenIssuer`로 발급한 토큰의 `iat` | 기준 시각 + 6분 (오프셋 스택이 실제로 전진한 시각을 쓴다) |
| **TC-020-04** | `AdvanceClock(-1m)` | 오류 반환, `offset` 불변 |
| **TC-020-05** | `Close()` | 서버 고루틴이 종료되고 `-race`에서 누수·레이스 0건 |
