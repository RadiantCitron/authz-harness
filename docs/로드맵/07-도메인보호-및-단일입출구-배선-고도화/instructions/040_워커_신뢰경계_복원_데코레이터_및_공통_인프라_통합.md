## 1. 목적 (Context & Why)

본 지시서는 감사 보고서에서 지적된 **AP-03(테스트 결함 주입 `--inject-revoke-before-io`를 위해 비신뢰 자식 워커인 `SubagentWorker`에 중앙 권한 상태 저장소 `state.Store` 쓰기 권한을 직접 주입하여 신뢰 경계를 허문 문제)**과 **AP-11(CLI 및 하네스 5곳에 복제된 60줄짜리 서비스 조립 코드, `auditWriter.Close()` 누수로 인한 파일 디스크립터 누수, 3곳에 복제된 `flock + atomic rename` 저장소 로직)**을 구조적으로 해결하는 단계다.

보안 및 아키텍처 불변식에 따라:
1. **비신뢰 워커(Subagent)의 Zone B 쓰기 권한 완전 박탈 (Trust Boundary 복원)**:
   - `internal/subagent/worker.go`에서 `stateStore state.Store` 필드, `SetStateStore` 메서드, 그리고 `Execute` 내부의 `if req.InjectRevokeBeforeIO` 블록을 삭제하여 `internal/subagent` 패키지가 `internal/authz/state`를 import조차 하지 못하도록 차단한다.
   - TOCTOU 경합 테스트(`InjectRevokeBeforeIO`)는 `pep.Gateway` 인터페이스를 감싸는 데코레이터(`pep.WithRevokeBeforeIO(gw, revokerFn)`)로 분리하여, 도메인/워커 코드의 신뢰 경계를 건드리지 않고 외부 배선 조립 시점에만 작동하게 한다.
2. **단일 스택 조립 빌더(`StackBuilder`) 및 안전한 라이프사이클 관리 (`Close()`)**:
   - `cli/pep.go`, `cli/subagent.go`, `cli/token.go`, `pep_test.go`, `harness/catalog/helpers.go` 5곳에 복제된 컴포넌트 조립 보일러플레이트를 공통 스택 빌더로 통합하고, `Close()` 메서드를 통해 열려 있는 `audit.Writer` 핸들을 안전하게 닫아 FD 누수를 제거한다.
3. **공통 원자적 파일 저장소 헬퍼를 통한 3중 중복 제거**:
   - `state.FileStore`, `keys.FileStore`, `token.FileReplayLedger`에 중복 작성된 `syscall.Flock + 임시 파일 쓰기 + os.Rename` 패턴을 공통 유틸리티로 추출한다.

## 3. 세부 설계 및 인터페이스 계약

### 3.1 결함 주입 데코레이터 계약 (`internal/authz/pep/decorator.go`)

```go
package pep

import "context"

// BeforeIOHook 은 결함 주입(TOCTOU 시뮬레이션 등)을 위해 관문 실행 직전에 호출되는 훅 함수 타입이다.
type BeforeIOHook func(ctx context.Context, req Request) error

// WithBeforeIOHook 은 기존 Gateway 를 감싸서 req.InjectRevokeBeforeIO 가 활성화되었을 때만
// 외부에서 주입된 hook 을 실행한 뒤 본래 Gateway.Execute 를 호출하는 데코레이터를 반환한다.
// 이를 통해 SubagentWorker 는 state.Store 의 존재를 전혀 알지 못한다.
func WithBeforeIOHook(next Gateway, hook BeforeIOHook) Gateway
```

> **데코레이터 기반 신뢰 경계(Trust Boundary) 복원 맥락**:
> - 프로덕션 비즈니스 코드인 `SubagentWorker`는 권한 저장소(`state.Store`) 인터페이스의 존재 자체를 완전히 알지 못하며, 오직 상위가 위임해 준 `pep.Gateway`만을 순수하게 실행한다.
> - `--inject-revoke-before-io` 결함 주입은 프로덕션 워커 코드를 더럽히지 않고, 오직 바깥 조립 계층(Composition Root)에서만 인터페이스 데코레이터(`pep.WithBeforeIOHook`) 형태로 주입되는 테스트 격리 패턴이다.
> - 이로써 "비신뢰 자식 워커가 중앙 권한 상태 파일을 직접 수정한다"는 아키텍처 결함(AP-03)을 원천 해소하고 신뢰 경계를 명확히 복원한다.

### 3.2 정화된 `SubagentWorker` 구조체 (`internal/subagent/worker.go`)

```go
package subagent

import "authz-harness/internal/authz/pep"

// SubagentWorker 는 오직 pep.Gateway 만을 보유하며 Zone B state.Store 에 대한 참조를 일절 가지지 않는다.
type SubagentWorker struct {
	gateway pep.Gateway
}

func NewWorker(gateway pep.Gateway) (*SubagentWorker, error)
```

## 4. 사전 점검 및 실패 위험 분석 (Pre-Mortem)

1. **위험: `SubagentWorker`에서 `SetStateStore`를 제거할 때 기존 `worker_test.go` 또는 `subagent_test.go`에서 `SetStateStore`를 호출하던 테스트가 컴파일 에러를 낼 가능성**
   - *방어책*: `pep.WithBeforeIOHook` 데코레이터를 통해 동일한 TOCTOU 주입을 구성하도록 테스트 셋업 헬퍼를 업데이트하고, 필요한 경우 Deprecated 래퍼 없이 깔끔하게 데코레이터 패턴으로 전환하여 AST 검사(`internal/subagent` 내 `internal/authz/state` import 금지)를 통과시킨다.
2. **위험: `harness/catalog/helpers.go`에서 `setupHarnessStack`이 생성한 `auditWriter`를 닫는 시점이 너무 빠르면 시나리오 실행 중 기록이 실패할 가능성**
   - *방어책*: `harnessStack`에 `Close() error` 메서드를 추가하고 각 시나리오의 `Setup` 및 `Execute` 함수 종료 시점(`defer stack.Close()`)에 닫도록 보장한다.

## 5. 4층위 검증 범위 설계

1. **1층위 (정적 아키텍처 검증)**:
   - AST 정적 검사 테스트(`TestSubagent_StrictNoStateStoreImport`)를 추가하여 `internal/subagent` 패키지가 `internal/authz/state`나 `internal/authz/pap`, `internal/authn/keys`를 절대 import하지 않음을 자동 검증.
2. **2층위 (데코레이터 단위 테스트)**:
   - `internal/authz/pep`: `WithBeforeIOHook` 데코레이터를 씌운 상태에서 `InjectRevokeBeforeIO: false`일 때는 훅이 호출되지 않고 `ALLOW(0)`가 나며, `InjectRevokeBeforeIO: true`일 때만 훅이 실행되어 `DENY(12, GRANT_REVOKED)`가 반환됨을 검증.
3. **3층위 (프로세스 격리 및 FD 누수 검증)**:
   - 30개 시나리오를 연속 5회 반복 실행해도 열린 파일 디스크립터 누수나 파일 락 교착이 발생하지 않음을 검증.
4. **4층위 (CLI 통합 검증)**:
   - `authz-harness orchestrate spawn --inject-revoke-before-io ...` 실행 시 자식 프로세스가 종료 코드 `12`(`ExitAuthzDenied`) 및 사유 `GRANT_REVOKED`로 차단됨을 검증.
