## 1. 목적 (Context & Why)

본 지시서는 07번 로드맵의 최종 마감 단계로서, **"테스트는 도메인과 배선을 별개로 테스트할 수 있어야 하고, 수정할 때마다 여기저기서 고장이 나면 절대 안 된다"**는 아키텍처 요구사항을 코드로 영구 고정하는 작업이다.

보안 및 엔지니어링 불변식에 따라:
1. **Track A (무-I/O 순수 도메인 격리 테스트 스위트) 확립**:
   - 디스크 파일(`t.TempDir`), `syscall.Flock`, `audit.JSONLWriter`, `os/exec`를 단 하나도 사용하지 않고 오직 메모리 상의 순수 입력 구조체와 반환값만으로 도메인 규칙(PDP `Epoch + Scope + Grant` 결정표, RFC 8693 Downscoping 부분집합·깊이·순환 검증, `*domain.Error` 매핑)을 검증하는 전용 테스트를 확립한다.
2. **Track B (단일 입구 · 단일 출구 배선 독립 테스트 스위트) 확립**:
   - 복잡한 암호화나 PDP 비즈니스 규칙 대신 가짜(Stub) 도메인 컴포넌트만 꽂아두고, 배선 파이프라인(단일 `TraceID` 스탬핑, 최상위 `Action`/`Decision`/`Reason` 정규화, Pre-Commit Fail-Closed 감사 차단, 해시 체인 연결, 데코레이터 작동)만 독립 검증하는 테스트를 확립한다.
3. **아키텍처 가드레일 정적 검증 테스트(Architecture Fitness Functions) 통합**:
   - 추후 누군가 코드를 수정하더라도 12대 안티패턴(PDP의 파일 I/O import, Subagent의 `state.Store` import, `strings.Contains(err.Error())` 사용 등)이 다시 유입되면 `go test`가 즉시 실패하도록 아키텍처 적합성 테스트를 구축한다.
4. **문서 동기화 및 07번 로드맵 결산(`결과정리및리뷰.md`)**:
   - 최상위 `README.md`, `docs/DEMO_GUIDE.md`의 시나리오 표(특히 `E2E-30` 종료 코드 `15` 등)와 아키텍처 설명을 실제 구현과 100% 일치시키고 전 계층 테스트를 완주하여 07번 로드맵을 마감한다.

## 2. 파급 범위와 무영향 근거 증명 및 검증 구조

```text
+---------------------------------------------------------------------------------------+
|                3-Track Orthogonal Verification & Architecture Guardrails              |
+---------------------------------------------------------------------------------------+
  [Architecture Guardrail Tests] (AST Static Fitness Functions)
    ├── Verify PDP has ZERO os / filepath / jail imports
    ├── Verify Subagent has ZERO state.Store / pap / keys imports
    └── Verify Codebase has ZERO strings.Contains(err.Error(), ...) patterns

  [Track A: Pure Domain Unit Tests]        [Track B: SESE Wiring Pipeline Tests]
    - Zero disk I/O, Zero audit file         - Stub Verifier / Stub PDP / Stub Jail
    - Pure PDP (Epoch + Scope + Grant)       - Single Entry TraceID & Clock binding
    - Pure Downscope Validator               - Single Exit HashChain & Fail-Closed Audit
    - Pure *domain.Error mapping             - Fault Injection Decorators

  [Track C: Full E2E Scenario Harness] (authz-harness run --scenario all)
    - 30 Scenarios (E2E-01 ~ E2E-30) with strict Quad-Assertion & Subprocess isolation
```

## 3. 세부 작업 내역 및 산출물

1. **아키텍처 가드레일 및 Track A / Track B 분리 테스트 구축**:
   - `internal/authz/pdp/pdp_test.go`: 순수 도메인 결정(Epoch + Scope + Grant 조합) 무-I/O 테스트 보강.
   - `internal/authz/pep/gateway_test.go`: 디스크 파일 생성 없이 인메모리 Stub Verifier, Stub PDP, Stub Jail, 인메모리 Audit Recorder만으로 5단계 관문 단락(Short-Circuit), 데코레이터, Fail-Closed 배선을 검증하는 Track B 테스트 추가.
   - AST 기반 아키텍처 적합성 검사 테스트(`TestArchitectureGuardrails`) 작성.
2. **최상위 문서 정합성 동기화**:
   - `README.md` 및 `docs/DEMO_GUIDE.md`에 단일 입구 · 단일 출구(SESE) 배선, 의존성 역전(DIP), 주문·결제 MSA 및 분산 에이전트 매핑 표, `E2E-30` 종료 코드(`15`) 정합성 반영.
3. **07번 로드맵 결산 문서 작성**:
   - `docs/로드맵/07-도메인보호-및-단일입출구-배선-고도화/결과정리및리뷰.md` 작성 및 대시보드/색인 상태 `Done` 갱신.

## 5. 4층위 검증 범위 설계

1. **1층위 (자동화 스크립트 및 보안 스캔)**:
   - `python3 scripts/public_safety_scan.py --tree` (Zero Leakage 통과)
   - `go vet ./...` 통과
2. **2층위 (Track A 순수 도메인 & Track B 배선 독립 테스트)**:
   - `go test -v ./internal/domain/... ./internal/authz/pdp/... ./internal/authn/exchange/...` (Track A 무-I/O 0.1초 내 통과)
   - `go test -v ./internal/authz/pep/... ./internal/audit/...` (Track B 배선 및 해시 체인 통과)
3. **3층위 (동시성 및 경합 검증)**:
   - `go test -race ./...` 전 패키지 Data Race 0건 통과
4. **4층위 (L5 30대 E2E 하네스 완주)**:
   - `./bin/authz-harness run --scenario all` (30/30 `PASS`, 종료 코드 `0`)
   - `./bin/authz-harness run --scenario all --output-format explain` 정상 렌더링 확인
