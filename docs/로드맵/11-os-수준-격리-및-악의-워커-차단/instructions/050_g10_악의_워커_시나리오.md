## 1. 목적 및 배경

PEP를 건너뛰고 OS 시스템콜을 직접 호출하는 악의 워커가 **격리를 껐을 때(대조군, `NoopConfiner`)는 실제로 공격에 성공(`Exit 0`)하지만, 커널 격리를 켰을 때(실험군, `DefaultConfiner`)는 OS 커널에 의해 차단(`Exit 13`, `CONFINEMENT_VIOLATION`)됨**을 한 쌍(Pair)으로 대조 증명하는 G10 그룹 5대 시나리오(`E2E-45`~`E2E-49`)를 구현한다.

| ID | 시나리오명 | 1단계: 대조군(`NoopConfiner`) 검증 | 2단계: 실험군(`DefaultConfiner`) 기대 결과 | 기대 Exit | 기대 감사 (`ExpectedAction` / `ExpectedReason`) |
|:---:|---|---|---|:---:|---|
| `E2E-45` | PEP 우회 Zone A 개인키 직접 읽기 차단 (쌍 대조) | 격리 끔에서 `bypass_read_zone_a` 실행 시 `Exit 0`(읽기 성공) 확인 | 격리 켬에서 커널 `EACCES`/`EPERM`으로 읽기 차단 | `13` | `agent.confined` / `CONFINEMENT_VIOLATION` |
| `E2E-46` | PEP 우회 Workspace 외부 파일 직접 쓰기 차단 (쌍 대조) | 격리 끔에서 별도 대조군 경로 쓰기 `Exit 0` 확인 후 정리 | 격리 켬에서 실험군 외부 경로 쓰기 차단(파일 미생성) | `13` | `agent.confined` / `CONFINEMENT_VIOLATION` |

| `E2E-48` | 손자 프로세스의 커널 격리 상속 및 우회 차단 (쌍 대조) | 격리 끔에서 `bypass_child_read_zone_a` `Exit 0` 확인 | 격리 켬에서 손자 프로세스도 Zone A 읽기 차단 | `13` | `agent.confined` / `CONFINEMENT_VIOLATION` |
| `E2E-49` | 격리 필수 모드 미지원 어댑터 Fail-Closed & 정직한 워커 허용 | `DefaultConfiner` 하에서 정직한 워커 `file:read` `Exit 0` 확인 | `RequireConfinement: true` + `NoopConfiner` 스폰 시 미기동 거부 | `16` | `agent.confined` / `CONFINEMENT_UNAVAILABLE` |

### 대조군 → 실험군 2단계 실행 규약 (Quad-Assertion 정합성 보장)
1. 각 시나리오의 `Execute(ctx, env)`는 **반드시 1단계(대조군)를 먼저 실행한 뒤 2단계(실험군)를 실행**한다.
2. 1단계(대조군)가 기대한 성공(`Exit 0`)을 거두지 못하면 즉시 `return domain.ExitInternalError, fmt.Errorf("control group failed")`를 반환하여 시나리오를 `FAIL` 처리한다 (격리가 없는데도 실패하는 가짜 테스트 방지).
3. `E2E-46`(외부 파일 쓰기)에서 1단계 대조군은 `outside_control.txt`에 쓰고 존재 확인 후 삭제하며, 2단계 실험군은 `outside_target.txt`에 쓰기를 시도하여 실패 후 파일이 존재하지 않음을 검증한다.
4. 2단계(실험군)가 마지막으로 실행되므로 `audit.jsonl`의 최신 이벤트는 실험군의 `Action: "agent.confined"`, `Decision: "deny"`, `Reason: "CONFINEMENT_VIOLATION"`(또는 `CONFINEMENT_UNAVAILABLE`)이 되어 [`assertion.go`](../../../../internal/harness/assertion.go)의 역순 이벤트 탐색과 정확히 일치한다.
