## 1. 목적 및 배경

PEP를 건너뛰고 OS 시스템콜을 직접 부르는 악의 워커가 **격리를 껐을 때(대조군)는 공격에 성공하고, 켰을 때(실험군)는 실패함**을 한 쌍으로 증명한다. 이 단계는 시험 측 모듈(`faultworker`, `harness`, `catalog`, `ui`)만 고친다.

두 가지 원칙을 지킨다.

1. **악의 워커는 프로덕션과 분리된 faultworker에 둔다.** ADR 0003 C-7(개정)과 로드맵 10의 [`faultworker/main.go`](../../../../internal/harness/faultworker/main.go)를 재사용한다. 빌드 태그·`-test-fault` 플래그·심볼 부재 테스트는 쓰지 않는다(020번 보고서 L-2). [`architecture_test.go`](../../../../internal/harness/architecture_test.go) 331행 `TC-040-AG`가 faultworker의 내부 패키지 import 0건을 계속 강제한다.
2. **판정은 부모가 관찰한 사실로만 한다.** faultworker는 관찰을 출력할 뿐이고, 종료 코드나 자기보고는 판정 근거가 아니다(L-3).

## 3. 세부 명세

### 3.1 faultworker 악의 모드 (표준 라이브러리만)

모든 모드는 stdin 요청 프레임을 읽지 않으며, 결과를 stdout 한 줄 `RESULT=ok|err errno=<이름> DATA=<내용>`으로 쓰고 **항상 exit 0**으로 끝난다. 종료 코드로 판정하지 않기 위해서다.

| 모드 | 동작 | 우회 시도 |
|---|---|---|
| `bypass_read_zone_a` | `-target` 파일을 `os.ReadFile`, 내용을 `DATA=`로 출력 | 실패하면 `os.Chmod(디렉터리, 0700)`·`os.Chmod(파일, 0600)` 후 한 번 더 읽음 |
| `bypass_write_outside` | `-target` 경로에 `os.WriteFile` | 실패하면 상위 디렉터리 `Chmod` 후 재시도 |
| `bypass_open_socket` | `net.DialTimeout("tcp", -target, 500ms)` 후 1바이트 쓰기 | — |
| `bypass_child_read_zone_a` | 자기 자신(`os.Executable()`)을 `-mode bypass_read_zone_a -target <같은 값>`으로 실행하고 그 stdout을 그대로 출력 | 손자는 부모의 격리를 상속받는지 확인 |

### 3.2 부모 관찰 오라클

| 공격 | 대조군 성공 조건 (부모 관찰) | 실험군 차단 조건 (부모 관찰) |
|---|---|---|
| Zone A 읽기 | 실행마다 `crypto/rand` 32바이트 hex canary를 `zone_a/canary.txt`에 쓰고, 자식 stdout에 canary **있음** | stdout에 canary **없음**, 부모는 같은 파일을 여전히 읽을 수 있음 |
| 밖 쓰기 | 샌드박스 밖 임시 디렉터리의 `outside_control.txt` **생성됨** (확인 후 삭제) | `outside_target.txt` **미생성** |
| 소켓 | 부모가 `127.0.0.1:0` 리스너를 열고 accept **1건** | deadline(1s) 안에 accept **0건** |

- 조건이 하나라도 어긋나면 `harness.Invariantf(...)`로 반환한다(대조군 실패는 "격리가 없는데도 막힘 = 가짜 시험", 실험군 실패는 "격리가 뚫림"). 10번의 `InvariantViolation` 오라클이 이를 FAIL로 처리한다.
- 실험군 조건이 모두 성립하면 시나리오는 `domain.ExitPathViolation(13)`을 반환한다. 이 코드는 **부모의 판정**이다.

### 3.3 시나리오 명세 (`G10`)

모든 시나리오는 `RequiresSubprocess: true`, `RequiresConfinement: true`이며, G9처럼 자체 스포너를 `env.FaultWorkerPath`로 만든다. 실험군 정책은 `confinement.WorkerPolicy(env.RootDir, env.WorkspaceDir, filepath.Dir(env.StatePath), env.AuditPath)`, 어댑터는 `confinement.Platform()`이다. 대조군은 같은 정책에 `Require: false` + `NoopConfiner{}`다.

| ID | 시나리오명 | 1단계 대조군 | 2단계 실험군 | 기대 Exit | 기대 감사 (`ExpectedAction` / `Decision` / `Reason`) |
|:---:|---|---|---|:---:|---|
| `E2E-45` | PEP 우회 Zone A 개인키 영역 직접 읽기 차단 | canary 유출 관찰 | canary 미유출 관찰 | `13` | `agent.confined` / `allow` / — |
| `E2E-46` | PEP 우회 샌드박스 밖 직접 쓰기 차단 | 대조 파일 생성 관찰 | 대상 파일 미생성 관찰 | `13` | `agent.confined` / `allow` / — |
| `E2E-47` | PEP 우회 네트워크 소켓 연결 차단 | accept 1건 | accept 0건 | `13` | `agent.confined` / `allow` / — |
| `E2E-48` | 손자 프로세스의 격리 상속 | 손자 경유 canary 유출 | 손자 경유 canary 미유출 | `13` | `agent.confined` / `allow` / — |
| `E2E-49` | 격리 필수 모드 Fail-Closed | 실험군 정책 + `Platform()`로 정직한 `bypass_read_zone_a -target workspace 파일` 성공(읽기 허용 경로가 실제로 열림) | `Require: true` + `NoopConfiner` 스폰 → 자식 미기동 | `16` | `agent.confined` / `deny` / `CONFINEMENT_UNAVAILABLE` |

- 감사 매칭: [`assertion.go`](../../../../internal/harness/assertion.go)는 `ExpectedAction`으로 역순 탐색한다. 대조군도 `agent.confined`(`confiner: "none"`)를 남기지만 실험군이 나중에 실행되므로 가장 최근 일치 이벤트는 실험군의 것이다. 1단계와 2단계는 서로 다른 `TraceID`를 쓰고, `ExpectedTraceID`로 실험군을 지정한다.
- `E2E-49`의 1단계는 "허용 목록이 너무 좁아서 모든 것이 막히는" 가짜 차단을 걸러낸다.
