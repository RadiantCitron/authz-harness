## 1. 목적 및 배경

010~040에서 만든 감독 계층, 소비자 배선, 결함 워커를 하네스 공식 카탈로그의 **G9 그룹 5대 시나리오**로 편입한다. 각 시나리오는 Quad-Assertion(종료 코드, 파일 무변화, 감사 액션·사유, 해시 체인)으로 검증한다. 종료 코드·감사로 드러나지 않는 부가 증거(손자 소멸, 버퍼 크기, MCP 응답 형식)는 010의 `harness.Invariantf`로 보고한다.

## 3. 시나리오 명세 (`G9`: 서브프로세스 자원·수명 통제)

공통 사항:
- 5대 모두 `RequiresSubprocess: true`이다. `inproc` 모드에서는 `Skipped`로 처리된다(040).
- 감사 이벤트는 부모 스포너가 `stack.AuditWriter`(`env.AuditPath`)에 기록한다.
- 결함 워커 스포너: `orchestrator.SpawnConfig{BinaryPath: env.FaultWorkerPath, Args: []string{"-mode", <모드>}, Limits: ..., Audit: stack.AuditWriter}`
- 파일 기대: 시나리오마다 `data/g9-target.txt`에 `ExpectZeroMutation: true`

| ID | 시나리오명 | 입력 | 기대 Exit | 기대 감사 (`Action` / `Decision` / `Reason`) | 부가 불변식 (`Invariantf`로 보고) |
|:---:|---|---|:---:|---|---|
| `E2E-40` | 멈춘 워커 시간 초과 강제 종료 | `hang`, `Limits{Timeout: 300ms}` | `17` | `agent.limit_exceeded` / `deny` / `RESOURCE_TIMEOUT` | `res.Termination == timed_out`, `res.Duration < 3s` |
| `E2E-41` | 손자를 남기고 멈춘 워커의 그룹 일괄 소멸 | `spawn_child_hang`, `Limits{Timeout: 300ms}` | `17` | `agent.limit_exceeded` / `deny` / `RESOURCE_TIMEOUT` | `StdoutRaw`에서 `CHILD_PID=<pid>` 추출 성공, `harness.WaitForProcessGone(pid, 1s) == true` |
| `E2E-42` | 출력 폭주 워커의 바이트 상한 즉시 차단 | `flood`, `Limits{MaxOutputBytes: 16 * 1024}` (Timeout 기본 10s) | `17` | `agent.limit_exceeded` / `deny` / `RESOURCE_OUTPUT_LIMIT` | `res.Termination == output_exceeded`, `len(res.StdoutRaw) <= 16384`, `res.Duration < 3s`(시간 초과가 아니라 상한으로 끝났음) |
| `E2E-43` | MCP `tools/call` 경로의 시간 초과와 토큰 비노출 | `executeMCPCall`에 결함 워커 `hang` 스포너(`Timeout: 300ms`) 주입, 유효한 읽기 토큰으로 `file_read` 호출 | `17` (구조화 필드 `structuredContent.exit_code`) | `agent.limit_exceeded` / `deny` / `RESOURCE_TIMEOUT` | 응답 `isError == true`, 텍스트에 `[RESOURCE_TIMEOUT]` 포함, 응답 전체 JSON에 `mcp.ContainsRawToken == false` |
| `E2E-44` | 기본 한계 아래 정상 위임 워커 비회귀 | 프로덕션 바이너리(`env.BinaryPath`) `subagent worker` + `Limits: orchestrator.DefaultLimits()` 명시, 유효 토큰으로 `file:read` | `0` | `pep.allow` / `allow` / `AUTHORIZED` | `res.Termination == exited`, `res.RawExitCode == 0` |

### 3.1 판정 규약
1. 부가 불변식이 깨지면 `return <실제 관찰한 종료 코드>, harness.Invariantf("...")`를 반환한다. 판정을 위해 종료 코드를 `16` 등으로 바꿔치기하지 않는다. 010의 판정기가 종료 코드와 상관없이 FAIL로 처리한다.
2. 스포너 생성·Setup 실패처럼 시나리오 자체를 실행할 수 없으면 `domain.ExitInternalError`와 일반 에러를 반환한다(기존 관례).
