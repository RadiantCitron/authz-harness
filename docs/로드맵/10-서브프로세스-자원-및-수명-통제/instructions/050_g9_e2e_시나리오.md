## 1. 목적 및 배경

`010`~`040` 단계에서 구축한 서브프로세스 자원·수명 통제 메커니즘을 하네스 공식 카탈로그의 **G9 그룹(`E2E-40`~`E2E-44`, 5대 시나리오)**으로 편입하여 Quad-Assertion(종료 코드, 파일 무변화, 감사 사유 코드, 감사 해시 체인 무결성)으로 자동 검증한다.
테스트 전용 결함 주입 바이너리 기능에 의존하지 않고도 일반 빌드(`authz-harness run --scenario all`)에서 항상 결정론적으로 실행되도록, 시나리오 전용 헬퍼 또는 스포너 커맨드 구성을 통해 5대 시나리오를 실증한다.

## 3. 신규 시나리오 명세 (`G9`: 서브프로세스 자원·수명 통제)

| ID | 시나리오명 | 입력 조건 | 기대 Exit | 기대 감사 사유 (`Reason`) | 핵심 검증 증거 |
|:---:|---|---|:---:|---|---|
| `E2E-40` | 멈춘 서브프로세스(Hang) 타임아웃 강제 종료 | 응답 없이 대기하는 워커 + 짧은 `Timeout` | `17` | `RESOURCE_TIMEOUT` | 지정 시간 내 즉시 종료, `agent.limit_exceeded` 기록, workspace 0바이트 무변화 |
| `E2E-41` | 손자 프로세스 생성 후 멈춘 워커의 프로세스 그룹 일괄 소멸 | 손자 프로세스를 띄우고 멈춘 워커 + 짧은 `Timeout` | `17` | `RESOURCE_TIMEOUT` | 그룹 종료 직후 `WaitForProcessGone(grandchildPID) == true` (잔존 프로세스 0), workspace 무변화 |
| `E2E-42` | 출력 폭주(Stdout Flood) 워커 바이트 상한 즉시 차단 | `MaxOutputBytes`(예: 16 KiB)를 초과해 연속 출력하는 워커 | `17` | `RESOURCE_OUTPUT_LIMIT` | 상한 도달 즉시 강제 종료, 부모 버퍼 보관량 `<= MaxOutputBytes`, workspace 무변화 |
| `E2E-43` | MCP `tools/call` 경로의 서브프로세스 타임아웃·토큰 비노출 | MCP `SubprocessExecutor`가 타임아웃 한계에 걸린 워커 호출 | `17` | `RESOURCE_TIMEOUT` | JSON-RPC `IsError: true` 응답에 `[RESOURCE_TIMEOUT]` 포함, 원시 JWT 토큰 노출 0건 |
| `E2E-44` | 기본 `Limits` 하에서 정상 위임 워커 비회귀 실행 | 유효한 토큰 + 기본 `DefaultLimits()` 적용 스포너로 `file:read` 수행 | `0` | `AUTHORIZED` | 정상 파일 읽기 성공, 기존 워커 동작 비회귀 증명 |

모든 시나리오는 Quad-Assertion(종료 코드 일치, 거부/한계 종료 시 파일 부작용 0, 감사 사유 코드 일치, `audit.jsonl` 해시 체인 `VALID`)을 통과해야 한다.
