## 1. 목적 및 배경

서브프로세스 수명 및 자원 통제 집행(`020`·`030` 단계)에 앞서, 순수 도메인 값 객체인 `domain.Limits`와 신규 종료 코드 `ExitResourceLimit = 17`, 한계 초과 사유 3종(`RESOURCE_TIMEOUT`, `RESOURCE_OUTPUT_LIMIT`, `RESOURCE_SIGNAL_KILLED`), 그리고 감사 액션 상수(`AuditActionAgentLimitExceeded = "agent.limit_exceeded"`)를 정의하고 `ExitCodeForReason()` 매핑을 확립한다.
아울러 무한 대기(hang), 출력 폭주(flood), 손자 프로세스 방치(spawn_child_hang) 결함을 재현하는 테스트 전용 워커 모드를 `//go:build testworker` 빌드 태그로 격리하여 프로덕션 바이너리 오염을 원천 차단한다 ([ADR 0003](../../../adr/0003-차기-로드맵-범위-개정-비목표-조건부-해제.md) C-5, C-7).

## 3. 세부 명세

### 3.1 종료 코드 및 사유 상수 (`internal/domain/constants.go`, `internal/domain/error.go`)
1. `ExitResourceLimit ExitCode = 17` 상수를 추가한다.
2. `AuditActionAgentLimitExceeded = "agent.limit_exceeded"` 상수를 추가한다.
3. 아래 3종의 `Reason` 상수를 추가한다:
   - `ReasonResourceTimeout Reason = "RESOURCE_TIMEOUT"`: 실행 시간 상한(`Timeout`) 초과로 강제 종료됨
   - `ReasonResourceOutputLimit Reason = "RESOURCE_OUTPUT_LIMIT"`: 표준 출력/오류 누적 바이트 상한(`MaxOutputBytes`) 초과로 차단됨
   - `ReasonResourceSignalKilled Reason = "RESOURCE_SIGNAL_KILLED"`: 타임아웃·출력 상한 외 외부 시그널(`SIGKILL`, `SIGTERM` 등)에 의해 비정상 종료됨
4. `ExitCodeForReason(r Reason)` 스위치에 위 3종을 추가하여 모두 `ExitResourceLimit(17)`을 반환하도록 매핑한다.

### 3.2 `domain.Limits` 값 객체 (`internal/domain/limits.go` — [016번 보고서](../../../보고서/016-다중로드맵_일괄설계_안티패턴_진단_및_10번로드맵_단독집중_구조정제_보고서.md) `R10-01` 플라시보 필드 제거 및 3필드 단순화)
1. 기본 상수:
   - `DefaultSpawnTimeout = 10 * time.Second` (기존 `spawner.go` 10초와 100% 호환)
   - `DefaultWaitDelay = 500 * time.Millisecond`
   - `DefaultMaxOutputBytes int64 = 1 << 20` (1 MiB = 1,048,576 bytes)
2. 구조체 필드 (부모 `SubprocessSpawner`가 외부에서 100% 확실하게 강제하는 3대 필드만 유지):
   - `Timeout time.Duration`: 전체 실행 시간 상한 (`0`이면 `DefaultSpawnTimeout`으로 정규화, 음수면 거부)
   - `WaitDelay time.Duration`: 만료/종료 후 파이프 닫힘 대기 상한 (`0`이면 `DefaultWaitDelay`로 정규화, 음수면 거부)
   - `MaxOutputBytes int64`: `stdout` 및 `stderr` 각각에 적용할 최대 바이트 상한 (`0`이면 `DefaultMaxOutputBytes`로 정규화, 음수면 거부)
3. 검증 메서드 `(l Limits) Normalize() (Limits, error)`:
   - `Timeout < 0`, `WaitDelay < 0`, `MaxOutputBytes < 0` 중 하나라도 음수이면 `domain.NewError(domain.ReasonInvalidArguments, "domain_limits", "...", nil)`을 반환하여 `ExitCodeFromError`가 `ExitBadInput(14)`을 산출하도록 보장한다.
   - 영값(`0`) 필드는 위 기본 상수로 채운 새 `Limits` 값 사본을 반환한다.

### 3.3 빌드 태그 격리 테스트 전용 워커 (`internal/subagent/testworker_*.go`, `internal/cli/subagent.go`)
1. `testworker_disabled.go` (`//go:build !testworker`):
   - `RunTestFaultMode(ctx context.Context, mode string, out io.Writer, errOut io.Writer) domain.ExitCode`가 호출되면 즉시 `ExitBadInput(14)`을 반환한다.
   - 결함 시뮬레이션용 내부 심볼(`runTestFaultHang`, `runTestFaultFlood`, `runTestFaultSpawnChildAndHang`)을 아예 정의하지 않는다.
2. `testworker_enabled.go` (`//go:build testworker`):
   - **주의 (Go 런타임 데드락 감지 회피)**: 단일 고루틴 프로세스에서 `select {}`나 만료 없는 `<-ctx.Done()`을 호출하면 Go 런타임이 즉시 `fatal error: all goroutines are asleep - deadlock!`(`exit status 2`)으로 패닉 종료해버린다. 따라서 대기 루프는 반드시 타이머 힙을 유지하는 `time.Sleep(1 * time.Hour)`로 구현한다.
   - `hang`: `time.Sleep(1 * time.Hour)`로 부모가 강제 종료할 때까지 대기한다.
   - `flood`: `out`으로 8 KiB 더미 바이트 청크를 루프로 반복 기록(에러 발생 시 종료)하여 출력 상한 초과를 유발한다.
   - `spawn_child_hang`: `cmd := exec.Command("sleep", "60")`으로 손자 프로세스를 띄운 직후(`cmd.Start()`, 단 손자에 `Setpgid`를 설정하지 않아 워커와 동일한 프로세스 그룹 `PGID`에 속하게 함), 손자의 PID를 `fmt.Fprintf(out, "CHILD_PID=%d\n", cmd.Process.Pid)`로 즉시 출력하고 `time.Sleep(1 * time.Hour)`로 대기한다. (JSON 형태가 아닌 `CHILD_PID=<pid>` 형식으로 출력하여 `spawner.go`의 `SubagentResponse` JSON 파서가 빈 구조체로 오인 파싱하는 것을 원천 방지한다.)
3. CLI 배선 (`internal/cli/subagent.go`):
   - `subagent worker` 플래그에 `-test-fault` 문자열 플래그를 추가한다.
   - `testFaultFlag != ""`이면 ` stack` 조립 전에 즉시 `subagent.RunTestFaultMode(ctx, testFaultFlag, r.stdout, r.stderr)`를 호출하고 종료 코드를 반환한다.
4. 릴리스 심볼 부재 검증 (`internal/subagent/testworker_symbol_test.go`):
   - 태그 없이 `go build`로 임시 바이너리를 빌드한 뒤 `go tool nm <bin>` 출력에 `runTestFaultHang`, `runTestFaultFlood`, `runTestFaultSpawnChildAndHang` 문자열이 **0건**임을 검증한다.
   - `go build -tags testworker`로 빌드한 바이너리에서는 세 심볼이 모두 존재함을 교차 검증한다.
