## 1. 목적 및 배경

서브프로세스 수명 및 자원 통제 집행(`020`·`030` 단계)에 앞서, 순수 도메인 값 객체인 `domain.Limits`와 신규 종료 코드 `ExitResourceLimit = 17`, 그리고 한계 초과 사유 3종(`RESOURCE_TIMEOUT`, `RESOURCE_OUTPUT_LIMIT`, `RESOURCE_SIGNAL_KILLED`)을 정의하고 `ExitCodeForReason()` 매핑을 확립한다.
아울러 무한 대기(hang), 출력 폭주(flood), 손자 프로세스 방치(orphan) 결함을 재현하는 테스트 전용 워커 모드를 `//go:build testworker` 빌드 태그로 격리하여 프로덕션 바이너리 오염을 원천 차단한다 ([ADR 0003](../../../adr/0003-차기-로드맵-범위-개정-비목표-조건부-해제.md) C-5, C-7).

## 3. 세부 명세

### 3.1 종료 코드 및 사유 상수 (`internal/domain/constants.go`, `internal/domain/error.go`)
1. `ExitResourceLimit ExitCode = 17` 상수를 추가한다.
2. 아래 3종의 `Reason` 상수를 추가한다.
   - `ReasonResourceTimeout Reason = "RESOURCE_TIMEOUT"`: 실행 시간 상한(`Timeout`) 초과로 강제 종료됨
   - `ReasonResourceOutputLimit Reason = "RESOURCE_OUTPUT_LIMIT"`: 표준 출력/오류 누적 바이트 상한(`MaxOutputBytes`) 초과로 차단됨
   - `ReasonResourceSignalKilled Reason = "RESOURCE_SIGNAL_KILLED"`: 타임아웃·출력 상한 외 외부 시그널(`SIGKILL`, `SIGTERM` 등)에 의해 비정상 종료됨
3. `ExitCodeForReason(r Reason)` 스위치에 위 3종을 추가하여 모두 `ExitResourceLimit(17)`을 반환하도록 매핑한다.

### 3.2 `domain.Limits` 값 객체 (`internal/domain/limits.go`)
1. 기본 상수:
   - `DefaultSpawnTimeout = 10 * time.Second` (기존 `spawner.go` 10초와 100% 호환)
   - `DefaultMaxOutputBytes int64 = 1 << 20` (1 MiB = 1,048,576 bytes; JSON 프레임 한계 64 KiB보다 넉넉하면서 메모리 고갈을 막는 기본 상한)
   - `DefaultWaitDelay = 500 * time.Millisecond`
   - `DefaultMaxOpenFiles uint64 = 64` (`RLIMIT_NOFILE` 기본 목표치)
   - `DefaultMaxCPonSeconds uint64 = 10` (`RLIMIT_CPU` 기본 목표치)
2. 구조체 필드:
   - `Timeout time.Duration`: 전체 실행 시간 상한 (`0`이면 `DefaultSpawnTimeout`으로 정규화, 음수면 거부)
   - `WaitDelay time.Duration`: 만료/종료 후 파이프 닫힘 대기 상한 (`0`이면 `DefaultWaitDelay`로 정규화, 음수면 거부)
   - `MaxOutputBytes int64`: `stdout` 및 `stderr` 각각에 적용할 최대 바이트 상한 (`0`이면 `DefaultMaxOutputBytes`로 정규화, 음수면 거부)
   - `MaxOpenFiles uint64`: best-effort `RLIMIT_NOFILE` 상한 (`0`이면 `DefaultMaxOpenFiles`)
   - `MaxCPUSeconds uint64`: best-effort `RLIMIT_CPU` 초 단위 상한 (`0`이면 `DefaultMaxCPUSeconds`)
3. 검증 메서드 `(l Limits) Normalize() (Limits, error)`:
   - `Timeout < 0`, `WaitDelay < 0`, `MaxOutputBytes < 0` 중 하나라도 음수이면 `domain.NewError(domain.ReasonInvalidArguments, "domain_limits", "...", nil)`을 반환하여 `ExitCodeFromError`가 `ExitBadInput(14)`을 산출하도록 보장한다.
   - 영값(`0`) 필드는 위 기본 상수로 채운 새 `Limits` 값 사본을 반환한다.

### 3.3 빌드 태그 격리 테스트 전용 워커 (`internal/subagent/testworker_*.go`)
1. `testworker_disabled.go` (`//go:build !testworker`):
   - `RunTestFaultMode(ctx context.Context, mode string, out io.Writer, errOut io.Writer) domain.ExitCode`가 호출되면 즉시 `ExitBadInput(14)`을 반환한다.
   - 결함 시뮬레이션용 내부 함수(`runTestFaultHang`, `runTestFaultFlood`, `runTestFaultSpawnChildAndHang`)를 아예 정의하지 않는다.
2. `testworker_enabled.go` (`//go:build testworker`):
   - `hang`: `<-ctx.Done()`까지 대기하거나 시그널을 받을 때까지 블록한다.
   - `flood`: `out`으로 8 KiB 청크를 반복 기록하여 출력 상한 초과를 유발한다.
   - `spawn_child_hang`: 자기 자신(또는 자식 프로세스)을 `hang` 모드로 스폰한 뒤 자식의 `PID`를 첫 줄(`{"child_pid": <pid>}`)로 `out`에 출력하고 `Flush`한 다음, 부모 워커 자신도 `<-ctx.Done()`까지 대기한다. (고정 `sleep 100` 외부 프로세스 방치 금지; 부모 그룹 종료 시 함께 수거되도록 구성)
3. 릴리스 심볼 부재 검증 (`internal/subagent/testworker_symbol_test.go`):
   - `go build` (태그 미지정)로 임시 바이너리를 빌드한 뒤 `go tool nm <bin>` 결과에 `runTestFaultHang`, `runTestFaultFlood`, `runTestFaultSpawnChildAndHang` 심볼이 **0건**임을 검증한다.
   - `go build -tags testworker`로 빌드한 바이너리에서는 해당 심볼이 존재함을 교차 검증한다.
