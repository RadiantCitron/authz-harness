## 1. 목적 및 배경

G9 E2E는 오작동하는 자식이 필요하다. 이전 설계는 그 오작동을 프로덕션 CLI(`authz-harness subagent worker -test-fault`) 안에 빌드 태그로 넣었다. 개정된 [ADR 0003](../../../adr/0003-차기-로드맵-범위-개정-비목표-조건부-해제.md) C-7은 이 방식을 버리고 **프로덕션 바이너리와 분리된 시험 전용 실행 파일**을 쓴다. 이유는 두 가지다.

- 스포너가 감독하는 대상은 *신뢰할 수 없는 임의 자식*이다. 시험 자식도 프로덕션 코드와 무관한 별도 프로그램이어야 실제 신뢰 경계를 시험한다.
- 하네스는 프로덕션 바이너리를 **태그 없이 그대로** 빌드해 시험해야 한다. 그래야 E2E-01~39가 계속 릴리스 바이너리를 증명한다.

또한 G9는 실제 OS 프로세스가 있어야만 의미가 있다. `inproc` 모드에서 몰래 바이너리를 빌드하지 않도록, 시나리오가 필요한 실행 모드를 **선언**하고 러너가 맞지 않는 모드에서 건너뛰게 한다.

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/harness/faultworker/main.go` [신규, `package main`]: 결함 모드 3종
  - `internal/harness/binary.go`: `CachedBinaryProvider`에 빌드 대상 패키지 경로 필드 추가, `NewFaultWorkerProvider()` 신규. `NewCachedBinaryProvider()`는 지금처럼 `./cmd/authz-harness`를 **태그 없이** 빌드
  - `internal/harness/scenario.go`: `ScenarioMetadata.RequiresSubprocess bool` 추가
  - `internal/harness/sandbox.go`: `SandboxEnvironment.FaultWorkerPath string` 추가
  - `internal/harness/runner.go`:
    - `ScenarioResult.Skipped bool` 추가
    - `RequiresSubprocess`인데 실행 모드가 `inproc`이면 샌드박스를 만들지 않고 `Skipped: true`, `Error: "requires subprocess mode"` 반환
    - 서브프로세스 모드에서 `RequiresSubprocess` 시나리오에 한해 `faultWorkerProvider`로 `env.FaultWorkerPath` 주입(`WithFaultWorkerProvider` 옵션, 기본값 `NewFaultWorkerProvider()`)
  - `internal/cli/run.go`: `!res.Passed && !res.Skipped`일 때만 실패로 집계
  - `internal/ui/json.go`, `summary.go`: `Skipped` 개수 집계·표시
  - `internal/harness/architecture_test.go`: 결함 워커 import 가드 추가
  - `internal/harness/binary_test.go`, `harness_test.go`: 아래 인수 테스트
- **무영향**:
  - 프로덕션 CLI(`cmd/authz-harness`, `internal/cli/subagent.go`)는 수정하지 않는다. 결함 모드 플래그, 빌드 태그, 심볼 부재 테스트는 **만들지 않는다**.
  - 기존 시나리오는 `RequiresSubprocess == false`(영값)이므로 두 실행 모드에서 동작이 지금과 같다.
  - `Skipped`가 0이면 CLI 종료 코드와 JSON의 `total`·`passed`는 지금과 같다.

## 3. 세부 명세

### 3.1 결함 워커 (`internal/harness/faultworker/main.go`)
1. 표준 라이브러리만 import한다. `authz-harness/...` 패키지를 하나도 import하지 않는다.
2. 플래그 `-mode`(필수). stdin은 읽지 않는다. 스포너가 주입하는 요청 프레임(토큰 포함)은 무시한다.
   - `hang`: `time.Sleep(1 * time.Hour)` (`select {}` 금지: Go 런타임 데드락 패닉)
   - `flood`: stdout에 8 KiB 청크를 쓰기 에러가 날 때까지 반복
   - `spawn_child_hang`: `exec.Command("sleep", "60").Start()`(손자에 `Setpgid` 미설정 → 같은 프로세스 그룹) → `fmt.Printf("CHILD_PID=%d\n", pid)` → `time.Sleep(1 * time.Hour)`
   - 그 밖의 값이나 누락: stderr에 사용법을 쓰고 `os.Exit(2)`
3. 로드맵 11·15·16은 이 파일에 모드를 추가해 재사용한다(ADR 0003 C-7).

### 3.2 바이너리 프로바이더 (`internal/harness/binary.go`)
1. `CachedBinaryProvider`에 `pkg string` 필드를 둔다. 빌드 명령은 `go build -o <tmp>/<name> <pkg>`이고 **태그는 없다**.
2. `NewCachedBinaryProvider()` → `pkg = "./cmd/authz-harness"` (기존과 같음)
3. `NewFaultWorkerProvider()` → `pkg = "./internal/harness/faultworker"`
4. 인터페이스 `BinaryProvider`는 그대로 쓴다.

### 3.3 실행 모드 선언과 건너뜀 (`scenario.go`, `runner.go`, `cli/run.go`, `ui`)
1. `RunScenario` 첫머리에서 `meta.RequiresSubprocess && r.executionMode != ModeSubprocess`이면 `ScenarioResult{Metadata: meta, Skipped: true, Passed: false, Error: "requires subprocess mode"}, nil`을 반환한다.
2. 서브프로세스 모드이고 `meta.RequiresSubprocess`이면, `env.BinaryPath` 주입 직후 `faultWorkerProvider.GetBinaryPath()`로 `env.FaultWorkerPath`를 채운다. 빌드에 실패하면 기존 바이너리 빌드 실패와 같은 방식으로 반환한다.
3. CLI 집계: `Skipped`는 실패가 아니다. 출력 요약과 JSON에 `skipped` 개수를 추가한다.

### 3.4 아키텍처 가드 (`internal/harness/architecture_test.go`)
- `TC-040-AG`: `internal/harness/faultworker`의 비테스트 파일 import 중 `"authz-harness/` 접두사가 0건임을 `go/parser`(기존 가드 방식)로 검증한다.
