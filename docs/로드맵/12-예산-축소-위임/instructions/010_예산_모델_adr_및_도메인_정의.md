## 1. 목적 및 배경

권한(Scope), 수명(TTL), 위임 깊이(Depth)에 이은 4번째 단조 축소 축으로 **호출 횟수·읽기 바이트·쓰기 바이트 예산(`domain.Budget`)**을 도입한다.
본 단계에서는 `ROADMAP.md` §8의 미결 4건을 확정하는 **예산 모델 ADR(`docs/adr/0004-예산-축소-위임-예약-및-정산-모델.md`)**을 수립하고, 순수 도메인 모델(`domain.Budget`), 토큰 클레임 필드(`TokenClaims.Budget`), 그리고 예산 거부 사유 2종(`ReasonBudgetExhausted`, `ReasonDelegationBudgetExceeded`)을 정의한다.

  - `internal/domain/token.go`: `TokenClaims`에 `Budget *Budget` (`json:"budget,omitempty"`) 선택 필드 추가
  - `internal/domain/budget_test.go` [신규]: 음수·오버플로·부분상한 비교 Table-Driven 테스트

## 3. 세부 명세

1. **ADR 0004 확정 원칙**:
   - **배분 방식**: **예약+정산(Reservation & Settlement)** 방식 채택. 자식 토큰 교환 시 부모 잔여 예산에서 자식 상한만큼 원자적으로 차감(예약)하고, 자식 만료 또는 회수 시 미사용분을 부모에게 반환한다.
   - **읽기 바이트 차감 시점**: PEP Stage 4 직전 최소 1회 호출(`Calls: 1`) 및 대상 파일 크기(사전 Stat 가능 시)를 예약 차감하고, Stage 5 읽기 완료 직후 실제 읽은 바이트 수로 정산한다(초과 시 결과를 버리고 `BUDGET_EXHAUSTED` 거부).
   - **예산 부재 토큰 정책**: `Budget == nil`인 토큰은 "예산 통제 비적용(기존 호환)"으로 처리하되, 부모 토큰에 `Budget != nil`이 설정되어 있으면 자식 토큰은 반드시 부모 잔여 예산 이하의 `Budget`을 가져야 한다(부모 예산이 있는데 자식이 `Budget == nil`로 우회하는 것 금지).
2. **`domain.Budget` 메서드**:
   - `Validate() error`: `MaxCalls < 0`, `MaxReadBytes < 0`, `MaxWriteBytes < 0`이거나 모든 필드가 `0`이면 `ReasonInvalidArguments`(`ExitBadInput = 14`) 반환.
   - `Exceeds(available Budget) bool`: 요청된 예산 항목 중 하나라도 `available` 잔여량을 초과하면 `true` 반환.

## 4. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |
