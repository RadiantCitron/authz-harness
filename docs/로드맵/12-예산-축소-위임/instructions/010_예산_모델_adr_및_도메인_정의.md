## 1. 목적 및 배경

권한(Scope), 수명(TTL), 위임 깊이(Depth)에 이은 4번째 단조 축소 축으로 **호출 횟수·읽기 바이트·쓰기 바이트 예산(`domain.Budget`)**을 도입한다.
본 단계는 예산 모델 ADR(`docs/adr/0004-예산-축소-위임-예약-및-정산-모델.md`)을 쓰고, 순수 도메인 값 `domain.Budget`, 토큰 클레임 필드 `TokenClaims.Budget`, 거부 사유 2종(`ReasonBudgetExhausted`, `ReasonDelegationBudgetExceeded`)만 정의한다. 원장·배선은 020 이후다.

## 3. 세부 명세

### 3.1 ADR 0004 필수 기재 사항
1. **배분 방식 — 예약+정산(Reservation & Lazy Reclaim)**: 교환 시 부모의 현재 잔여(`Remaining`)에서 자식 요청량을 원자적으로 떼어 자식 엔트리로 옮긴다. 자식이 만료(`now >= child.ExpiresAt`)되면 다음 원장 쓰기 트랜잭션에서 자식의 미사용분을 부모로 돌려준다. 「모두가 한 통을 나눠 쓰는 방식」을 고르지 않은 이유(자식 크래시 시 누가 얼마를 썼는지 장부만으로 설명할 수 있어야 함)를 함께 적는다.
2. **`Initial`과 `Remaining`의 `0` 의미 분리**:
   - 유효한 `Budget`은 `MaxCalls > 0`이 필수다.
   - 바이트 한도는 **초기 상한**(`Initial.MaxReadBytes > 0`, `Initial.MaxWriteBytes > 0`)이 양수일 때만 활성이다(`HasReadLimit()`, `HasWriteLimit()`). `0`은 「한도 없음」이다.
   - 활성 한도에서 소비 후 `Remaining == 0`은 「소진」이다. 「한도 없음」으로 풀리지 않는다.
3. **Gate 1 Replay 원장과의 역할 분리**: [`verifier.go`](../../../../internal/authn/token/verifier.go) 233~238행은 `opts.RecordReplay && v.replayLedger != nil`일 때 jti를 1회 소비한다(PEP는 `true`, 교환은 `false`). `claims.Budget != nil` 토큰은 다회 호출 토큰이므로 이 소비를 건너뛰고 예산 원장의 `MaxCalls`가 횟수를 통제한다. `Budget == nil` 토큰은 기존 1회성 그대로다(`E2E-18` 보존).
4. **원장의 위치와 집행 지점**: 원장은 기존 Replay 원장과 같은 구조로 `internal/authn/budget`, 파일 `zone_b/budget_ledger.json`에 둔다. 집행(원자 차감)은 PEP 한 곳이며 PDP·PIP는 예산을 보지 않는다. 상태를 소비하는 것은 Replay 원장처럼 판정자 밖에서 원자적으로 집행한다는 원칙을 근거로 적는다.
5. **Fail-Closed 규칙**: 원장 미배선(16), 원장 손상(16), 부모 엔트리 없음(`DELEGATION_BUDGET_EXCEEDED`, 12), 소비 엔트리 없음(`BUDGET_EXHAUSTED`, 12). 원장에 없는 부모를 토큰 클레임으로 **자동 초기화하지 않는다**(롤백·삭제로 예산이 되살아나는 것을 막기 위해).
6. **보장 범위**: 예산 보장은 PEP를 거치는 정직한 워커에 한정된다. 워커 격리 정책([`confinement/policy.go`](../../../../internal/confinement/policy.go) `WorkerPolicy`)은 `zone_b` 쓰기를 허용하므로 악의 워커의 원장 직접 변조는 범위 밖이다(기존 `grants_state.json`과 같은 한계).

ADR 상태는 작성 시 `Accepted`로 둔다(본 단계 지시가 곧 채택 결정이다). 060에서 최종 점검한다.

### 3.2 `domain.Budget` 메서드 (`internal/domain/budget.go`)
- `Validate() error`: `MaxCalls <= 0 || MaxReadBytes < 0 || MaxWriteBytes < 0`이면 `domain.NewError(domain.ReasonInvalidArguments, "domain_budget", "...", nil)`(`ExitBadInput = 14`).
- `HasReadLimit() bool`: `MaxReadBytes > 0`.
- `HasWriteLimit() bool`: `MaxWriteBytes > 0`.
- `Within(upper Budget) bool`: 정적 상한 비교. `MaxCalls <= upper.MaxCalls`이고, `upper.HasReadLimit()`이면 `HasReadLimit() && MaxReadBytes <= upper.MaxReadBytes`(쓰기도 동일). 상위가 바이트 한도를 가졌는데 하위가 「한도 없음」이면 `false`(무제한 격상 차단). 030 정적 검사와 020 예약 검사가 같은 규칙을 쓰도록 여기 한 번만 정의한다.
