## 1. 목적 및 배경

루트 토큰 발급 시 초기 예산을 원장에 등록하고, [RFC 8693 토큰 교환(`internal/authn/exchange`)](../../../../internal/authn/exchange/service.go) 시 자식 요청 예산이 **부모의 현재 잔여 예산 이하($B_{child} \le B_{parent\_remaining}$)**인지 검증한 뒤 부모 잔여량에서 원자적으로 예약(차감)한다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/authn/exchange/validator.go`: `ValidateBudgetDownscope(parentBudget, childBudget *domain.Budget) error` 추가 (부모에 예산이 있을 때 자식 예산 누락 또는 상한 초과 시 `ReasonDelegationBudgetExceeded` 반환)
  - `internal/authn/exchange/service.go`: `ExchangeRequest`에 `Budget *domain.Budget` 추가, `BudgetLedger` 연동하여 부모 잔여 예산 검증 및 자식 JTI로 원자 예약 수행
  - `internal/authn/token/issuer.go` 및 `internal/cli/token.go`: `--max-calls`, `--max-read-bytes`, `--max-write-bytes` 선택 플래그 지원
  - `internal/authn/exchange/budget_exchange_test.go` [신규]: 단조 축소·다단계(2-Hop) 합계 보존 단위 테스트
- **무영향**:
  - 예산 플래그를 지정하지 않은 기존 토큰 발급·교환 호출은 `Budget == nil`로 동작하여 기존 테스트와 100% 호환된다.

---

## 3. 세부 명세

1. **단조 축소 불변식**:
   - 부모 토큰의 `Budget != nil`이면 자식 교환 요청에도 유효한 `Budget != nil`이 있어야 한다(예산 없는 자식 토큰으로 격상 우회 차단).
   - 원장에서 조회한 부모의 **현재 잔여 예산(`parentRemaining`)**보다 자식의 요청 예산이 어느 한 항목이라도 크면 `domain.NewError(domain.ReasonDelegationBudgetExceeded, "exchange", "...", nil)`(`ExitAuthzDenied = 12`)로 발급을 거부하고 `token.exchange.deny` 감사를 기록한다.
2. **2-Hop 합계 보존**:
   - `Root(10) → Lead(6 예약, Root 잔여 4) → Worker(4 예약, Lead 잔여 2)`로 이어질 때 전체 잔여 합계(`4 + 2 + 4 = 10`)가 항상 보존되어야 한다.

## 4. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |
|:---:|---|---|
| **TC-030-01** | 부모 잔여 `Calls: 10`에서 자식 `Calls: 11` 교환 요청 | `ReasonDelegationBudgetExceeded`(`ExitCode == 12`) 거부, 부모 잔여 `10` 유지 |
| **TC-030-02** | 부모 잔여 `Calls: 10`에서 자식 A(`Calls: 6`), 자식 B(`Calls: 5`) 순차 교환 요청 | 자식 A 성공(부모 잔여 `4`), 자식 B는 잔여 `4 < 5`이므로 `ReasonDelegationBudgetExceeded` 거부 |
| **TC-030-03** | 부모 `Budget != nil`인데 자식 `Budget == nil`로 교환 요청 | `ReasonDelegationBudgetExceeded` 거부 (무제한 우회 차단) |
| **TC-030-04** | 2-Hop(Root → Lead → Worker) 예산 분할 교환 | 각 단계 잔여량 합계가 초기 루트 예산과 정확히 일치 |
