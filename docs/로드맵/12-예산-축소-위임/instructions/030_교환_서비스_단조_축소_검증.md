## 1. 목적 및 배경

루트 토큰 발급([`internal/authn/token/issuer.go`](../../../../internal/authn/token/issuer.go)) 시 초기 예산을 Zone B `BudgetLedger`에 등록하고, RFC 8693 토큰 교환([`internal/authn/exchange/service.go`](../../../../internal/authn/exchange/service.go)) 시 자식 요청 예산이 **부모의 정적 클레임 상한 및 원장 내 실시간 잔여 예산 이하($B_{child} \le B_{parent\_remaining}$)**인지 검증한 뒤 원자적으로 예약한다.
또한 `Verifier.VerifyToken`([`internal/authn/token/verifier.go`](../../../../internal/authn/token/verifier.go))에서 `claims.Budget != nil`인 토큰은 Gate 1의 일회성 `replayLedger.CheckAndConsume` 대신 `BudgetLedger`가 호출 횟수를 통제하도록 연결한다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/authn/token/issuer.go`:
    - `IssueRequest`에 `Budget *domain.Budget` 및 내부 제어용 `SkipBudgetLedgerInit bool`(교환 서비스가 `ReserveChildBudget`으로 직접 등록할 때 중복 초기화 방지) 추가
    - `Service`에 선택적 `WithBudgetLedger(ledger budget.Ledger)` 옵션 추가: `req.Budget != nil && !req.SkipBudgetLedgerInit`일 때 발급된 `claims.JWTID`로 `ledger.InitBudget` 호출
  - `internal/authn/token/verifier.go`:
    - 9단계 Replay 소비 검사(225행)에서 `claims.Budget == nil`일 때만 `v.replayLedger.CheckAndConsume`을 수행하도록 조건화 (`claims.Budget != nil`인 다회성 예산 토큰이 2회차 호출 시 Gate 1에서 `TOKEN_REPLAY_DETECTED(11)`로 오차단되는 현상 방지)
  - `internal/authn/exchange/validator.go`: `ValidateBudgetDownscope(parentBudget, childBudget *domain.Budget) error` 추가
  - `internal/authn/exchange/service.go`: `ExchangeRequest`에 `Budget *domain.Budget` 추가, `WithBudgetLedger(ledger budget.Ledger)` 옵션을 통해 자식 토큰 발급 시 `ledger.ReserveChildBudget` 수행 (실패 시 `token.exchange.deny` 감사 기록 및 `ReasonDelegationBudgetExceeded` 반환)
  - `internal/authn/exchange/budget_exchange_test.go` [신규]: 단조 축소·잔여량 초과 거부·2-Hop 합계 보존 단위 테스트
- **무영향**:
  - `Budget == nil`인 기존 모든 토큰은 `IssueToken`, `VerifyToken`(`replayLedger` 1회성 검사 포함), `Exchange` 전 구간에서 기존과 100% 동일하게 동작한다.

## 3. 세부 명세

1. **정적 + 동적 2단 예산 축소 검증 (`ExchangeService.Exchange`)**:
   - **1차(정적 클레임 검증)**: `parentClaims.Budget != nil`인데 `req.Budget == nil`이거나 `req.Budget`의 어느 한 항목이라도 `parentClaims.Budget`보다 크면 원장을 열기도 전에 `ReasonDelegationBudgetExceeded`(`ExitAuthzDenied = 12`)로 즉시 거부한다.
   - **2차(원장 잔여량 원자 예약)**: `s.budgetLedger != nil`이고 `req.Budget != nil`일 때, 부모가 아직 원장에 없다면 `parentClaims.Budget`으로 자동 초기화한 뒤 `ReserveChildBudget(parentClaims.JWTID, childResult.Claims.JWTID, *req.Budget, childResult.Claims.ExpiresAt, now)`를 수행한다. 부모의 **현재 잔여량(`Remaining`)**이 부족하면 `ReasonDelegationBudgetExceeded`(`12`) 에러를 반환하고 `token.exchange.deny` 감사를 남긴다.
