## 1. 목적 및 배경

루트 토큰 발급 시 예산을 원장에 등록하고, 토큰 교환 시 자식 예산이 **부모의 클레임 상한 이하이고 원장의 현재 잔여 이하($B_{child} \le B_{parent\_remaining}$)**인지 확인한 뒤 원자적으로 예약한다. 예산 토큰은 Gate 1 Replay 1회 소비에서 빼서 여러 번 쓸 수 있게 한다. 원장은 합성 루트 `app.BuildStack` 한 곳에서 만들어 발급자·교환 서비스에 주입한다(PEP 주입은 040).

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/authn/token/issuer.go`:
    - `IssueRequest`에 `Budget *domain.Budget` 추가. 발급 클레임에 그대로 싣는다.
    - `Service`에 선택적 원장 주입(`WithBudgetLedger(budget.Ledger)` 옵션 또는 생성자 인자 — 기존 생성자 호출부를 깨지 않는 쪽).
    - **루트 등록 규칙**: `req.Budget != nil && req.Actor == nil`(위임 체인 없는 루트)이면 서명 후 `ledger.Init(jti, *req.Budget, exp)`. 원장이 `nil`이면 발급하지 않고 `ReasonInternalError`(16). `Init` 실패 시 토큰을 반환하지 않는다. 교환 발급은 `Actor`가 항상 채워지므로([`exchange/service.go`](../../../../internal/authn/exchange/service.go) 130~134행) 등록되지 않는다. 별도 제어 플래그(`SkipBudgetLedgerInit` 등)는 만들지 않는다.
  - `internal/authn/token/verifier.go`: 9단계(233~238행) 조건을 `opts.RecordReplay && v.replayLedger != nil && claims.Budget == nil`로 바꾼다.
  - `internal/authn/exchange/validator.go`: 패키지 함수 `ValidateBudgetDownscope(parent, child *domain.Budget) error` 추가(기존 `DownscopeValidator` 인터페이스 시그니처는 바꾸지 않는다). 규칙: `parent == nil && child == nil` 통과, `parent == nil && child != nil` 거부(예약할 부모 엔트리가 없으므로 — 예산은 루트 발급에서만 시작한다), `parent != nil && child == nil` 거부(무제한 격상), 그 외 `child.Within(*parent)`가 거짓이면 거부. 거부는 모두 `ReasonDelegationBudgetExceeded`(12).
  - `internal/authn/exchange/service.go`: `ExchangeRequest`에 `Budget *domain.Budget`, 원장 주입 옵션, 아래 §3 흐름.
  - `internal/app/builder.go`:
    - `AppConfig.BudgetPath string`. 비면 `filepath.Join(filepath.Dir(cfg.ReplayPath), "budget_ledger.json")`.
    - `budget.NewFileLedger(path, cfg.Clock)` 생성, `AppStack.BudgetLedger budget.Ledger` 노출, 발급자(`!VerifyOnly`)에 주입.
    - `AppStack.ExchangeService exchange.Service`: `!cfg.VerifyOnly`일 때 원장을 주입해 여기서 한 번 조립.
  - `internal/authn/exchange/budget_exchange_test.go`, `internal/authn/token` 테스트, `internal/app/builder_test.go` 보강
- **고치지 않는 것**: 기존 `NewExchangeService` 호출부 6곳([`multi_hop.go`](../../../../internal/orchestrator/multi_hop.go) 69행, [`cli/token.go`](../../../../internal/cli/token.go) 42·309행, [`g5_delegation_pdp.go`](../../../../internal/harness/catalog/g5_delegation_pdp.go) 85·170·273행). 이들은 예산을 요청하지 않으며, 예산 토큰이 들어오면 §3 Fail-Closed로 거부된다. `multi_hop.go` DI 정제는 범위 밖이다.
- **경로 근거**: 토큰 CLI의 `BuildStack`([`cli/token.go`](../../../../internal/cli/token.go) 31~36행)에는 `StatePath`가 없지만 `ReplayPath`는 [`builder.go`](../../../../internal/app/builder.go) 138행에서 항상 쓰이므로 모든 호출부에 있다. 따라서 `ReplayPath` 디렉터리 기준 파생이면 부모·자식·CLI가 같은 원장을 본다. 새 CLI 플래그는 만들지 않는다.
- **무영향**: `Budget == nil` 토큰은 발급·검증(1회성 Replay 포함)·교환 전 구간이 기존과 같다.

## 3. 세부 명세 — 교환 흐름 (`ExchangeService.Exchange`)

기존 1~5단계(클라이언트 인증, 부모 검증 `RecordReplay: false`, `ValidateDownscope`, act 체인) 뒤에 다음을 넣는다. 예산이 관여하지 않으면(`parentClaims.Budget == nil && req.Budget == nil`) 모두 건너뛴다.

1. **정적 검사**: `ValidateBudgetDownscope(parentClaims.Budget, req.Budget)`. 실패 시 원장을 열지 않고 `token.exchange.deny` + `ReasonDelegationBudgetExceeded`(12).
2. **원장 필수**: 원장이 `nil`이면 `token.exchange.deny` + `ReasonInternalError`(16).
3. **발급 후 예약**: 자식 토큰을 발급(`IssueRequest.Budget = req.Budget`)한 뒤 `ledger.Reserve(parentClaims.JWTID, child.JWTID, *req.Budget, child.ExpiresAt)`.
   - 부모 엔트리가 없으면 **자동 초기화하지 않는다**. `Reserve`가 `ReasonDelegationBudgetExceeded`(12)를 돌려준다.
   - 예약 실패 시 자식 토큰을 **반환하지 않고** `token.exchange.deny`를 남긴다. 이 토큰은 원장에 엔트리가 없어 PEP에서 거부되므로(040) 유출되어도 쓸 수 없다.
4. 성공 시 기존 `token.exchange` 감사와 결과 반환.

교환은 부모 토큰을 소비하지 않는다(`RecordReplay: false`, [`service.go`](../../../../internal/authn/exchange/service.go) 111행). 예산 부모를 여러 번 교환에 써도 한도는 원장 예약이 정한다.
