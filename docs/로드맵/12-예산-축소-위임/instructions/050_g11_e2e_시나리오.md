예산 초과 위임 거부, 호출·바이트 예산 소진 차단, **실제 다중 OS 서브프로세스 동시 차감 경합 시 총합 보존**, 자식 크래시 시 만료 예산 자동 회수, 2-Hop 예산 보존을 검증하는 G11 그룹 5대 시나리오(`E2E-50`~`E2E-54`)를 카탈로그에 편입한다.

## 3. 신규 시나리오 명세 (`G11`: 예산 축소 위임)

| ID | 시나리오명 | 입력 조건 | 기대 Exit | 기대 감사 (`ExpectedAction` / `ExpectedReason`) | 핵심 검증 증거 |
|:---:|---|---|:---:|---|---|
| `E2E-50` | 부모 잔여 예산 초과 위임(Exchange) 거부 | 부모 `MaxCalls: 3` 토큰으로 자식 `MaxCalls: 5` 교환 시도 | `12` | `token.exchange.deny` / `DELEGATION_BUDGET_EXCEEDED` | 토큰 미발급, 부모 잔여 예산 `3` 그대로 유지, 파일 무변화 |
| `E2E-51` | 호출 횟수 및 쓰기 바이트 예산 소진 즉시 차단 | `MaxCalls: 2, MaxWriteBytes: 20` 토큰으로 10바이트 쓰기 2회 성공(`target_ok.txt`) 후 3회차(`target_blocked.txt`) 쓰기 시도 | `12` | `pep.deny` / `BUDGET_EXHAUSTED` | 1·2회차 허용 후 3회차 정확히 거부, `target_blocked.txt` 0바이트 무변화 |
| `E2E-52` | 다중 OS 서브프로세스 동시 예산 경합(TOCTOU) 방어 | 총 예산 `MaxCalls: 3` 토큰으로 6개 서브프로세스(`SubprocessSpawner`) 동시 기동 | `12` | `pep.deny` / `BUDGET_EXHAUSTED` | `sync.WaitGroup` 동시 스폰 결과 정확히 3개만 `Exit 0` 성공하고 3개는 `Exit 12` 거부, 원장 잔량 `0` |
| `E2E-53` | 자식 크래시 후 만료 예산 자동 회수(누수 0) 및 재위임 | 부모(`Calls: 5`) → 자식 A(`Calls: 4`, TTL 1분) 예약 후 미사용 만료(시계 `+2m` 전진) → 자식 B(`Calls: 4`) 재위임 및 파일 읽기 실행 | `0` | `pep.allow` / `AUTHORIZED` | 만료된 자식 A의 예약분(`4`)이 부모에게 자동 회수되어 자식 B 위임 및 읽기 성공 |
| `E2E-54` | 2-Hop 다단계 예산 분할 위임 및 합계 보존 | `Root(Calls: 5) → Lead(Calls: 3) → Worker(Calls: 2)` 연쇄 교환 및 워커 1회 파일 읽기 실행 | `0` | `pep.allow` / `AUTHORIZED` | 실행 후 각 주체 잔여량(`Root=2, Lead=1, Worker=1`) + 소비량(`1`) == 초기 루트 예산(`5`) 일치 |

### `E2E-52` 다중 프로세스 경합 시나리오 주의사항
- 6개 고루틴이 동시에 서브프로세스를 띄우면 마지막에 `audit.jsonl`에 기록되는 이벤트가 성공(`pep.allow`)일 수도 있고 거부(`pep.deny`)일 수도 있다.
- [`assertion.go`](../../../../internal/harness/assertion.go)의 역순 감사 탐색이 항상 `pep.deny` / `BUDGET_EXHAUSTED`를 마지막에 확인하고 `ExpectZeroMutation` 대상 파일(`contended_blocked.txt`)이 무변화임을 검증할 수 있도록:
  1) 1단계로 6개 동시 서브프로세스를 `contended_shared.txt` 읽기로 경합 실행하여 **정확히 성공 3건(`Exit 0`), 거부 3건(`Exit 12`)**임을 시나리오 내부에서 검증(어긋나면 즉시 에러 반환)하고,
  2) 직후 소진된 동일 토큰으로 `contended_blocked.txt` 쓰기를 1회 호출하여 `Exit 12` (`pep.deny` / `BUDGET_EXHAUSTED`)로 수렴시킨다.
