## 1. 목적 및 배경

원장 잔여 초과 위임 거부, 쓰기 바이트 소진 차단, **실제 다중 OS 서브프로세스 동시 차감 경합 시 합계 보존**, 자식 만료 후 예약 자동 회수, 2-Hop 합계 보존을 G11 그룹 5대 시나리오로 카탈로그에 넣는다. 각 시나리오의 수치는 **증명하려는 검사만 걸리도록** 골랐다(§3 「수치 선택 이유」).

## 3. 신규 시나리오 명세 (`G11`: 예산 축소 위임)

| ID | 시나리오명 | 입력 조건 | 기대 Exit | 기대 감사 (`ExpectedAction` / `ExpectedReason`) | 핵심 검증 증거 |
|:---:|---|---|:---:|---|---|
| `E2E-50` | 부모 **잔여** 초과 위임 거부 | 루트 `MaxCalls: 5` → 자식 A(`2`) 교환 성공(루트 잔여 `3`) → 자식 B(`4`) 교환 시도 | `12` | `token.exchange.deny` / `DELEGATION_BUDGET_EXCEEDED` | B 토큰 미반환, 루트 잔여 `3` 유지, 파일 무변화 |
| `E2E-51` | 쓰기 바이트 예산 소진 차단 | `MaxCalls: 5, MaxWriteBytes: 20` 루트 토큰으로 10바이트 쓰기 2회(`target_ok.txt`) 성공 후 1바이트 쓰기(`target_blocked.txt`) | `12` | `pep.deny` / `BUDGET_EXHAUSTED` | 3회차만 거부, 그때 호출 잔여 `3`(호출 한도가 원인이 아님), `target_blocked.txt` 미생성 |
| `E2E-52` | 다중 OS 서브프로세스 동시 경합(TOCTOU) 방어 | `MaxCalls: 3` 루트 토큰 하나로 워커 서브프로세스 6개 동시 스폰(`contended_shared.txt` 읽기) | `12` | `pep.deny` / `BUDGET_EXHAUSTED` | 정확히 3개 `Exit 0`, 3개 `Exit 12`, 원장 잔량 `0` |
| `E2E-53` | 자식 만료 후 예약 자동 회수(누수 0) 및 재위임 | 기준 시각 T: 루트 `Calls: 5` → 자식 A(`4`, TTL 60초) 교환(루트 잔여 `1`), A 미사용 → T+120초 스택으로 자식 B(`4`) 교환 및 B로 파일 읽기 | `0` | `pep.allow` / `AUTHORIZED` | B 교환·읽기 성공, A `Reclaimed == true`, 루트 잔여 `1`(= 1 + 4 회수 − 4 예약) |
| `E2E-54` | 2-Hop 분할 위임 및 합계 보존 | `Root(5) → Lead(3) → Worker(2)` 연쇄 교환, Worker로 1회 읽기 | `0` | `pep.allow` / `AUTHORIZED` | 잔여 `Root=2, Lead=1, Worker=1` + 소비 `1` = `5` |

### 수치 선택 이유
- **E2E-50**: 자식 B 요청 `4`는 루트 **클레임** `5` 이하라 정적 검사를 통과하고, 루트 **잔여** `3`을 넘어 원장 검사에서만 막힌다. 그래서 「자식 ≤ 부모 잔여」를 E2E 층위에서 증명한다(정적 검사는 TC-030-02가 맡는다).
- **E2E-51**: `MaxCalls`를 넉넉히(`5`) 두어 3회차 거부 원인이 쓰기 바이트뿐이 되게 한다. 호출 수 소진은 E2E-52와 TC-040-01이 맡는다.

### `E2E-52` 구현 주의
- 스폰은 [`catalog/helpers.go`](../../../../internal/harness/catalog/helpers.go) 159행 일대의 기존 서브프로세스 경로를 쓴다. 워커는 같은 `-replay-file`을 받으므로 030의 경로 파생에 따라 같은 `budget_ledger.json`을 본다.
- 동시 스폰 결과(3/3)는 시나리오 안에서 직접 검사하고 어긋나면 즉시 에러를 반환한다.
- 감사 역순 탐색([`assertion.go`](../../../../internal/harness/assertion.go))이 항상 `pep.deny` / `BUDGET_EXHAUSTED`를 마지막으로 보도록, 경합 직후 소진된 같은 토큰으로 `contended_blocked.txt` 쓰기를 1회 더 호출해 `Exit 12`로 수렴시킨다. `ExpectZeroMutation` 대상은 `contended_blocked.txt`.

### `E2E-53` 구현 주의
- 하네스 `MockClock`은 전진하지 않는 고정 시계다([`harness/sandbox.go`](../../../../internal/harness/sandbox.go) 36~42행). 그래서 같은 파일 경로로 **두 번째 스택**을 「T + 120초」 고정 시계로 조립해 자식 B 교환·읽기를 인프로세스로 수행한다. 오프셋 시계 스택은 [`cli/token.go`](../../../../internal/cli/token.go) 295~301행이 선례다.
- 자식 A의 「크래시」는 A를 한 번도 쓰지 않고 만료시키는 것으로 표현한다(원장 입장에서 미사용 만료와 크래시는 구별되지 않는다).
- 루트 토큰 TTL은 T+120초에도 유효하도록 충분히 길게 잡는다.
