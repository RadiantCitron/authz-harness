## 1. 목적 (Context & Why)

본 지시서는 팀장 오케스트레이터와 서브에이전트 워커 간의 OS 프로세스 격리 실행 체계를 CLI 명령(`authz-harness orchestrate spawn`, `authz-harness subagent worker`)으로 완성하고, 실제 독립 OS 자식 프로세스 기동, `stdin` JSON 프레임 전달, 표준 종료 코드 수거, 단일 `trace_id` 감사 연쇄를 종합 검증하는 작업이다.

또한 `--inject-revoke-before-io` 결함 주입 스위치를 통해 Gate 1(AuthN) 통과 후 파일 I/O 직전에 권한이 회수되는 TOCTOU(Time-of-Check to Time-of-Use) 레이스 컨디션 상황에서 파일 수정 0바이트 및 정확한 인가 거부 종료 코드(`12`) 반환을 입증하고, `go test -race`를 통해 다중 동시 스폰 시에도 데이터 레이스가 없음을 증명한다.

보안 불변식:
1. **OS 프로세스 격리 CLI 배선**: `orchestrate spawn`은 내부 고루틴이 아닌 독립된 OS 서브프로세스로 `subagent worker`를 실행한다.
2. **명령행 인자 비밀값 누출 원천 차단 (Zero Leakage in argv)**: 자식 프로세스 기동 시 토큰이나 파일 페이로드를 `argv`로 넘기지 않고 오직 `stdin` JSON 스트림으로만 주입한다.
3. **단일 감사 연쇄 (`trace_id`) 보존**: 부모의 `ORCHESTRATE_SPAWN`, 자식의 `pep-gateway` 5단계 관문, 부모의 `ORCHESTRATE_COLLECT`가 동일한 `trace_id`를 유지하며 `audit.jsonl`에 해시 체인으로 기록된다.
4. **TOCTOU 동시성 방어**: 토큰이 유효하더라도 I/O 집행 시점에 Grant가 회수되면 즉시 차단되고 디스크 쓰기 0바이트가 보장된다.

## 2. 패키지 배치 및 6계층 DAG 구조

```text
Layer 5:  [cmd/authz-harness] (main.go 서브커맨드 라우팅)
                │
                v
          [internal/cli] (orchestrate.go, subagent.go)
                │
          ┌─────┴────────────────────────┐
          v                              v
Layer 4:  [internal/orchestrator]        [internal/subagent]
          (Spawner, CleanEnv)            (SubagentWorker, JSON IPC)
                │                              │
                │                              v
Layer 3:        │                        [internal/authz/pep] (Gateway)
                │                              │
                v                              v
Layer 2:  [internal/audit, domain]       [internal/authn, authz/pdp, jail]
```

- **Layer 5 CLI (`internal/cli`, `cmd/authz-harness`)**:
  - `cmd/authz-harness/main.go`: `orchestrate`, `subagent` 서브커맨드 라우팅 추가
  - `internal/cli/orchestrate.go`: `OrchestrateRunner` 구현 (`orchestrate spawn`)
  - `internal/cli/orchestrate_test.go`: 오케스트레이터 CLI 단위 및 통합 테스트
  - `internal/cli/subagent.go`: `SubagentRunner` 구현 (`subagent worker`)
  - `internal/cli/subagent_test.go`: 서브에이전트 워커 CLI 단위 테스트
- **Layer 4 보강 (`internal/subagent/worker.go`)**:
  - `req.InjectRevokeBeforeIO` 플래그 수신 시 Gate 1 통과 후 Gate 2 직전 권한 회수를 시뮬레이션할 수 있도록 `StateStore` 또는 `Revoker` 인터페이스 연동

## 3. 세부 설계 및 계약 (APIs & Specs)

### 3.1 `subagent worker` CLI 서브커맨드 명세 (`internal/cli/subagent.go`)

자식 OS 프로세스로 실행되는 내부 워커 진입점이다.

```go
package cli

import (
    "context"
    "io"

    "authz-harness/internal/domain"
)

// SubagentRunner 는 자식 서브에이전트 프로세스 진입점을 담당하는 CLI 러너다.
type SubagentRunner struct {
    stdout       io.Writer
    stderr       io.Writer
    workspaceDir string
    statePath    string
    pubJWKSPath  string
    replayPath   string
    auditPath    string
}

func NewSubagentRunner(
    stdout, stderr io.Writer,
    workspaceDir, statePath, pubJWKSPath, replayPath, auditPath string,
) (*SubagentRunner, error)

// Run 은 subagent 서브커맨드 인자를 파싱하고 작업을 실행한다.
// 문법: authz-harness subagent worker [flags]
func (r *SubagentRunner) Run(ctx context.Context, args []string) domain.ExitCode
```

- 동작 파이프라인:
  1. `worker` 서브커맨드 파싱.
  2. PEP Gateway 의존성 조립:
     - `token.NewVerifier(pubJWKSPath, replayPath, auditWriter)`
     - `pdp.NewService(stateStore, auditWriter)`
     - `jail.NewJail(workspaceDir)`
     - `pep.NewGateway(...)`
  3. `subagent.NewWorker(gateway)` 생성 (필요 시 `stateStore` 연동 주입).
  4. `worker.ExecuteStream(ctx, os.Stdin, r.stdout)` 실행.
  5. 반환된 종료 코드(`domain.ExitCode`)를 그대로 반환.

### 3.2 `orchestrate spawn` CLI 서브커맨드 명세 (`internal/cli/orchestrate.go`)

부모 프로세스에서 서브에이전트 자식 프로세스를 기동하고 종료 코드를 수거하는 진입점이다.

```go
package cli

import (
    "context"
    "io"

    "authz-harness/internal/domain"
    "authz-harness/internal/orchestrator"
)

// OrchestrateRunner 는 오케스트레이터 서브프로세스 생성 및 제어를 담당하는 CLI 러너다.
type OrchestrateRunner struct {
    stdout       io.Writer
    stderr       io.Writer
    workspaceDir string
    statePath    string
    pubJWKSPath  string
    replayPath   string
    auditPath    string
    workerBin    string // 테스트 시 모의/커스텀 바이너리 주입 지원 (기본: os.Executable())
}

func NewOrchestrateRunner(
    stdout, stderr io.Writer,
    workspaceDir, statePath, pubJWKSPath, replayPath, auditPath string,
) (*OrchestrateRunner, error)

// SetWorkerBinaryPath 는 자식 프로세스로 실행할 바이너리 경로를 재정의한다 (테스트 지원).
func (r *OrchestrateRunner) SetWorkerBinaryPath(binPath string)

// Run 은 orchestrate 서브커맨드 인자를 파싱하고 실행한다.
// 문법: authz-harness orchestrate spawn [flags]
func (r *OrchestrateRunner) Run(ctx context.Context, args []string) domain.ExitCode
```

- `orchestrate spawn` 플래그 명세:
  - `-token <string>`: 서브에이전트에 주입할 축소 위임 Access Token (필수)
  - `-action <string>`: 수행할 파일 작업 (`file:read` 또는 `file:write`, 축약 `read`/`write` 허용, 기본 `file:read`)
  - `-file <string>`: 작업 대상 상대 경로 (필수)
  - `-data <string>`: 쓰기 작업 시 기록할 내용
  - `-timeout <duration>`: 자식 프로세스 타임아웃 (기본 `10s`)
  - `-inject-revoke-before-io`: Gate 1 통과 후 I/O 직전 Grant Revoke 결함 주입 스위치 (불리언)
  - `-trace-id <string>`: 분산 추적 식별자 (미지정 시 `orch-<nanotime>` 자동 생성)

- 동작 파이프라인:
  1. 플래그 유효성 검증 (`token`, `file` 누락 시 `ExitBadInput(2)`).
  2. Spawner 설정 조립:
     - `BinaryPath`: `r.workerBin` (기본값 `os.Executable()`)
     - `Args`: `[]string{"subagent", "worker", "-workspace", r.workspaceDir, "-state-file", r.statePath, "-pub-jwks-file", r.pubJWKSPath, "-replay-file", r.replayPath, "-audit-file", r.auditPath}`
     - `Timeout`: 지정된 타임아웃
     - `Audit`: `auditWriter`
  3. 요청 프레임 조립 (`subagent.SubagentRequest`):
     - `Version`: `"1.0"`
     - `TraceID`: traceID
     - `Token`: token
     - `Action`: normAction
     - `FilePath`: cleanFile
     - `Data`: data
     - `InjectRevokeBeforeIO`: injectRevoke
  4. `spawner.Spawn(ctx, req)` 실행 및 `SpawnResult` 수거.
  5. 결과 포맷팅 출력 (`r.stdout`):
     - `TraceID`, `ExitCode`, 소요 시간, 자식의 응답 요약(읽은 바이트/쓴 바이트/에러 사유 등).
  6. 종료 코드 반환:
     - `result.ExitCode`를 `domain.ExitCode`로 변환하여 반환 (자식이 12로 실패 시 부모 CLI도 12로 종료).

### 3.3 TOCTOU 결함 주입(`--inject-revoke-before-io`) 메커니즘

1. 부모 CLI에 `-inject-revoke-before-io` 플래그가 지정되면 `SubagentRequest.InjectRevokeBeforeIO = true`가 자식 프레임에 설정된다.
2. 자식 워커(`subagent.Worker`)는 `req.InjectRevokeBeforeIO == true`를 감지하면:
   - Gate 1(토큰 검증) 통과 후 Gate 2(PDP 인가) 호출 직전에 토큰의 Subject 또는 해당 활성 Grant를 `Revoke` 상태로 갱신한다 (`stateStore.RevokeGrant`).
3. Gate 2 PDP 인가 엔진이 최신 상태 파일을 조회할 때 Grant가 이미 회수되어 있으므로 `domain.ExitAuthzDenied(12)` 및 `ReasonGrantRevoked`로 즉시 거부된다.
4. Gate 2c(Jail) 및 Stage 5(File I/O)는 호출되지 않으며, 파일 수정은 0바이트를 유지한다.
5. 자식 프로세스는 Exit Code `12`로 종료되고, 부모 오케스트레이터는 Exit Code `12`를 정상 수집한다.

## 4. 파급 범위 및 무영향 근거 (Blast Radius & Non-Impact Proof)

- **파급 범위**:
  - `cmd/authz-harness/main.go`: `orchestrate`, `subagent` 서브커맨드 라우팅 추가
  - `internal/cli/orchestrate.go`, `internal/cli/orchestrate_test.go`: 신규 생성
  - `internal/cli/subagent.go`, `internal/cli/subagent_test.go`: 신규 생성
  - `internal/subagent/worker.go`: `InjectRevokeBeforeIO` 처리를 위한 StateStore/Revoker 연동 지원
- **무영향 근거**:
  - 기존 Phase 1, 2, 3의 핵심 보안 패키지(`internal/authz/pdp`, `internal/authn/token`, `internal/jail`, `internal/authz/pep`)의 인터페이스와 핵심 로직은 변경되지 않는다.
  - 기존 CLI 서브커맨드(`grant`, `pdp`, `keys`, `token`, `pep`)의 동작 및 플래그는 100% 하위 호환성을 유지한다.

## 5. 사전 점검 및 실패 위험 분석 (Pre-Mortem)

| 위험 요소 | 실패 시나리오 | 방어 설계 (Countermeasure) |
|---|---|---|
| **`os.Executable()` 테스트 환경 불일치** | `go test` 실행 시 바이너리가 실제 CLI가 아닌 테스트 러너 바이너리로 인식됨 | `OrchestrateRunner`에 `workerBin` 필드 및 `SetWorkerBinaryPath` 제공. 통합 테스트 시 임시 CLI 바이너리 빌드(`go build`) 후 주입 |
| **파이프 버퍼 데드락** | 자식 프로세스가 표준 에러나 출력을 대량 쏟아낼 때 파이프가 블로킹됨 | `spawner.go`에서 `bytes.Buffer`를 `cmd.Stdout`/`cmd.Stderr`에 바인딩하여 `os/exec` 내부 고루틴으로 자동 소진 |
| **자식 프로세스 좀비화** | 자식 프로세스가 무한 대기 시 부모 프로세스가 멈춤 | `context.WithTimeout` 강제 적용 및 컨텍스트 취소 시 OS 레벨 SIGKILL 보장 |
| **감사 로그 파일 동시 쓰기 충돌** | 부모와 자식 프로세스가 `audit.jsonl`에 동시 쓰기를 시도할 때 손상 발생 | `internal/audit.Writer`의 `syscall.Flock` 기반 상호 배제 잠금 강제 |
| **Data Race** | 동시 다중 스폰 시 고루틴 경합 | `go test -race` 실행으로 모든 동시성 시나리오 데이터 레이스 0건 검증 |

## 6. 4층위 검증 범위 설계 (Verification Grid)

- **1층위 (CLI 플래그 및 입력 검증)**:
  - 필수 플래그 누락 시 `ExitBadInput(2)` 즉시 반환 검증
  - 액션 표준화(`read`, `write`, `file:read`, `file:write`) 정상 매핑 검증
- **2층위 (자식 워커 단독 프로세스 검증)**:
  - `subagent worker` 서브커맨드 실행 및 `stdin` 파이프 JSON 주입
  - 성공(0), 토큰 무효(11), 인가 거부(12), 경로 위반(13), 감사 실패(15) 정상 종료 코드 검증
- **3층위 (오케스트레이터 스폰 및 부모 수거 통합 검증)**:
  - `orchestrate spawn` 실행으로 실제 OS 자식 프로세스 기동
  - 부모 프로세스가 자식의 Exit Code를 정확히 수거하고 자신의 종료 코드로 전파하는지 확인
  - `audit.jsonl`에 단일 `trace_id`로 부모-자식 감사 체인 순차 기록 검증
- **4층위 (결함 주입 및 동시성 검증)**:
  - `--inject-revoke-before-io` 결함 주입 시 Exit Code 12 수거 및 파일 0바이트 쓰기 입증
  - 다중 동시 `orchestrate spawn` 실행 시 `go test -race` 100% 무결성 통과

## 7. 10대 표준 인수 테스트 시나리오 (Acceptance Criteria)

| 번호 | 시나리오명 | 입력 조건 | 기대 결과 (Exit Code & 동작) |
|---|---|---|---|
| **TC-01** | 자식 워커 정상 파일 읽기 | 유효 토큰, 허용 경로, `file:read` JSON 프레임 주입 | Exit Code 0, `stdout`에 읽은 파일 내용 포함된 JSON 응답 |
| **TC-02** | 자식 워커 잘못된 JSON 프레임 | 손상된 JSON 문자열 주입 | Exit Code 2 (`ExitBadInput`), JSON 에러 응답 |
| **TC-03** | 자식 워커 위조/누락 토큰 | 빈 토큰 또는 서명 위조 토큰 주입 | Exit Code 11 (`ExitTokenInvalid`), 감사 기록 |
| **TC-04** | 자식 워커 권한 거부 | 스코프에 없는 리소스 파일 쓰기 시도 | Exit Code 12 (`ExitAuthzDenied`), 파일 수정 0바이트 |
| **TC-05** | 자식 워커 경로 탈출 시도 | `../../etc/passwd` 파일 읽기 시도 | Exit Code 13 (`ExitPathViolation`), 탈출 차단 |
| **TC-06** | 오케스트레이터 정상 스폰 및 실행 | `orchestrate spawn` 유효 토큰 + 정상 파일 읽기 | 부모 Exit Code 0, 자식 응답 내용 출력 |
| **TC-07** | 오케스트레이터 필수 인자 누락 | `-token` 또는 `-file` 누락 | 부모 Exit Code 2 (`ExitBadInput`), 자식 미실행 |
| **TC-08** | 오케스트레이터 자식 거부 수거 | 자식에게 권한 없는 파일 쓰기 요청 주입 | 자식 Exit Code 12 수거, 부모 최종 Exit Code 12 반환 |
| **TC-09** | TOCTOU 결함 주입 방어 검증 | `orchestrate spawn --inject-revoke-before-io` | Gate 2 인가 거부, 자식 Exit Code 12 수거, 파일 수정 0바이트 |
| **TC-10** | 부모-자식 단일 감사 체인 & 동시성 | 5개 병렬 스폰 실행 및 `audit.jsonl` 검증 | 모든 스폰 동일 `trace_id` 연쇄 보존, `go test -race` 무결 통과 |
