# 010. 서브에이전트 워커 모듈 및 stdin JSON 프레임 프로토콜 구현지시서

> **상태**: `Draft`
> **선행 조건**: Phase 3 (PEP 게이트웨이 및 Workspace File Jail) 완료
> **상위 대시보드**: [README.md](../README.md) | **마스터 설계**: [ROADMAP.md](../ROADMAP.md)

---

## 1. 목적 (Context & Why)

본 지시서는 팀장 오케스트레이터(Layer 4: `internal/orchestrator`)가 생성한 독립 OS 자식 프로세스 내에서 동작할 **서브에이전트 워커 모듈(`internal/subagent`)**과 부모-자식 간 **`stdin` 단일 JSON 프레임 프로토콜**을 구축하는 작업이다.

보안 불변식에 따라:
1. **토큰 명령행 노출 금지**: `ps -ef` 등 프로세스 목록에서 토큰, 파일명, 페이로드가 노출되지 않도록 모든 작업 지시는 `stdin` 스트림의 단일 JSON 프레임으로 수령한다.
2. **단일 감사 연쇄 (`trace_id`)**: 부모의 `trace_id`를 프레임으로 수령하여 자식 프로세스의 PEP 감사 로그 및 응답 프레임까지 단일 감사 체인으로 연결한다.
3. **원시 I/O 배제 (No Raw File I/O)**: 자식 워커는 직접 `os.Open`이나 `os.WriteFile`을 호출하지 않고, Phase 3에서 검증된 PEP 게이트웨이(`internal/authz/pep.Gateway`)를 통해서만 5단계 관문 집행을 수행한다.
4. **표준 종료 코드(Exit Code) 보장**: 관문 판정 결과에 따라 표준 종료 코드(`0`, `11`~`15`)를 프로세스 종료 코드로 반환한다.
5. **거부 시 무부작용 원칙 (Zero Side-Effects on Deny)**: 거부된 모든 요청에 대해 파일 시스템 부작용 0바이트를 보장한다.

## 2. 패키지 배치 및 6계층 DAG 구조

```text
Layer 4:  [internal/subagent] (Subagent Worker & Protocol Parser)
                │
                v
Layer 3:  [internal/authz/pep] (Gateway: 5-Stage Gate Enforcement)
                │
                v
Layer 2:  [internal/authn, internal/authz/pdp, internal/jail]
                │
                v
Layer 0/1: [internal/domain, internal/audit]
```

- **Layer 4 (`internal/subagent`)**:
  - `protocol.go`: `SubagentRequest`, `SubagentResponse` 프레임 스키마 및 직렬화/역직렬화
  - `worker.go`: `stdin` 스트림 파싱, PEP 게이트웨이 호출 조율, `stdout` 응답 프레임 기록 및 Exit Code 매핑
- **금지 결합 (Forbidden Couplings)**:
  - `internal/subagent`는 서명 개인키(Zone A)를 로드하거나 참조하지 않는다.
  - `internal/subagent`는 원시 파일 시스템 API(`os.OpenFile` 등)를 직접 호출하지 않는다.

## 3. 세부 설계 및 프레임 프로토콜 계약

### 3.1 요청/응답 프레임 스키마 (`internal/subagent/protocol.go`)

```go
package subagent

import "authz-harness/internal/domain"

// SubagentRequest 는 부모 오케스트레이터가 stdin 파이프로 주입하는 단일 실행 요청 프레임이다.
type SubagentRequest struct {
    Version               string `json:"version"`                 // 프로토콜 버전 (기본 "1.0")
    TraceID               string `json:"trace_id"`                // 부모로부터 전파된 분산 추적 식별자
    Token                 string `json:"token"`                   // 축소 위임된 Bearer Access Token
    Action                string `json:"action"`                  // "file:read" 또는 "file:write"
    FilePath              string `json:"file_path"`               // 대상 리소스 상대 경로
    Data                  string `json:"data,omitempty"`          // 쓰기 작업 시 기록할 내용
    InjectRevokeBeforeIO  bool   `json:"inject_revoke_before_io"` // 결함 주입 스위치 (TOCTOU 검증용)
}

// SubagentResponse 는 자식 서브에이전트가 stdout 파이프로 반환하는 단일 실행 결과 프레임이다.
type SubagentResponse struct {
    TraceID      string            `json:"trace_id"`                // 요청의 trace_id와 일치
    ExitCode     int               `json:"exit_code"`               // 표준 종료 코드 (0, 11~15)
    Action       string            `json:"action"`                  // 실행된 액션
    FilePath     string            `json:"file_path"`               // 대상 리소스 상대 경로
    BytesRead    int               `json:"bytes_read,omitempty"`    // 읽은 바이트 수
    BytesWritten int               `json:"bytes_written,omitempty"` // 기록된 바이트 수
    Output       string            `json:"output,omitempty"`        // 파일 읽기 결과
    Error        string            `json:"error,omitempty"`         // 에러 메시지
    Reason       domain.ReasonCode `json:"reason,omitempty"`        // 세부 인가/인증 사유 코드
}
```

### 3.2 서브에이전트 워커 인터페이스 및 실행 흐름 (`internal/subagent/worker.go`)

```go
package subagent

import (
    "context"
    "io"

    "authz-harness/internal/authz/pep"
)

// Worker 는 stdin JSON 프레임을 수신하여 PEP 게이트웨이를 경유해 작업을 집행하는 서브에이전트 인터페이스다.
type Worker interface {
    // Execute 는 파싱된 요청을 바탕으로 PEP 게이트웨이를 호출하고 응답과 Exit Code를 반환한다.
    Execute(ctx context.Context, req SubagentRequest) (SubagentResponse, int)

    // ExecuteStream 은 io.Reader(stdin)에서 JSON 프레임을 읽어 작업을 집행하고,
    // io.Writer(stdout)에 JSON 응답을 기록한 뒤 프로세스 종료 코드를 반환한다.
    ExecuteStream(ctx context.Context, in io.Reader, out io.Writer) int
}
```

### 3.3 실행 알고리즘 및 표준 Exit Code 매핑 불변식

1. **입력 파싱**:
   - `in`으로부터 JSON 디코딩 실패 시: `ExitInvalidArgs (14)` 반환 및 에러 응답 프레임 작성.
   - `TraceID` 누락 시: `ExitInvalidArgs (14)` 반환.
   - `Token` 누락 시: `ExitAuthNFailure (11)` 반환.
   - `Action` 미지원(`file:read`, `file:write` 외) 또는 `FilePath` 공백 시: `ExitInvalidArgs (14)` 반환.
2. **PEP 게이트웨이 요청 변환**:
   - `pep.Request` 생성:
     - `TraceID`: `req.TraceID`
     - `RawToken`: `req.Token`
     - `Action`: `domain.Action(req.Action)`
     - `Resource`: `req.FilePath`
     - `Data`: `[]byte(req.Data)`
3. **PEP 관문 집행 (`pepGateway.Execute`)**:
   - PEP 게이트웨이를 호출하여 Gate 1(AuthN) -> Gate 2(PDP) -> Gate 2c(Jail) -> Gate 5(Audit) -> Confined I/O 순차 집행.
4. **결과 변환 및 Exit Code 매핑**:
   - PEP 판정 성공(`Response.Allowed == true`):
     - `ExitSuccess (0)` 반환
     - 읽기 작업: `BytesRead`, `Output` 채움
     - 쓰기 작업: `BytesWritten` 채움
   - PEP 판정 실패(`Response.Allowed == false` 또는 에러):
     - `pepResp.Reason`에 따른 표준 종료 코드 매핑:
       - 인증 실패 사유(`REASON_TOKEN_*`, `REASON_CLIENT_*`): `ExitAuthNFailure (11)`
       - 인가 거부 사유(`REASON_NO_ACTIVE_GRANT`, `REASON_GRANT_REVOKED`, `REASON_SCOPE_MISMATCH`, `REASON_EPOCH_REVOKED`): `ExitAuthZDenied (12)`
       - 경로 위반 사유(`REASON_PATH_*`, `REASON_SYMLINK_*`): `ExitPathViolation (13)`
       - 감사 기록 실패 사유(`REASON_AUDIT_WRITE_FAILED`): `ExitAuditFailure (15)`
       - 기타 인자 오류: `ExitInvalidArgs (14)`
5. **응답 프레임 출력**:
   - `out`에 `SubagentResponse` JSON 인코딩 기록 (줄바꿈 포함).

## 5. 인수 테스트 시나리오 (10대 표준 검증망)

| 번호 | 시나리오 명 | 입력 (SubagentRequest / stdin) | 기대 결과 (Exit Code / Response) | 보안 검증 포인트 |
|---|---|---|---|---|
| **TC-01** | 정상 파일 읽기 | 유효한 Read 토큰, `docs/task.txt` | Exit Code `0`, `output` 일치, `bytes_read > 0` | 5단계 관문 통과 및 정규 I/O 집행 |
| **TC-02** | 정상 파일 쓰기 | 유효한 Write 토큰, `docs/out.txt`, `Hello` | Exit Code `0`, `bytes_written == 5`, 파일 생성 확인 | 정상 권한 축소 쓰기 집행 |
| **TC-03** | 토큰 누락 | `token: ""` | Exit Code `11`, `reason: TOKEN_MISSING` | Gate 1 즉시 차단 및 파일 접근 차단 |
| **TC-04** | 위조된 토큰 | 서명 위조 토큰 주입 | Exit Code `11`, `reason: TOKEN_SIGNATURE_INVALID` | 무효 토큰 파일 I/O 원천 차단 |
| **TC-05** | PDP 인가 거부 (미인가 액션) | Read 전용 토큰으로 `file:write` 요청 | Exit Code `12`, `reason: ACTION_MISMATCH`, 파일 0바이트 | 축소 위임 권한 초과 집행 차단 |
| **TC-06** | 상위 탈출 경로 공격 | `file_path: "../../etc/passwd"` | Exit Code `13`, `reason: PATH_TRAVERSAL`, 파일 0바이트 | Jail 경계 탈출 차단 |
| **TC-07** | 심볼릭 링크 외부 탈출 | 외부 심볼릭 링크 경로 요청 | Exit Code `13`, `reason: SYMLINK_ESCAPE`, 파일 0바이트 | 물리적 탈출 차단 |
| **TC-08** | 기형적 stdin JSON 파싱 오류 | `"invalid-json-stream{{"` | Exit Code `14`, JSON 에러 응답 | 입력 무결성 방어 및 패닉 0건 |
| **TC-09** | 단일 trace_id 연쇄 검증 | 특정 `trace_id: "tr-test-9999"` 주입 | 응답 `trace_id` 일치 및 `audit.jsonl`에 동일 trace 기록 | 부모-자식 분산 추적 무결성 |
| **TC-10** | Fail-Closed 감사 실패 방어 | 감사 파일 쓰기 실패 모드 주입 | Exit Code `15`, `reason: AUDIT_WRITE_FAILED`, 쓰기 0바이트 | 감사 없는 파일 변경 원천 차단 |
