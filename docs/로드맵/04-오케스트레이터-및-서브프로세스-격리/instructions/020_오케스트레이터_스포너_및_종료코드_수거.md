## 1. 목적 (Context & Why)

본 지시서는 팀장 오케스트레이터(Layer 4: `internal/orchestrator`)가 RFC 8693 축소 위임(Downscoping) 토큰을 받아 독립된 OS 자식 프로세스(`os/exec`)로 서브에이전트 워커를 실행하고, `stdin` 단일 JSON 프레임 프로토콜로 토큰과 `trace_id`를 전달한 뒤 자식의 `stdout` 응답과 표준 종료 코드(Exit Code)를 안전하게 수거하는 **오케스트레이터 Spawner 모듈**을 구축하는 작업이다.

보안 불변식에 따라:
1. **OS 프로세스 완전 격리 (No Goroutines)**: 서브에이전트를 부모 프로세스 내부의 고루틴(`go func()`)으로 실행하지 않고, 반드시 `os/exec`를 통한 독립 OS 자식 프로세스로 분리하여 메모리와 파일 디스크립터를 완전 격리한다.
2. **클린 환경변수 화이트리스트 (Clean Environment Boundary)**: 부모 프로세스의 전체 환경변수를 무분별하게 상속하지 않고, 실행에 필수적인 시스템 환경변수(`PATH`, `TMPDIR`, `HOME` 등)만 엄격히 선별하며 Zone A 서명 개인키 경로 등 민감 정보의 상속을 원천 차단한다.
3. **토큰 명령행 노출 금지 (Zero Leakage in argv)**: 토큰 및 실행 페이로드를 명령행 인자(`argv`)에 일체 포함하지 않고 `stdin` 스트림 JSON 프레임으로만 주입하여 `ps` 명령 등을 통한 노출을 방지한다.
4. **단일 감사 연쇄 (`trace_id`)**: 부모의 `trace_id`를 프레임에 주입하고, 부모 로거(`audit.Writer`)에 `ORCHESTRATE_SPAWN` 및 `ORCHESTRATE_COLLECT` 이벤트를 기록하여 분산 단일 감사 체인을 보존한다.
5. **파이프 데드락 및 좀비화 방어**: 버퍼링 I/O 및 `context.WithTimeout`을 강제하여 무한 대기 및 프로세스 좀비화를 원천 차단한다.

## 2. 패키지 배치 및 6계층 DAG 구조

```text
Layer 4:  [internal/orchestrator] (Spawner, CleanEnv, ExitCode Collector)
                │                 │
                │                 └──> [internal/subagent] (SubagentRequest / SubagentResponse IPC Frame)
                v
Layer 0/1: [internal/domain, internal/audit]
```

- **Layer 4 (`internal/orchestrator`)**:
  - `cleanenv.go`: 클린 환경변수 화이트리스트 필터링 (`SanitizeEnv`)
  - `spawner.go`: `Spawner` 인터페이스, `SubprocessSpawner` 구현체 (`Spawn`), 감사 연쇄 및 종료 코드 수거
  - `spawner_test.go`: 클린 환경 정제, 프로세스 스폰, Exit Code(0, 11~15) 수거, 타임아웃, 동시성 검증
- **의존성 규칙 (Dependency Rules)**:
  - `internal/orchestrator`는 Layer 4 컴포넌트로서 `internal/subagent`, `internal/domain`, `internal/audit`만 참조한다.
  - 서명 개인키(Zone A: `internal/authn/keys`)를 직접 참조하지 않는다.
  - 원시 파일 조작 없이 프로세스 생성 및 감사 기록만 담당한다.

## 3. 세부 설계 및 계약 (APIs & Specs)

### 3.1 클린 환경변수 화이트리스트 (`cleanenv.go`)

자식 프로세스 생성 시 부모 프로세스의 전체 환경(`os.Environ()`)을 상속하지 않고 오직 최소 필수 변수만 전달한다.

```go
package orchestrator

// AllowedEnvKeys 는 서브에이전트 자식 프로세스에 상속이 허용된 환경변수 화이트리스트 키 목록이다.
var AllowedEnvKeys = []string{
    "PATH",
    "TMPDIR",
    "TEMP",
    "TMP",
    "HOME",
    "USER",
    "LANG",
    "LC_ALL",
}

// BlockedEnvPrefixes 는 자식 프로세스 상속이 엄격히 차단되는 민감 환경변수 접두사 목록이다.
var BlockedEnvPrefixes = []string{
    "ZONE_A_",
    "SECRET_",
    "AUTHZ_KEY_",
    "GO",
    "DEBUG",
}

// SanitizeEnv 는 입력 환경변수 목록에서 화이트리스트에 부합하고 차단 접두사를 갖지 않는 환경변수만 추출한다.
// 추가 환경변수(extraEnv)가 주어지면 동일한 차단 규칙을 통과한 것에 한해 추가한다.
func SanitizeEnv(environ []string, extraEnv ...string) []string
```

### 3.2 Spawner 인터페이스 및 실행 모델 (`spawner.go`)

```go
package orchestrator

import (
    "context"
    "time"

    "authz-harness/internal/audit"
    "authz-harness/internal/subagent"
)

// SpawnConfig 는 서브에이전트 자식 프로세스 실행에 필요한 설정이다.
type SpawnConfig struct {
    BinaryPath string        // 실행할 바이너리 경로 (기본: os.Executable())
    Args       []string      // 명령행 인자 (주의: 토큰 노출 금지)
    Timeout    time.Duration // 타임아웃 (기본: 10초)
    Audit      audit.Writer  // 부모 감사 로거 (선택적)
    ExtraEnv   []string      // 추가 안전 환경변수 (선택적)
}

// SpawnResult 는 자식 프로세스 실행 후 수거된 결과다.
type SpawnResult struct {
    TraceID      string                     `json:"trace_id"`
    ExitCode     int                        `json:"exit_code"`
    Response     *subagent.SubagentResponse `json:"response,omitempty"`
    StdoutRaw    string                     `json:"stdout_raw,omitempty"`
    StderrRaw    string                     `json:"stderr_raw,omitempty"`
    Duration     time.Duration              `json:"duration"`
    TimedOut     bool                       `json:"timed_out"`
}

// Spawner 는 서브에이전트 자식 프로세스를 생성하고 제어하는 인터페이스다.
type Spawner interface {
    // Spawn 은 독립 OS 자식 프로세스를 실행하고 stdin으로 요청을 주입한 뒤 결과를 수거한다.
    Spawn(ctx context.Context, req subagent.SubagentRequest) (*SpawnResult, error)
}
```

### 3.3 자식 프로세스 제어 및 Exit Code 수거 파이프라인

1. **사전 준비 및 입력 검증**:
   - `req.TraceID` 누락 시 즉시 에러 반환.
   - 요청 프레임 JSON 직렬화 (`json.Marshal(req)`).
2. **부모 사전 감사 이벤트 (`ORCHESTRATE_SPAWN`)**:
   - `audit.Writer`가 주입된 경우 감사 로그 기록:
     - `Actor`: `"orchestrator"`
     - `Action`: `req.Action`
     - `Resource`: `req.FilePath`
     - `TraceID`: `req.TraceID`
     - `Step`: `"ORCHESTRATE_SPAWN"`
3. **`os/exec` 자식 프로세스 조립**:
   - `ctx, cancel := context.WithTimeout(ctx, cfg.Timeout)` 적용.
   - `cmd := exec.CommandContext(ctx, cfg.BinaryPath, cfg.Args...)`
   - 클린 환경변수 주입: `cmd.Env = SanitizeEnv(os.Environ(), cfg.ExtraEnv...)`
   - `stdin`: `cmd.Stdin = bytes.NewReader(reqBytes)` (단일 프레임 주입)
   - `stdout` / `stderr`: `cmd.Stdout = &stdoutBuf`, `cmd.Stderr = &stderrBuf` (파이프 데드락 원천 차단)
4. **프로세스 실행 및 종료 코드 수거**:
   - `err := cmd.Run()`
   - 종료 코드 판정:
     - `err == nil`: `ExitCode = 0`
     - `exitErr, ok := err.(*exec.ExitError)`: `ExitCode = exitErr.ExitCode()`
     - 컨텍스트 취소 시 (`ctx.Err() != nil`): `TimedOut = true`, `ExitCode = 1`
   - `stdoutBuf`에서 `subagent.SubagentResponse` JSON 역직렬화.
5. **부모 사후 감사 이벤트 (`ORCHESTRATE_COLLECT`)**:
   - 감사 로그 기록:
     - `Step`: `"ORCHESTRATE_COLLECT"`
     - `TraceID`: `req.TraceID`
     - `Success`: `result.ExitCode == 0`
     - `Metadata`: `map[string]interface{}{"exit_code": result.ExitCode, "duration_ms": duration.Milliseconds()}`

## 4. 사전 점검 및 실패 위험 분석 (Pre-Mortem)

| 위험 요소 | 실패 시나리오 | 방어 설계 (Countermeasure) |
|---|---|---|
| **파이프 데드락** | 자식이 대량의 출력을 쏟아낼 때 `StdoutPipe()` 버퍼가 차서 중단 | `bytes.Buffer`를 `cmd.Stdout`, `cmd.Stderr`에 직접 바인딩하여 `os/exec` 내부 고루틴으로 자동 드레인 |
| **자식 프로세스 좀비화/타임아웃** | 자식이 루프에 빠져 무한 대기 | `context.WithTimeout` 강제 및 `exec.CommandContext` 기반 SIGKILL 보장 |
| **토큰 유출 위험** | 명령행 인자(`argv`)에 토큰 노출 | `cfg.Args`에 토큰 전달 원천 금지, `stdin` 버퍼로만 전송 |
| **부모 환경변수 오염** | 부모의 Zone A 서명키 환경변수가 자식에게 상속 | `SanitizeEnv` 화이트리스트 필터링 필수 적용 |
| **종료 코드 유실** | 자식이 0이 아닌 코드로 종료 시 Go `cmd.Run()` 에러로 종료 코드 추출 누락 | `errors.As(err, &exitErr)` 패턴으로 `exitErr.ExitCode()` 정확한 추출 |

## 5. 4층위 검증 범위 설계 (Verification Grid)

- **1층위 (환경 정제 및 단위 검증)**:
  - `SanitizeEnv` 화이트리스트 변수(`PATH`, `TMPDIR`, `HOME`) 통과 검증
  - `ZONE_A_*`, `SECRET_*`, `AUTHZ_KEY_*`, `GO*`, `DEBUG*` 변수 차단 검증
- **2층위 (스포너 및 Exit Code 계약 검증)**:
  - Go 표준 `TestHelperProcess` 패턴을 활용하여 독립 OS 자식 프로세스를 기동
  - 정상 실행(Exit Code 0) 및 표준 에러 종료 코드(`11`, `12`, `13`, `14`, `15`) 정확한 수거 검증
- **3층위 (감사 체인 및 상태 정합성 검증)**:
  - 부모 `trace_id`가 자식 프레임 및 감사 이벤트(`ORCHESTRATE_SPAWN`, `ORCHESTRATE_COLLECT`)에 단일 체인으로 보존되는지 확인
  - 감사 로그 해시 체인 무결성 확인
- **4층위 (타임아웃 및 동시성 검증)**:
  - 타임아웃 초과 시 자식 프로세스 종료 및 `TimedOut = true` 확인
  - `go test -race` 실행 시 다중 스폰 경합 없음 확인

## 6. 10대 표준 인수 테스트 시나리오 (Acceptance Criteria)

| 번호 | 시나리오명 | 입력 조건 | 기대 결과 (Exit Code & 동작) |
|---|---|---|---|
| **TC-01** | 화이트리스트 환경변수 보존 | `PATH`, `TMPDIR`, `HOME` 포함 환경변수 슬라이스 | 해당 변수들만 정상 보존됨 |
| **TC-02** | 민감/금지 환경변수 차단 | `ZONE_A_KEY_PATH`, `SECRET_TOKEN`, `GO_ENV` 포함 슬라이스 | 해당 변수들이 완전 제거됨 |
| **TC-03** | 정상 서브에이전트 스폰 및 성공 수거 | 유효한 요청 프레임 주입, 헬퍼 프로세스 정상 응답 | `ExitCode == 0`, `Response.ExitCode == 0`, `Duration > 0` |
| **TC-04** | 서브에이전트 인가 거부(12) 수거 | 스코프 불일치 요청, 자식 프로세스 Exit Code 12 반환 | `ExitCode == 12`, `Response.ExitCode == 12` 수거 |
| **TC-05** | 서브에이전트 탈출 위반(13) 수거 | 경로 탈출 요청, 자식 프로세스 Exit Code 13 반환 | `ExitCode == 13`, `Response.ExitCode == 13` 수거 |
| **TC-06** | 서브에이전트 토큰 무효(11) 수거 | 위조 토큰 요청, 자식 프로세스 Exit Code 11 반환 | `ExitCode == 11`, `Response.ExitCode == 11` 수거 |
| **TC-07** | 입력 검증 (TraceID 누락) | `req.TraceID == ""` | 스폰 실행 전 에러 반환, 프로세스 미실행 |
| **TC-08** | 부모 감사 연쇄 검증 | 감사 로거 주입 후 스폰 실행 | `ORCHESTRATE_SPAWN`, `ORCHESTRATE_COLLECT` 순차 기록 및 동일 `trace_id` 확인 |
| **TC-09** | 컨텍스트 타임아웃 차단 | 헬퍼 프로세스 무한 대기(`time.Sleep`), 타임아웃 50ms 설정 | 컨텍스트 취소, 프로세스 강제 종료, `TimedOut == true` |
| **TC-10** | 다중 동시 스폰 안정성 | 10개 고루틴 동시 스폰 실행 | 데이터 레이스 없이 모든 프로세스 결과 개별 수거 (`go test -race`) |
