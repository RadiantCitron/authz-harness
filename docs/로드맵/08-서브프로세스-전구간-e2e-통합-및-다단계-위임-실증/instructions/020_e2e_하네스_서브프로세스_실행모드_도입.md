## 1. 목적 및 배경

현재 `authz-harness run --scenario all`로 구동되는 30대 시나리오 카탈로그는 같은 프로세스 안에서 `stack.PEP.Execute()`를 직접 호출하고 있어, 실제 OS 서브프로세스 격리 시뮬레이터라는 정체성을 온전히 보여주지 못하고 있습니다.
본 단계에서는 `authz-harness run` 명령어에 **`--execution-mode subprocess|inproc`** 옵션을 도입하고(기본값: `subprocess`), 테스트 실행 시 바이너리를 임시 디렉터리에 1회 빌드·캐싱하여, 각 시나리오가 실제 OS 서브프로세스(`authz-harness subagent worker`)를 스폰하여 실행되고 4중 검증(Quad-Assertion)을 통과하도록 인프라를 확립합니다.

## 2. 파급 범위와 무영향 근거 증명

- **변경 대상 컴포넌트**:
  - `internal/cli/run.go`: `--execution-mode` CLI 플래그 파싱 및 러너 전달
  - `internal/harness/runner.go`: `ExecutionMode` 설정 및 시나리오 실행 컨텍스트에 스포너 주입
  - `internal/harness/catalog/helpers.go`: `ExecuteHarnessAction` 헬퍼 함수를 추가하여 모드에 따라 서브프로세스(`SubprocessSpawner`) 또는 인메모리(`PEP.Execute`)로 라우팅
  - `internal/harness/catalog/*.go`: 시나리오 실행부를 `ExecuteHarnessAction`으로 점진 전환
- **무영향 근거 증명**:
  - 기존 인메모리 실행 경로(`--execution-mode inproc`)를 온전히 보존하므로, 빠른 단위 테스트나 레거시 동작이 100% 호환됩니다.
  - 시나리오 메타데이터와 기대 결과(Quad-Assertion) 정의는 단 한 줄도 수정되지 않습니다.

## 3. 세부 구현 명세

### 3.1 바이너리 캐싱 프로바이더 (`internal/harness/binary.go`)
- `type BinaryProvider interface { GetBinaryPath() (string, error) }`
- `type CachedBinaryProvider struct`:
  - `sync.Once`를 사용하여 첫 요청 시 `go build -o <tempDir>/authz-harness ./cmd/authz-harness` 실행.
  - 빌드 성공 시 바이너리 경로 반환, 실패 시 에러 캐싱.

### 3.2 시나리오 통합 액션 실행기 (`helpers.go`)
```go
type ActionRequest struct {
    Token    string
    Action   domain.Action
    Resource string
    Data     []byte
    TraceID  string
}

func executeHarnessAction(ctx context.Context, stack *harnessStack, req ActionRequest, mode harness.ExecutionMode) (domain.ExitCode, error) {
    if mode == harness.ModeSubprocess {
        spawner, err := orchestrator.NewSubprocessSpawner(orchestrator.SpawnConfig{
            BinaryPath: stack.Env.BinaryPath,
            Args:       []string{"subagent", "worker", "-workspace", stack.Env.WorkspaceDir, ...},
            Audit:      stack.AuditWriter,
        })
        if err != nil { return domain.ExitInternalError, err }
        res, err := spawner.Spawn(ctx, subagent.SubagentRequest{...})
        return domain.ExitCode(res.ExitCode), err
    }
    // ModeInProc
    res, err := stack.PEP.Execute(ctx, pep.Request{...})
    return res.ExitCode, err
}
```
