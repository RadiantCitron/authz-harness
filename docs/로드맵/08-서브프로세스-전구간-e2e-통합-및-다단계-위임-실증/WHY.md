## 1. 왜 이미 완성된 프로그램을 두고 08번 로드맵을 시작하는가? (Why)

우리는 00번부터 07번 로드맵까지 완주하며, 도메인 규칙을 순수하게 보호하고 단일 관문(단일 입구·단일 출구)을 통해 감사 도장(해시 체인)을 찍는 단단한 권한 엔진을 완성했습니다. 30가지 보안 공격 시나리오가 모두 정상적으로 차단되고 통과합니다.

하지만 우리는 스스로에게 가장 본질적인 질문을 던져야 합니다:
> **"우리가 만든 프로그램의 진짜 정체성은 무엇인가?"**

이 프로젝트의 본질은 단순한 계산기나 단위 테스트 코드가 아니라, **"실제 격리된 자식 일꾼(OS 서브프로세스)을 띄우고, 권한을 쪼개어 맡긴 뒤, 위험한 행동을 할 때 문지기(PEP)가 정확히 가로막는 것을 눈으로 증명하는 시뮬레이터(Test Harness)"**입니다.

그러나 현재 완성된 코드의 안쪽을 들여다보면, 아주 중요한 모순이 하나 숨어 있었습니다:
- 부모와 자식 프로세스를 실제로 띄워보는 훌륭한 엔진(`SubprocessSpawner`)은 이미 만들어져 있습니다.
- 하지만 정작 이 프로그램의 간판이자 대표 쇼케이스인 **30가지 종합 시험(`run --scenario all`)**을 돌려보면, 자식 프로세스를 단 한 번도 띄우지 않고 **같은 방(같은 프로세스 메모리) 안에서 함수를 직접 호출하는 방식**으로만 시험을 치르고 있었습니다.

이것은 마치 **"실제 도로 주행 시험을 치를 수 있는 진짜 자동차를 만들어 두고, 최종 면허 시험은 실내 시뮬레이터 화면만 보고 통과시켜 주는 것"**과 같습니다.

이번 08번 로드맵은 이 간극을 100% 해소하여, **"간판에 걸린 말과 실제 안에서 돌아가는 엔진이 완벽하게 일치하는 진짜 다중 프로세스 권한 하네스"**로 거듭나기 위해 시작합니다.

## 2. 왜 '다단계(Multi-Hop) 프로세스 위임'과 '감사 타임라인'이 핵심인가?

현실의 기업 시스템이나 여러 인공지능 에이전트가 협동하는 환경을 상상해 보십시오:

1. **에이전트는 1대1로만 일하지 않습니다 (다단계 사슬)**:
   - 총괄 오케스트레이터(팀장)가 중간 관리자 에이전트(기획자)에게 일을 맡기고, 중간 관리자가 다시 전문 작업 에이전트(문서 작성자)에게 세부 업무를 맡깁니다.
   - 이때 가장 위험한 사고는 **"중간 관리자가 자기도 가지고 있지 않은 권한을 아랫사람에게 쥐여주거나, 아랫사람이 받은 권한을 넘어서서 중요한 파일을 건드리는 것"**입니다.
   - 우리는 총괄 팀장(PID 1) → 중간 관리자(PID 2) → 말단 일꾼(PID 3)으로 이어지는 **3단계의 실제 독립된 프로세스 사슬**을 띄우고, 권한이 단계마다 조금씩 깎여나가는 과정(축소 위임)과 월권 시도가 그 자리에서 즉시 차단되는 모습을 명백한 증거로 보여주어야 합니다.

2. **기록이 아무리 완벽해도 사람이 읽지 못하면 소용없습니다 (타임라인 시각화)**:
   - 여러 프로세스가 찰나의 순간에 서로 다른 방에서 일을 벌이고 장부에 기록을 남기면, 장부 파일(JSONL)에는 수많은 글자가 빽빽하게 쌓입니다.
   - 외부 면접관이나 보안 감사관이 보았을 때, **"누가 누구에게 권한을 위임했고, 어떤 자식 프로세스가 언제 어디서 무슨 이유로 막혔는지"**를 한눈에 직관적으로 보여주는 시간표(타임라인)와 족보(프로세스 트리)가 터미널에 아름답게 펼쳐져야 비로소 시스템의 신뢰성을 눈으로 체감할 수 있습니다.

## 3. 왜 딱 이 정도 범위까지만 하는가? (Why this scope)

이번 08번 로드맵의 범위는 명확합니다:

- **하지 않는 것 (Non-Goals)**:
  - 외부 거대 LLM 모델 연동이나 복잡한 웹 프론트엔드를 만들지 않습니다.
  - 리눅스 커널의 복잡한 컨테이너(cgroups, namespaces) 기술로 도망가지 않습니다.
- **반드시 달성하는 것 (Goals)**:
  - 표준 Go 환경에서 지원하는 가장 확실하고 정직한 방법(OS 서브프로세스, 익명 파이프, 안전한 환경변수 정리, 파일 잠금 원장)으로 **다중 프로세스 권한 위임의 전 과정을 100% 재현**합니다.
  - 30대 시나리오를 실제 서브프로세스 모드로 돌리고, 2-Hop 다단계 프로세스 위임 신규 시나리오 2종을 추가하며, 그 전체 실행 족보를 `audit timeline` 한 줄로 깨끗하게 보여줍니다.

이 08번 로드맵이 마감되면, 본 프로젝트는 면접관이나 엔지니어링 리더에게 **"말뿐인 에이전트가 아니라, 프로세스 경계와 권한 축소, 그리고 시계열 증명 체계를 가장 정교하고 실증적으로 다루는 개발자"**임을 완벽하게 증명하는 압도적인 포트폴리오가 됩니다.
