## 0. 오랜 시간이 지난 뒤 복귀할 때를 위한 상황 파악 가이드 (Quick Resume Guide)

오랜 시간이 지난 뒤 이 프로젝트를 다시 열었을 때, **아래 4가지만 확인하면 단 3분 만에 전체 상황을 100% 파악하고 바로 이어서 진행**할 수 있습니다.

### 1) 이 프로젝트의 정체성 (절대 잊지 말아야 할 원칙)
- 본 프로그램(`authz-harness`)은 헤르메스나 오픈클로 같은 LLM 에이전트 애플리케이션이 **아닙니다**.
- 멀티·분산 에이전트 프로그램들이 공통으로 필요로 하는 **권한 축소 위임(AuthZ), 프로세스·커널 격리(Confinement), 실패-안전 감사 배선(Fail-Closed Audit Wiring)을 비결정적 LLM 없이 100% 결정론적으로 시뮬레이션하고 증명하는 코어 엔진 겸 아키텍처 학습 교보재**입니다([007번 보고서](../보고서/007-분산에이전트_권한감사_아키텍처_타당성_및_감사무결성_권한결합_보고서.md)).
- 따라서 **16번 로드맵까지만 보안·배선 검증 기능을 구현한 뒤 일체의 기능 추가를 동결(Feature Freeze)**하고, **17번(의존성 역전 DIP 완결 및 중복 제거)**과 **18번(7대 디자인 패턴 및 클린 아키텍처 코드리딩 교보재 편찬)**으로 마감합니다([008번 보고서](../보고서/008-로드맵16_완주이후_차기방향_및_클린아키텍처_DIP_모범정제_보고서.md)).

### 2) 현재 어디까지 되어 있는가? (2026-11-03 기준점)
- **코드 구현 완료 (`Done`)**: **00번 ~ 09번 로드맵 완주** (39대 E2E 시나리오 `E2E-01`~`E2E-39`, `go test -race ./...` 100% 통과).
- **설계 및 구현지시서 완비 (`Draft`, 코드 미착수)**: **10번 ~ 18번 로드맵 (총 9개 로드맵, 56개 단계별 구현지시서)** 작성 및 정밀 검증 완료.
  - 10~18번 로드맵의 모든 설계서와 구현지시서는 실제 Go 코드베이스와 라인 단위로 보텀업·크로스커팅 대조하여 **43가지 구조·구현 함정과 5대 코어 권한·파이프라인 기본기(다단계 위임 `act` 계보 Epoch 연쇄 검증, 컨트롤 플레인 SESE 감사 무결성, 전 구간 `domain.Clock` 주입, 상태 원장 `StateVersion` 단조 증가 스탬핑, `Approval.ArgHash` 페이로드 바인딩)를 사전에 모두 반영**해 두었으므로([009번 보고서](../보고서/009-차기로드맵_10_16_전구간_정밀재검토_및_아키텍처_세션전체기록.md), [010번 보고서](../보고서/010-로드맵_10_18_보텀업_및_크로스커팅_정합성_전수검증_보고서.md), [011번 보고서](../보고서/011-권한관리_본질_코어파이프라인_안티패턴_및_분산적응형_기본구조_전문가진단_보고서.md)), 지시서대로만 1단계씩 구현하면 시행착오 없이 완주됩니다.

### 3) 다음에 무엇부터 어떻게 실행하면 되는가? (단일 로드맵 순차 집중[Rolling-Wave] 원칙 — 다수 로드맵 동시 핸들링 금지)
- **[중요 원칙 ([015번](../보고서/015-지속적_수정발생_근본원인_진단_및_과잉설계_제거_구조단순화_보고서.md)·[016번 보고서](../보고서/016-다중로드맵_일괄설계_안티패턴_진단_및_10번로드맵_단독집중_구조정제_보고서.md))]**: 여러 미구현 로드맵을 한꺼번에 수정·핸들링하는 것은 가정 위에 가정을 쌓는 BDUF 안티패턴입니다. **반드시 한 번에 하나의 로드맵만 집중 점검 → 코드 구현 완주(`Done`) → 실제 완성된 코드 위에서 다음 번호 로드맵 1개 점검** 순서로 진행합니다.
1. **착수점**: **[10번 로드맵 (`10-서브프로세스-자원-및-수명-통제`)](10-서브프로세스-자원-및-수명-통제/README.md)의 [`010` 단계](10-서브프로세스-자원-및-수명-통제/instructions/010_하네스_판정기_및_mcp_구조화_오류_보강.md)**가 첫 번째 실행 대상입니다.
2. **선행 ADR 처리**:
   - 10번 로드맵 `010` 착수 시 [ADR 0003](../adr/0003-차기-로드맵-범위-개정-비목표-조건부-해제.md) 상태를 `Proposed` → `Accepted`로 전환합니다.
   - 14번 로드맵 `010` 착수 시 [ADR 0002](../adr/0002-관측성-포트-분리-및-오픈텔레메트리-전환.md) 상태를 `Proposed` → `Accepted`로 전환합니다.
3. **에이전트에게 내릴 복귀 첫 명령 예시**:
   - `"docs/로드맵/README.md와 009, 010번 보고서를 읽고 현재 상태를 파악해라. ADR 0003을 Accepted로 전환하고 10번 로드맵의 010 단계를 구현해라."`
