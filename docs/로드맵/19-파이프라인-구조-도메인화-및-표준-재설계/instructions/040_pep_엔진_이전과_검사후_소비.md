## 1. 목적

`runPipeline`을 엔진 조립 목록으로 바꾸고, ADR 0007의 열 단계와 새 이름, 검사 후 소비를 적용합니다. **이 로드맵에서 동작이 가장 크게 바뀌는 단계입니다.**

## 3. 구현

- 조립 목록은 [ROADMAP.md](../ROADMAP.md) 2장 모양으로 `NewGateway`가 한 번 만든다. `New` 오류는 `NewGateway` 오류다
- `pipeline`은 `domain`을 모르므로 `domain.StageKind`에서 `pipeline.Kind`로 가는 변환 표는 `pep`의 조립 코드에 둔다
- 조립 목록과 `domain.PEPStages()`의 일치를 시험으로 강제한다. ID, 순서, 성격, 조건부(`Applies` 유무)를 모두 대조한다
- `Execute`는 엔진을 부르고 `finalize` 한 곳에서 마감한다. `finalize`의 감사 규칙은 그대로다. 사전 감사 실패 시 거부 감사를 남기지 않는 규칙도 유지한다
- 완료 감사의 단계는 `Trace.Passed`의 마지막 값이다. 정산을 거쳤으면 `settle`, 아니면 `execute`다 ([ADR 0009](../../../adr/0009-감사-스키마-v4-단계-보호.md) 2장 1번). 이 단계에서는 `Metadata["stage"]`에 쓰고 050이 최상위로 옮긴다
- 상태 구조체(현재 `pipelineState`)를 타입 인자로 쓰는 `Hook` 구현이 기존 관측을 잇는다. `traceID`, `resource`, `subject`는 상태에서 읽는다. `duration_ms`는 Hook이 `g.clock`으로 잰 시작 시각을 상태에 두고 계산한다. `OnStepEnd`가 성공일 때 `StageObserver`를 동기로 호출하므로 `toctou_window_test.go`의 단계 사이 끼어들기는 유지된다
- 예산 집행 ([ADR 0008](../../../adr/0008-범용-파이프라인-엔진과-도구-전략.md) 2장 6번). `BudgetPlan`의 `PreCharge`는 이제 모든 도구가 참이므로 삭제한다

  | 도구 | `budget` 사전 차감 | `settle` 사후 정산 | 실행 시작 뒤 환급 |
  |---|---|---|:-:|
  | `file:read`, `net:fetch` | 호출 1 | 읽은 바이트 | 가능 |
  | `file:write` | 호출 1, 쓰기 바이트 | 없음 | 가능 |
  | `exec:run` | 호출 1, 쓰기 바이트 | 출력 바이트 | 금지 |

- `budget` 단계는 예산 토큰이면 항상 돈다. `Compensate`가 환급한다. `RefundAfterStart`가 거짓이고 실행이 시작됐으면 환급하지 않는다
- `settle` 단계는 바이트만 차감한다. 실패하면 결과를 돌려주지 않는다. `file:read`·`net:fetch`는 `budget`의 보상으로 호출분을 돌려받아 원장이 기존 결과와 같다. 시작한 `exec:run`은 환급하지 않는다
- 단계 함수는 메서드 하나씩이고, 조립 목록이 한 화면에 들어오게 한다

## 4. 사전 점검

- `Result.Stage`가 성공 시 실행 단계 값을 갖는 기존 동작을 유지한다
- `InjectAuditFailure`, `RequireTraceID` 경로를 잃지 않는다
- 경계 거부 뒤 재시도가 가능해지므로 재시도가 감사에 두 번 남는지 확인한다
- 승인·jti 소비 사이 실패 시 jti는 타고 승인은 남을 수 있다. 소비끼리의 순서는 현행(`replay` → `approval`)을 유지하고 한계로 기록한다
