## 1. 목적

`runPipeline`을 엔진 조립 목록으로 바꾸고, ADR 0007의 열 단계와 새 이름, 검사 후 소비를 적용합니다. **이 로드맵에서 동작이 가장 크게 바뀌는 단계입니다.**

## 2. 파급 범위와 무영향 근거

- **변경**: `internal/authz/pep/gateway.go`, `internal/cli/pep.go`, `internal/harness/catalog/g15_tool_egress_exec.go`(`"stage5_io"` 문자열을 상수 참조로), `pep`·`cli` 시험의 단계 기대값, `pepAllowedImports`에 `internal/pipeline` 추가, [ADR 0005](../../../adr/0005-pdp-3값-결정-및-일회성-승인-바인딩.md)에 개정 표시
- **삭제**: `pep.Stage` 타입과 상수, `stageOrder`, `Stages()`, `runStage`. `domain`과 엔진이 대체
- **무영향**: PDP, Jail, 가드, 원장의 내부. 종료 코드와 사유 코드 (단, 아래 인수 시험의 jti 변화는 의도됨)

## 3. 구현

- 조립 목록은 [ROADMAP.md](../ROADMAP.md) 2장 모양으로 `NewGateway`가 한 번 만든다. `New` 오류는 `NewGateway` 오류다
- 조립 목록과 `domain.PEPStages()`의 일치를 시험으로 강제한다
- `Execute`는 엔진을 부르고 `finalize` 한 곳에서 마감한다. `finalize`의 감사 규칙은 그대로다
- `Hook` 구현이 기존 `OnStageStart`·`OnStageEnd` 관측을 잇는다
- `budget` 단계의 `Compensate`가 환급한다. `RefundAfterStart`가 거짓이고 실행이 시작됐으면 환급하지 않는다
- `settle` 단계가 사후 차감을 맡는다. 실패하면 결과를 돌려주지 않는다. 시작한 `exec:run`은 환급하지 않는다
- 단계 함수는 메서드 하나씩이고, 조립 목록이 한 화면에 들어오게 한다

## 4. 사전 점검

- `Result.Stage`가 성공 시 실행 단계 값을 갖는 기존 동작을 유지한다
- `InjectAuditFailure`, `RequireTraceID` 경로를 잃지 않는다
- 경계 거부 뒤 재시도가 가능해지므로 재시도가 감사에 두 번 남는지 확인한다
- 승인·jti 소비 사이 실패 시 jti는 타고 승인은 남을 수 있다. 소비끼리의 순서는 현행(`replay` → `approval`)을 유지하고 한계로 기록한다
