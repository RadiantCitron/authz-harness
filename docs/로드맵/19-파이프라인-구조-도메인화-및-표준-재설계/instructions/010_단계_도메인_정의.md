# [구현지시서 010] 단계 도메인 정의

> **문서 상태**: `Done`
> **상위 대시보드**: [19번 README.md](../README.md) | [ROADMAP.md](../ROADMAP.md)
> **선행 조건**: [ADR 0007](../../../adr/0007-파이프라인-단계-분류-기준.md) 채택
> **후속 단계**: [020](020_범용_파이프라인_엔진.md)

## 1. 목적

단계와 성격을 도메인 개념으로 정의합니다. 이 단계는 정의만 더하고 기존 코드는 아직 옮기지 않습니다.

## 2. 파급 범위와 무영향 근거

- **변경**: `internal/domain/stage.go`와 시험 신규, [`MASTER_ROADMAP.md`](../../MASTER_ROADMAP.md) 용어집에 단계·성격·관문 항목 추가
- **무영향**: 아직 아무도 쓰지 않으므로 동작 변화 없음. `domain` import 허용 목록을 벗어나지 않음

## 3. 구현

- `type Stage string`과 ADR 0007의 열 개 상수: `StageInput`, `StageAuthn`, `StageAuthz`, `StageBoundary`, `StageReplay`, `StageApproval`, `StageBudget`, `StagePrecommitAudit`, `StageExecute`, `StageSettle`
- `type StageKind string`: `check`, `decide`, `consume`, `record`, `execute`, `settle`
- `StageSpec{ID, Kind, Conditional, Label}`과 정식 순서 목록 `PEPStages()`. 복사본을 돌려준다
- `Label`은 화면용 한국어 이름 한 벌이다. 화면은 자기 이름표를 갖지 않는다

## 4. 사전 점검

- 010 상수와 `pep` 기존 상수의 이름이 겹쳐 혼란스러울 수 있다 → 패키지가 다르고 040에서 `pep` 쪽을 삭제한다
- 토큰 교환 단계는 080에서 더한다. 미리 넣지 않는다
