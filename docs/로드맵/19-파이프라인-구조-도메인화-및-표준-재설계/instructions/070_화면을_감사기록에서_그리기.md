## 1. 목적

보고서 036 2장의 결함을 없앱니다. 화면은 추측하지 않고 실제 기록을 그립니다. 모르면 `PASS`로 그리지 않습니다.

## 2. 파급 범위와 무영향 근거

- **변경**: `internal/ui/pipeline.go`, `explain.go`, `internal/cli/pep.go`, `internal/cli/pdp.go`, `internal/harness/runner.go`(결과에 관측 단계 전달), `ui` 시험
- **삭제**: `ComputePipelineGates`의 추측 표, 시나리오 ID 분기, 6단계 이름표, `stageLabels`, `pdp` 화면의 `Simulated Context` 고정 줄
- **무영향**: 판정 결과, `summary`·`json` 출력의 기존 필드

## 3. 구현

- 공통 표시 상태: `통과`, `차단`, `건너뜀`, `해당 없음`, `미진입`, `판단 불가`
- 칸 목록과 이름은 `domain.PEPStages()`에서 읽는다
- `explain`은 시나리오가 관측한 단계 기록을 그린다
- 기록이 없으면 전 칸 `미진입`, 읽기 실패나 모르는 값이면 `판단 불가`
- 관문 밖 판정(격리, 자원 한계, 감사 변조)은 관문 칸과 별도 줄로 표시한다. 기존 「실행 감독」 줄을 일반화한다
- `pdp` 화면은 PDP만 실행한 사실대로 판정 칸 하나만 그린다
- 해설 문구의 `Gate N` 표현을 단계 이름으로 바꾼다

## 4. 사전 점검

- 화면 시험이 또 손으로 만든 결과만 보면 같은 일이 반복된다 → 실제 79건을 돌려 대조하는 시험을 넣는다
- 다단계 시나리오에서 어느 요청을 그릴지 → 060과 같은 기준을 쓴다
