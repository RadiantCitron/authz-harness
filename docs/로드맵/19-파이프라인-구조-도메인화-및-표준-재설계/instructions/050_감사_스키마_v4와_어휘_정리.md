## 1. 목적

[ADR 0009](../../../adr/0009-감사-스키마-v4-단계-보호.md)를 구현합니다. 단계를 최상위 필드로 올려 해시로 보호하고, 감사 어휘를 규칙에 맞춥니다.

## 2. 파급 범위와 무영향 근거

- **변경**: `internal/domain/audit.go`, `internal/audit/audit.go`, `pep`의 감사 기록, 토큰·교환·오케스트레이터·PAP·`main.go`의 `Step`·`Action` 값(부록), `internal/ui/timeline.go`·`tree.go`, `Metadata["stage"]`를 읽는 세 곳(`internal/harness/catalog/g15_tool_egress_exec.go`, `internal/authz/pep/budget_test.go`, `internal/authz/pep/tool_dispatch_test.go`)
- **삭제**: `domain.DomainEvent`와 `EventBuffer`, `WithEventRecorder` 일체, `pdp/service.go`의 기록 호출, 이를 시험하는 `pdp_test.go`의 해당 부분
- **무영향**: v0~v3 해시 공식, 체크포인트 형식, 카탈로그 `ExpectedAction` 값(쓰는 값이 모두 이미 규칙에 맞음)

## 3. 구현

- `AuditEvent.Stage string` (`json:"stage,omitempty"`)
- `computeHashV4`: v3 입력에 `Stage`를 더한다. `CurrentSchemaVersion = 4`
- `VerifyHashChain`의 다운그레이드·주입 규칙에 `ev.SchemaVersion < 4 && ev.Stage != ""`을 더해 `AUDIT_INTEGRITY_BROKEN`으로 거부한다
- `Metadata["stage"]` 기록을 삭제하고 `logEvent`와 `logApprovalConsumed`가 최상위 `Stage`를 채운다
- `Step`·`Action`은 부록의 어휘 변경표대로 바꾼다. 착수 때 표를 코드와 다시 대조하고, 표에 없는 값이 나오면 멈춰 보고한다
- 오케스트레이터의 `Action`을 바꾸면서 요청 행동을 `Metadata["requested_action"]`에 옮긴다. 표시 정보가 사라지면 안 된다

## 4. 사전 점검

- `g13` 시나리오가 스키마 버전을 전제한다 → v4 기대로 조정하되 탐지 능력을 낮추지 않는다
- `audit tree`가 `Action` 값으로 노드를 찾는다 → 변경표에 소비자를 함께 적는다
- 혼합 파일(v3 뒤 v4)의 사슬이 이어지는지 확인한다
