## 1. 목적

[ADR 0009](../../../adr/0009-감사-스키마-v4-단계-보호.md)를 구현합니다. 단계를 최상위 필드로 올려 해시로 보호하고, 감사 어휘를 규칙에 맞춥니다.

## 2. 파급 범위와 무영향 근거

- **변경**: `internal/domain/audit.go`, `internal/audit/audit.go`, `pep`의 감사 기록, 토큰·교환·오케스트레이터·PAP·`main.go`의 `Step`·`Action` 값, 카탈로그 `ExpectedAction` 44곳, `internal/ui/timeline.go`·`tree.go`, `internal/harness/catalog/g15`의 `Metadata["stage"]` 읽기
- **삭제**: `domain.DomainEvent`와 `EventBuffer`, `WithEventRecorder` 일체, `pdp/service.go`의 기록 호출
- **무영향**: v0~v3 해시 공식, 체크포인트 형식

## 3. 구현

- `AuditEvent.Stage string` (`json:"stage,omitempty"`)
- `computeHashV4`: v3 입력에 `Stage`를 더한다. `CurrentSchemaVersion = 4`
- `Metadata["stage"]` 기록 삭제
- 어휘 변경표를 이 단계 첫 작업으로 코드 전수 조사 후 이 지시서에 추가하고 사용자 확인 없이 진행하지 않는다

## 4. 사전 점검

- `g13` 시나리오가 스키마 버전을 전제한다 → v4 기대로 조정하되 탐지 능력을 낮추지 않는다
- `audit tree`가 `Action` 값으로 노드를 찾는다 → 변경표에 소비자를 함께 적는다
- 혼합 파일(v3 뒤 v4)의 사슬이 이어지는지 확인한다

## 5. 4층위 검증

1. `go test -race ./...`
2. 어휘 규칙 시험: 코드의 `Step` 리터럴이 규칙을 만족
3. v3 파일 검증 유지, 혼합 파일 검증, 단계 변조 탐지
