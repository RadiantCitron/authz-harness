## 1. 목적

`gateway.go`의 도구별 분기를 `pep.Tool` 구현 네 개로 옮깁니다. **순수 리팩토링입니다.** 단계 순서, 이름, 문자열, 시험 기대값을 바꾸지 않습니다.

## 2. 파급 범위와 무영향 근거

- **변경**: `internal/authz/pep/gateway.go`, `internal/authz/pep/tool.go`, `tool_file.go`, `tool_net.go`, `tool_exec.go` 신규
- **무영향**: 기존 `pep` 시험과 79건을 고치지 않고 통과해야 함. 패키지를 새로 만들지 않으므로 `pepAllowedImports` 불변

## 3. 구현

- `Tool` 인터페이스는 [ADR 0008](../../../adr/0008-범용-파이프라인-엔진과-도구-전략.md) 2장 4번을 따른다
- `BudgetPlan{PreCharge bool, PostCharge bool, RefundAfterStart bool}`
  - `file:write`: 사전 차감, 실행 뒤 실패 시 환급
  - `exec:run`: 사전 차감, 시작 뒤 환급 금지, 출력 크기 사후 차감
  - `file:read`, `net:fetch`: 사후 차감
- 표에 없는 행동은 `input`에서 거부. 기존 `ParseAction` 오류 경로를 유지한다
- `net:fetch`의 원문 URL 지문 처리 같은 감사 보호를 빠뜨리지 않는다

## 4. 사전 점검

- 도구 분리 중 오류 사유가 미묘하게 달라질 수 있다 → 기존 시험을 고치지 않는 것이 이 단계의 합격선이다
- `state`에 도구 전용 필드가 남는다 → `fetchTarget`을 `Call` 안으로 옮기되 다른 필드는 040에서 다룬다

## 5. 4층위 검증

1. `go test -race ./...`, `go vet ./...`
2. 도구별 단위 시험
3. `net:fetch` 잘못된 URL이 감사에 원문을 남기지 않음
4. 79건 PASS
