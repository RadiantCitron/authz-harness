## 1. 목적 및 배경

민감한 파일 쓰기 등 고위험 작업에 대해 자동 허용도 무조건 거부도 아닌 **사람 승인 요청(`DecisionAsk = "ASK"`)**을 내릴 수 있도록 PDP 3값 결정 도메인 모델을 정의한다.
본 단계에서는 `ROADMAP.md` §8의 미결 3건을 확정하는 **ADR 0005(`docs/adr/0005-pdp-3값-결정-및-일회성-승인-바인딩.md`)**를 `Accepted` 상태로 작성하고, 종료 코드 `ExitApprovalRequired = 18` 및 사유 상수 3종(`APPROVAL_REQUIRED`, `APPROVAL_EXPIRED`, `APPROVAL_MISMATCH`), `Grant.RequiresApproval` 필드, `Approval` 도메인 모델을 정의한다.

## 3. 세부 명세

1. **4요소 엄격 바인딩 (`Approval.Matches(sub string, action Action, resource string, jti string, now time.Time) (bool, Reason)`)**:
   - `Subject != sub || Action != action || Resource != resource || TokenJTI != jti` 중 하나라도 다르면 불일치(`false, ReasonApprovalMismatch`).
   - 바인딩 4요소가 모두 일치하나 `Consumed == true`이면 미승인/재사용 차단(`false, ReasonApprovalRequired`).
   - 바인딩 4요소가 모두 일치하나 `now.UTC().Unix() >= ExpiresAt`이면 만료(`false, ReasonApprovalExpired`).
   - 모두 통과하면 `true, ReasonAuthorized`를 반환한다.
2. **TTL 검증 (`ValidateApprovalTTL(ttl time.Duration) error`)**:
   - `ttl == 0`이면 `DefaultApprovalTTL(5m)`을 적용하고, `ttl < 0` 또는 `ttl > MaxApprovalTTL(1h)`이면 `ReasonInvalidArguments(14)` 에러를 반환한다.
3. **종료 코드 매핑**:
   - `ReasonApprovalRequired`, `ReasonApprovalExpired`, `ReasonApprovalMismatch`는 모두 `ExitCodeForReason`에서 `ExitApprovalRequired(18)`로 매핑한다.

## 4. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |
|:---:|---|---|
| **TC-010-01** | 4요소(`sub`, `action`, `resource`, `jti`)가 모두 일치하고 미만료·미소비인 `Approval.Matches` | `true, ReasonAuthorized` |
| **TC-010-02** | `sub`, `action`, `resource`, `jti` 중 어느 1개라도 다른 요청으로 `Matches` 호출 | `false, ReasonApprovalMismatch` (`ExitCode == 18`) |
| **TC-010-03** | `now.Unix() == ExpiresAt` 또는 `Consumed == true`인 `Approval.Matches` 호출 | `false` (`ReasonApprovalExpired` 또는 `ReasonApprovalRequired`, `ExitCode == 18`) |
| **TC-010-04** | `ttl = 2 * time.Hour`로 승인 생성 검증 호출 | `MaxApprovalTTL(1h)` 초과로 `ReasonInvalidArguments(14)` 거부 |
