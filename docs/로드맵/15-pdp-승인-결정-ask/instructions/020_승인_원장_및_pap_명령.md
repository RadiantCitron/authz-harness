## 1. 목적 및 배경

사람 승인자를 대역하는 PAP CLI(`authz-harness approval grant/list`)와, 승인 확인 및 1회용 소비(`Consumed = true`)를 단일 파일 잠금 임계 구역에서 원자적으로 수행하는 Zone B 승인 원장(`approvals_state.json`, `AtomicFileStore` 기반)을 구현한다.
특히 부모 프로세스와 자식 워커(`subagent worker`)가 추가 CLI 플래그 없이도 동일한 승인 원장을 공유하도록 [`internal/app/builder.go`](../../../../internal/app/builder.go)에서 `StatePath` 기준 자동 경로 파생을 함께 구성한다.

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/authz/state/approval_store.go` [신규]: `AtomicFileStore[ApprovalsState]` 기반 저장소(`ApprovalStore` 인터페이스 및 `FileApprovalStore`: `CreateApproval`, `ListBySubject`, `ConsumeMatching`, `ListApprovals`) 구현
  - `internal/authz/pap/service.go`: `CreateGrantRequest`에 `RequiresApproval bool` 지원 추가, `CreateApproval(ctx, CreateApprovalRequest)` 및 `ListApprovals(ctx, subject)` 관리 메서드 추가 (생성 시 `approval.granted` 감사 이벤트 기록)
  - `internal/app/builder.go` 및 `internal/harness/sandbox.go`:
    - `AppConfig` 및 `SandboxEnvironment`에 `ApprovalPath string` 추가, `AppStack`에 `ApprovalStore state.ApprovalStore` 추가
    - `BuildStack`에서 `cfg.ApprovalPath == ""`이고 `cfg.StatePath != ""`이면 `filepath.Join(filepath.Dir(cfg.StatePath), "approvals_state.json")`으로 자동 파생하여 `PAP`(VerifyOnly가 아닐 때), `PIP`, `PEP`에 자동 주입
  - `internal/cli/approval.go` [신규], `internal/cli/grant.go`, `cmd/authz-harness/main.go`: `grant create --requires-approval` 플래그 및 `approval grant --subject ... --action ... --resource ... --jti ... --ttl ...`, `approval list` 명령 구현
  - `internal/harness/architecture_test.go`: 워커(`internal/subagent`)가 승인 원장을 직접 수정(자기 승인)하지 못하도록 기존 `TC-060-02` 및 `TC-081-01` 가드 유지 확인
- **무영향**:
  - 기존 `grants_state.json` 스키마 및 명령과 하위 호환된다.

## 3. 세부 명세

1. **원자적 1회용 소비 (`ConsumeMatching(sub string, action domain.Action, resource string, jti string, now time.Time) (*domain.Approval, error)`)**:
   - `store.Update` 배타 잠금 안에서 `(sub, action, resource, jti)` 4요소가 모두 일치하고 `Consumed == false && now.UTC().Unix() < ExpiresAt`인 승인 레코드를 찾아 `Consumed = true`, `ConsumedAt = &now`로 마킹하고 저장한다.
   - 만약 2개 이상의 고루틴/프로세스가 동시에 같은 승인을 소비하려 해도 정확히 1개만 성공하고, 나머지는 이미 `Consumed == true`가 된 상태를 보므로 `domain.NewError(domain.ReasonApprovalRequired, "approval_store", "approval already consumed or not found", nil)`(`ExitApprovalRequired = 18`)로 거부된다.
2. **합성 루트 자동 경로 파생**:
   - 자식 서브프로세스(`authz-harness subagent worker -state-file ...`)는 별도 `-approval-file` 플래그를 받지 않더라도 `BuildStack`이 `filepath.Dir(cfg.StatePath)` 아래의 `approvals_state.json`을 자동으로 연결하므로 부모가 발급한 승인을 즉시 조회·소비할 수 있다.
3. **자기 승인 원천 차단**:
   - `internal/subagent`는 `internal/authz/state`와 `internal/authz/pap`를 import할 수 없다(`TC-060-02`).
