## 1. 목적 및 배경

`020`의 `netguard`와 `030`의 `execguard`를 별도 우회 입구가 아닌 **기존 [`internal/authz/pep/gateway.go`](../../../../internal/authz/pep/gateway.go) 단일 입출구 파이프라인(`Gateway.Execute`)**에 통합한다.
이를 통해 `net:fetch`와 `exec:run` 역시 Gate 0(Trace) → Gate 1(AuthN/JWKS/Replay) → Gate 2(PDP Grant/Epoch/Scope/Budget/Approval) → Gate 2c(도구별 가드: `jail` / `netguard` / `execguard`) → Stage 4(사전 감사 + 인자 해시) → Stage 5(도구 실행 + 자원 한계) → `finalize` 사후 감사라는 동일한 6단 관문을 거치게 한다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/authz/pep/gateway.go`:
    - `NormalizeAction`에 `domain.ActionNetFetch`, `domain.ActionExecRun` 추가
    - Gate 2c에서 액션 종류에 따라 `file:*`는 `jail.ResolvePath`, `net:fetch`는 `netguard.ValidateTarget`, `exec:run`은 `execguard.ValidateRequest`를 호출하도록 분기
    - Stage 5에서 검증된 타겟에 대해 각 실행기를 호출하고 결과를 수거(`Execute` 함수 내 `return` 문 1개 불변식 `TC-060-04` 유지)
  - `internal/authz/pep/tool_dispatch_test.go` [신규]: 3종 도구(`file`, `net`, `exec`)에 대한 PEP 관문 통합 단위 테스트
- **무영향**:
  - 기존 `file:read`, `file:write` 요청 처리 경로와 종료 코드는 그대로 보존된다.

---

## 3. 세부 명세

1. **단일 입출구(`TC-060-04`) 및 PDP 순수성(`TC-060-01`) 유지**:
   - PDP는 여전히 `(sub, action, normalized_resource)` 문자열만 비교하여 순수 판정을 내린다 (예: `action = "net:fetch"`, `resource = "127.0.0.1:18080"`).
   - 만약 `netguard`가 Gate 2c에서 비허용 호스트/포트를 적발하면 Stage 4/5로 진행하지 않고 즉시 `ReasonEgressDenied`(`ExitAuthzDenied = 12`)로 `finalize`에 수렴하여 `pep.deny` 감사를 남긴다.
2. **인자 해시 감사 연동**:
   - 로드맵 14 `030` 단계의 `ArgHash`/`ResultHash` 규칙에 따라, `exec:run` 인자나 `net:fetch` 응답 원문은 감사에 남기지 않고 정규화된 리소스 식별자(`127.0.0.1:18080`, `echo-safe`)와 해시 지문만 기록한다.
