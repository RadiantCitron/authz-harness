## 1. 목적 및 배경

로드맵 11의 격리 정책은 네트워크를 `AllowNetwork` 한 값으로만 다룬다([`policy.go`](../../../../internal/confinement/policy.go) 24행). 정직한 워커 정책은 `false`이므로 격리를 켜면 정상 `net:fetch`도 커널이 막는다. 그래서 「허용 포트로만 나갈 수 있다」는 규칙을 정책에 더한다. netguard가 1차, 이 커널 규칙이 2차 방어다. PEP를 건너뛴 악의 워커는 커널에 막힌다.

또 지금 격리는 G10의 faultworker에만 걸려 봤고, 정직한 `subagent worker`가 격리 하에서 실제로 도는지는 확인된 적이 없다. 이 단계에서 먼저 실측한다.

## 2. 파급 범위와 무영향 근거

- **변경**:
  - [`internal/confinement/policy.go`](../../../../internal/confinement/policy.go): `Policy.AllowConnectPorts []int`. `Validate`에 규칙 추가. `WorkerPolicy` 시그니처는 그대로 두고 호출자가 필드를 채운다.
  - [`internal/confinement/seatbelt_darwin.go`](../../../../internal/confinement/seatbelt_darwin.go) `RenderSeatbeltProfile`: `(deny network*)` 뒤에 포트마다 `(allow network-outbound (remote ip "localhost:<port>"))`. SBPL은 뒤 규칙이 앞 규칙을 덮는다.
  - [`internal/confinement/landlock_linux.go`](../../../../internal/confinement/landlock_linux.go) `ApplySelf`: ABI ≥ 4에서 포트마다 `landlock_add_rule(LANDLOCK_RULE_NET_PORT, {allowed_access: CONNECT_TCP, port})`. bind는 계속 막는다.
  - 테스트: `policy_test.go`, `seatbelt_darwin_test.go`, (Linux) 규칙 생성 단위 테스트.
- **무영향**: `AllowConnectPorts`가 비면 생성되는 프로필·규칙이 지금과 바이트 단위로 같다(G10 E2E-45~49 불변). 스포너·런처·`classifyExit`는 바꾸지 않는다.

## 3. 세부 명세

1. **Validate**:
   - 각 포트는 1~65535. 중복은 허용하되 한 번만 렌더한다.
   - `AllowNetwork == true`이면서 `AllowConnectPorts`가 비어 있지 않으면 `INVALID_ARGUMENTS`(모호한 정책 → Fail-Closed).
2. **seatbelt**: 루프백(`localhost`) + 지정 포트로 나가는 TCP만 열린다. 다른 포트, 외부 주소, bind는 계속 막힌다.
3. **Landlock**:
   - ABI < 4면 지금처럼 「네트워크를 막을 수 없음」으로 unavailable이다(포트 지정 여부와 무관).
   - Landlock 포트 규칙은 **호스트를 구분하지 못한다.** 같은 포트로 외부 주소에 나가는 연결은 커널이 막지 않는다. 이 한계는 WHY에 적었고, 호스트 제한은 netguard가 맡는다.
4. **정직 워커 실측**: 하네스 샌드박스에서 `WorkerPolicy(root, workspace, zoneB, audit)` + `AllowConnectPorts`로 실제 `authz-harness subagent worker`를 띄운다. 워커가 읽고 쓰는 파일(Zone B의 `jwks.json`·`grants_state.json`·`replay_ledger.json`·`budget_ledger.json`, 감사 파일과 `.lock`, 워크스페이스)은 모두 `WritePaths`에 들어 있어야 한다. **실측에서 막히는 경로가 나오면 정책을 임의로 넓히지 말고 멈추고 보고한다.**
