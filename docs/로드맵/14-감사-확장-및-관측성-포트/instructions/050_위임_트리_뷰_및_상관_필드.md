## 1. 목적 및 배경

현재 [`internal/ui/timeline.go`](../../../../internal/ui/timeline.go)의 `renderProcessTree`는 실제 부모→자식 위임 관계를 분석하지 않고 단순히 감사 로그에 등장한 `actor` 순서대로 `strings.Repeat("   ", i)` 선형 들여쓰기를 수행하여, 병렬 형제 워커(`worker-01`, `worker-02`)까지 부모·자식 관계처럼 잘못 표현한다.
본 단계에서는 `audit.Event`에 W3C 호환 `SpanID`/`ParentSpanID`(16-hex) 선택 필드를 추가하고 `stdin` 프레임(`SubagentRequest`)으로 전파하며, 실제 위임 간선(`parent_sub → child_sub`, `caller_id → agent_id`, `parent_span_id → span_id`)을 기반으로 정확한 계층 트리를 렌더링하는 `authz-harness audit tree --trace-id <id>` 명령을 구현한다.

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/audit/audit.go`: `Event`에 선택적 `SpanID string` (`json:"span_id,omitempty"`), `ParentSpanID string` (`json:"parent_span_id,omitempty"`) 필드 추가 (기존 해시 체인 공식은 변경하지 않아 하위 호환 유지)
  - `internal/subagent/protocol.go`: `SubagentRequest`에 선택적 `ParentSpanID string` (`json:"parent_span_id,omitempty"`) 필드 추가 (환경변수 전달 금지, `cleanenv` 원칙 준수)
  - `internal/ui/tree.go` [신규]: 동일 `TraceID`의 감사 이벤트들에서 위임 간선(`token.exchanged`의 `Metadata["parent_sub"] → Metadata["child_sub"]`, `pep.allow`/`pep.deny`의 `Metadata["caller_id"] → Metadata["agent_id"]`, 그리고 `ParentSpanID → SpanID`)을 추출해 실제 부모→자식 트리 그래프를 조립·렌더링하는 `RenderDelegationTree` 구현
  - `internal/cli/audit.go`: `audit tree` 서브커맨드 추가 (`--trace-id`, `--audit-file` 플래그 지원)
  - `internal/ui/tree_test.go` [신규]: 2-Hop 직렬 위임(`Root → Lead → Worker`) 및 1-to-N 병렬 형제 위임(`Root → Worker1, Worker2`)의 트리 렌더링 단위 테스트
- **무영향**:
  - 기존 `TraceID` 문자열 형식과 `audit timeline` 출력 포맷은 그대로 유지하여 기존 골든 테스트를 깨뜨리지 않는다.

## 3. 세부 명세

1. **`stdin` 프레임 기반 상관 ID 전파**:
   - [ADR 0002](../../../adr/0002-관측성-포트-분리-및-오픈텔레메트리-전환.md) B-6에 따라 자식 프로세스 환경변수에 `TRACEPARENT`를 넣지 않고 오직 `SubagentRequest` JSON 프레임(`parent_span_id`)으로만 전달한다.
2. **실제 위임 그래프 재구성 (`RenderDelegationTree`)**:
   - 단순 등장 순서가 아니라, 각 에이전트 노드의 부모를 ① `token.exchanged` 이벤트의 `Metadata["parent_sub"]` → `Metadata["child_sub"]`, ② PEP/PDP 이벤트의 `Metadata["caller_id"]` → `Metadata["agent_id"]`(또는 `Actor`), ③ `ParentSpanID` → `SpanID`로부터 결정한다.
   - 이를 통해 `Root`가 `worker-01`과 `worker-02`에 각각 위임한 경우 두 워커가 같은 Depth 1 형제 노드(`├── worker-01`, `└── worker-02`)로 출력되고, 2-Hop 위임(`Root → lead-01 → worker-01`)은 Depth 0 → Depth 1 → Depth 2로 정확히 들여쓰기된다.

## 4. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |

| **TC-050-01** | 2-Hop 위임(`Root → Lead → Worker`) 실행 후 `audit tree --trace-id <id>` 호출 | Depth 0 → Depth 1 → Depth 2 계층 트리와 각 노드의 `Decision`/`Reason` 출력 |
