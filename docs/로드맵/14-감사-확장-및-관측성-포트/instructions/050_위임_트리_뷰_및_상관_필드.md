## 1. 목적 및 배경

다단계 위임(`Root → Lead → Worker`) 실행 시 시간순 평면 목록(`audit timeline`)만으로는 누가 누구에게 권한을 위임해 어떤 자식 프로세스에서 차단·허용되었는지 계층 구조를 한눈에 파악하기 어렵다.
본 단계에서는 `audit.Event`의 `AgentID`/`CallerID` 및 W3C 호환 `SpanID`/`ParentSpanID` 상관 필드를 `stdin` 프레임으로 전파하고, 이를 계층 트리로 렌더링하는 `authz-harness audit tree --trace-id <id>` 명령을 구현한다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/subagent/protocol.go`: `SubagentRequest`에 선택적 `ParentSpanID string` (`json:"parent_span_id,omitempty"`) 필드 추가 (환경변수 전달 금지, `cleanenv` 원칙 준수)
  - `internal/ui/tree.go` [신규]: 동일 `TraceID`의 감사 이벤트들을 `CallerID → AgentID` 및 `ParentSpanID → SpanID` 관계로 묶어 계층 트리 텍스트로 렌더링하는 `RenderDelegationTree` 구현
  - `internal/cli/audit.go`: `audit tree` 서브커맨드 추가
  - `internal/ui/tree_test.go` [신규]: 2-Hop 위임 이벤트의 트리 렌더링 단위 테스트
- **무영향**:
  - 기존 `TraceID` 문자열 형식과 `audit timeline` 출력 포맷은 그대로 유지하여 기존 골든 테스트를 깨뜨리지 않는다.

## 3. 세부 명세

1. **`stdin` 프레임 기반 상관 ID 전파**:
   - [ADR 0002](../../../adr/0002-관측성-포트-분리-및-오픈텔레메트리-전환.md) B-6에 따라 자식 프로세스 환경변수에 `TRACEPARENT`를 넣지 않고 오직 `SubagentRequest` JSON 프레임으로만 전달한다.
2. **`audit tree` 렌더링 구조**:
   - Depth 0(`root-orchestrator`) → Depth 1(`lead-01`) → Depth 2(`worker-01`)로 이어지는 토큰 교환과 PEP 허용/거부 이벤트를 들여쓰기 트리(`├──`, `└──`)로 시각화한다.
