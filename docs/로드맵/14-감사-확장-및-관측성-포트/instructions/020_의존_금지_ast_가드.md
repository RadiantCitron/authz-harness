## 1. 목적 및 배경

1. **코어 패키지의 구체 로거·OTel 의존 금지 (`TC-140-01`)**:
   - `010`에서 분리한 관측성 포트 구조가 깨지지 않도록 코어 도메인(`domain`, `authn`, `authz`, `jail`, `audit`)이 `"log/slog"`나 `"go.opentelemetry.io/..."`를 직접 import하는 것을 정적 AST 검사로 차단한다 ([ADR 0002](../../../adr/0002-관측성-포트-분리-및-오픈텔레메트리-전환.md) B-8).
2. **컨트롤 플레인(`ExchangeService`, `Verifier`, `KeyManager`) SESE 통일 및 감사 에러 무시(`_ = ...Log`) 전수 제거 ([011번 보고서](../../../보고서/011-권한관리_본질_코어파이프라인_안티패턴_및_분산적응형_기본구조_전문가진단_보고서.md) 제안 2)**:
   - 현재 [`internal/harness/architecture_test.go:196`](../../../../internal/harness/architecture_test.go)의 `TC-080-01`은 `internal/orchestrator` 폴더만 검사하고 있어, 정작 컨트롤 플레인 코어인 [`internal/authn/exchange/service.go:202`](../../../../internal/authn/exchange/service.go), [`internal/authn/token/verifier.go:270`](../../../../internal/authn/token/verifier.go), [`internal/authn/keys/manager.go:103,222,299`](../../../../internal/authn/keys/manager.go)에 남아 있는 `_ = ...auditWriter.Log(...)` 감사 에러 무시(Fail-Open)를 놓치고 있다.
   - 본 단계에서는 `authn` 코어 3개 패키지의 감사 에러 무시를 전수 제거하고, `ExchangeService.Exchange`의 8개 조기 `return`을 `pep.Gateway`와 동일한 SESE(단일 출구 + `*domain.Error` 정형 반환) 구조로 정돈하며, `TC-080-01`의 검사 범위를 **`internal/` 하위 전체 프로덕션 패키지**로 확장한다.

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/authn/exchange/service.go`: `Exchange` 메서드를 SESE 단일 출구 구조로 정리하고, 거부/성공 감사 기록 실패 시 `_ =`로 무시하지 않고 `ReasonAuditLogFailed`(`ExitAuditFailure = 15`) 에러를 반환하도록 수정
  - `internal/authn/token/verifier.go` 및 `internal/authn/keys/manager.go`: `_ = v.auditWriter.Log(...)` / `_ = m.auditWriter.Log(...)` 감사 에러 무시를 제거하고 감사 기록 실패 시 즉시 `ReasonAuditLogFailed`(`15`) 에러를 반환하도록 Fail-Closed 통일
  - `internal/harness/architecture_test.go`:
    - `TC-140-01` 추가: `internal/domain`, `internal/authn`, `internal/authz`, `internal/jail`, `internal/audit` 프로덕션 파일의 `"log/slog"` 및 `"go.opentelemetry.io/..."` import 0건 검증
    - `TC-080-01` 확대: `internal/orchestrator`뿐 아니라 **`internal/` 하위 전체 프로덕션 `.go` 파일**에서 `_ = ...Log(...)` 형태의 감사 에러 무시가 0건임을 전수 검증
- **무영향**:
  - 정상 감사 기록 환경에서는 모든 토큰 발급·교환·검증·키 회전 동작이 기존과 100% 동일하며, 감사 디스크 결함 시에만 Fail-Closed(`Exit 15`)가 일관되게 보장된다.
