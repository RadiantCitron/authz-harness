## 1. 목적 및 배경

도구 입력·파일 내용 원문을 감사에 남기면 비밀이 샌다. 그렇다고 아무것도 남기지 않으면 「어떤 입력과 결과였는지」를 나중에 대조할 수 없다. 그래서 원문 대신 지문(SHA-256)을 남긴다.

지금 해시 체인([`ComputeEventHash`](../../../../internal/audit/audit.go) 46~60행)은 9필드만 보호한다. 따라서 새 필드를 추가할 때는 **그 필드가 해시로 보호되는지**가 핵심이다. 교정 전 규칙(「해시가 있을 때만 v2로 자동 승격」)으로 만들면, v1 레코드에 `arg_hash`를 끼워 넣어도 VALID가 나온다(023 O-1). 본 단계는 v2를 다음과 같이 정의한다.
- 새로 쓰는 레코드는 **항상 v2**다.
- 버전 다운그레이드를 검증기가 거부한다.
- 기존 v1 파일은 v1 공식 그대로 계속 VALID다.

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/domain/digest.go` [신규]: `DataDigest(data []byte) string`. 빈 입력이면 `""`, 아니면 `"sha256:" + hex(sha256(data))`이다. 15번(승인 `ArgHash`)과 16번(`exec:run` 인자)이 같은 함수를 쓰므로, `audit`이 아니라 순수 `domain`에 둔다(023 O-2. `pdp`가 `audit`을 import하면 17번 DIP 목표와 어긋난다).
  - `internal/audit/audit.go`:
    - `Event`에 `SchemaVersion int`(`json:"schema_version,omitempty"`), `ArgHash string`(`json:"arg_hash,omitempty"`), `ResultHash string`(`json:"result_hash,omitempty"`)을 추가한다.
    - `ComputeEventHash`를 버전별로 나눈다(§3.2).
    - `JSONLWriter.Log`는 `NormalizeEvent` 뒤에 `event.SchemaVersion = 2`로 **고정**한다. 호출자가 다른 값을 넣었어도 덮어쓴다.
    - `VerifyHashChain`에 다운그레이드 3규칙을 추가한다(§3.3).
  - `internal/authz/pep/gateway.go`:
    - `pipelineState.argHash`(15번 040과 같은 이름)를 추가한다. Gate 0에서 `domain.DataDigest(req.Data)`로 채운다.
    - `logEvent(state, stage, success, reason, details, resultHash string)`: `ArgHash: state.argHash`, `ResultHash: resultHash`.
    - `resultHash`는 `finalize` 완료 이벤트에서만 `domain.DataDigest(res.Data)`이고, 나머지(Stage 4 사전 감사, 거부)는 `""`이다(023 O-3: Stage 4는 I/O 전이라 결과가 없다).
  - `internal/audit/schema_compat_test.go` [신규], `internal/domain/digest_test.go` [신규], `internal/authz/pep` 시험 보강: §4.
- **바꾸지 않는 것**: `metadata.prev_hash`/`curr_hash` 동기화(기존 하위 호환). Metadata에 `arg_hash`를 동기화하는 교정 전 규칙은 **넣지 않는다**(보호되지 않는 사본만 늘기 때문).
- **무영향**:
  - 기존 v1 레코드(`schema_version` 없음)는 v1 공식으로 검증되므로 그대로 VALID다.
  - 모든 시험은 매번 새 임시 감사 파일을 쓰므로, 항상 v2가 되어도 `TestQuadAssertion_SuccessCase` 등 기존 시험의 판정은 같다.
  - 판정 로직은 바뀌지 않는다.

## 3. 세부 명세

1. **v2가 보호하는 필드 (사용자 결정 2)**: v1 9필드(`prev_hash`, `timestamp`, `trace_id`, `actor`, `action`, `resource`, `decision`, `reason`, `success`)에 더해 `token_jti`, `agent_id`, `arg_hash`, `result_hash`를 보호한다.
   - **보호하지 않는 것**: `step`, `error_class`, `metadata` 전체(예: `caller_id`, `parent_jti`, `details`). 이 필드들은 고쳐도 VALID다. 이 한계는 [ROADMAP §2](../ROADMAP.md)에 적었고, 050 트리가 이 한계를 물려받는다.
2. **`ComputeEventHash` 분기**:
   - `SchemaVersion <= 1`: 기존 공식 `prev|ts|trace|actor|action|resource|decision|reason|success`를 1바이트도 바꾸지 않는다.
   - `SchemaVersion == 2`: `v1 문자열 + "|v2|" + token_jti + "|" + agent_id + "|" + arg_hash + "|" + result_hash`.
3. **검증기 다운그레이드 규칙** (모두 `ReasonAuditIntegrityBroken`, `ExitAuditFailure = 15`):
   - ① `SchemaVersion`이 0·1인데 `arg_hash` 또는 `result_hash`가 비어 있지 않음 → v2 필드 주입.
   - ② `SchemaVersion`이 0·1·2가 아님 → 알 수 없는 버전.
   - ③ 앞 레코드가 v2인데 다음 레코드가 v1 → 다운그레이드. v1 → v2 전환은 허용한다(기존 파일에 이어 쓰는 경우).
4. **지문 원칙**:
   - `req.Data`·`res.Data` 원문은 `audit.Event`의 어느 필드에도 넣지 않는다.
   - **한계 (023 O-14)**: 솔트가 없는 SHA-256이므로, 짧거나 추측하기 쉬운 입력은 사전 대입으로 원문을 되찾을 수 있다. 「원문 비노출」은 「원문 추측 불가」와 같지 않다. 15번 승인 바인딩이 결정론적 대조를 요구하므로 솔트는 두지 않는다.

## 4. 인수 테스트 시나리오

| ID | 입력 | 기대 결과 |
|:---:|---|---|
| **TC-030-01** | `schema_version` 없는 v1 픽스처 3줄(v1 공식으로 해시)에 `VerifyHashChain` | `nil` (VALID) |
| **TC-030-02** | v1 픽스처 3줄 뒤에 `JSONLWriter.Log`로 2건 추가 | 추가된 2건은 `schema_version: 2`이고 체인이 이어짐, `VerifyHashChain` VALID |
| **TC-030-03** | v2 레코드의 `arg_hash`, `result_hash`, `token_jti`, `agent_id`를 각각 1글자 변조 | 네 경우 모두 `ReasonAuditIntegrityBroken` |
| **TC-030-04** | v1 레코드에 `"arg_hash":"sha256:…"`만 추가(해시는 그대로) | `ReasonAuditIntegrityBroken` (규칙 ①) |
| **TC-030-05** | `schema_version: 3` 레코드 / v2 뒤에 v1 레코드(해시는 v1 공식으로 정상 계산) | 각각 `ReasonAuditIntegrityBroken` (규칙 ②·③) |
| **TC-030-06** | PEP로 `"TOP_SECRET_PAYLOAD"`를 `file:write` → 같은 파일을 `file:read` | `audit.jsonl`에 평문 0건. 쓰기 이벤트의 `arg_hash`와 읽기 완료 이벤트의 `result_hash`가 모두 `domain.DataDigest([]byte("TOP_SECRET_PAYLOAD"))`와 같음. 읽기의 Stage 4 이벤트는 `result_hash`가 없음 |
| **TC-030-07** | `domain.DataDigest(nil)`, `DataDigest([]byte("a"))` | `""`, `"sha256:ca97…"`(64 hex) |
