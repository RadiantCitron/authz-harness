## 1. 목적 및 배경

감사 로그에 민감한 도구 입력 데이터나 파일 내용 원문을 기록하면 비밀 유출 위험이 생기고, 아예 기록하지 않으면 "어떤 입력과 결과였는지" 사후 대조할 수 없다.
본 단계에서는 감사 이벤트에 `SchemaVersion`(`1` 또는 `2`), 입력 지문(`ArgHash`), 결과 지문(`ResultHash`)을 추가하되, **구버전(`SchemaVersion` 미기재 또는 `1`) 레코드의 `ComputeEventHash` 공식을 그대로 보존**하여 기존 감사 파일 픽스처와 [`internal/harness/harness_test.go`](../../../../internal/harness/harness_test.go)의 `TestQuadAssertion_SuccessCase` 등이 새 검증기에서도 100% `VALID`로 통과하도록 하위 호환성을 보장한다 ([006번 보고서](../../../보고서/006-차기로드맵_10_16_타당성_및_단계분할_정밀검토_보고서.md) §3.5).

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/audit/audit.go`: `Event`에 `SchemaVersion int` (`json:"schema_version,omitempty"`), `ArgHash string` (`json:"arg_hash,omitempty"`), `ResultHash string` (`json:"result_hash,omitempty"`) 및 헬퍼 `ComputeDataHash(data []byte) string` 추가. `NormalizeEvent` 및 `ComputeEventHash`에 버전별 분기 적용
  - `internal/authz/pep/gateway.go`: `len(req.Data) > 0`일 때 `ArgHash: audit.ComputeDataHash(req.Data)`, `len(res.Data) > 0`일 때 `ResultHash: audit.ComputeDataHash(res.Data)`를 계산해 `pep.allow`/`pep.deny` 감사 이벤트에 전달(원문 기록 금지)
  - `internal/audit/schema_compat_test.go` [신규]: v1 픽스처·v2 레코드 혼합 체인 검증 및 원문 비노출 단위 테스트
- **무영향**:
  - `ArgHash`·`ResultHash`가 없는 기존 이벤트는 `NormalizeEvent`가 `SchemaVersion`을 강제 변경하지 않으므로, 기존 테스트(`TestQuadAssertion_SuccessCase` 등)와 시나리오가 생성한 v1 감사 레코드 해시 검증은 단 1바이트도 깨지지 않는다.

## 3. 세부 명세

1. **`NormalizeEvent` 자동 승격 규칙 (기존 테스트 호환성 핵심)**:
   - `NormalizeEvent(event *Event)`에서 `event.SchemaVersion == 0 && (event.ArgHash != "" || event.ResultHash != "")`인 경우에만 `event.SchemaVersion = 2`로 자동 설정한다.
   - `ArgHash`와 `ResultHash`가 모두 비어 있고 `SchemaVersion == 0`인 기존 호출은 그대로 두어 v1 해시 공식이 적용되게 한다.
   - `event.SchemaVersion == 2`일 때는 `event.Metadata["arg_hash"]`와 `event.Metadata["result_hash"]`도(값이 있을 경우) 동기화한다.
2. **버전별 해시 공식 분리 (`ComputeEventHash`)**:
   - `ev.SchemaVersion <= 1`: 기존 `fmt.Sprintf("%s|%s|%s|%s|%s|%s|%s|%s|%t", prevHash, ts, traceID, actor, action, resource, decision, reason, success)` 공식 100% 유지.
   - `ev.SchemaVersion >= 2`: 기존 9필드 뒤에 `|v2|%s|%s`(`ev.ArgHash`, `ev.ResultHash`)를 결합하여 `arg_hash`·`result_hash` 위변조까지 해시 체인으로 보호한다.
3. **데이터 지문 계산 (`ComputeDataHash`) 및 원문 비노출 원칙**:
   - `len(data) == 0`이면 `""`를 반환하고, `len(data) > 0`이면 `"sha256:" + hex.EncodeToString(sha256.Sum256(data))`를 반환한다.
   - `req.Data`나 `res.Data` 원문 문자열은 `audit.Event`의 어느 필드에도 넣지 않는다.
