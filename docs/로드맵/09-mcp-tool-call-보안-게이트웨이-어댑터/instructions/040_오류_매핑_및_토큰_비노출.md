## 1. 목적 및 배경
PEP가 내린 거부 사유와 종료 코드를 호출자가 구분할 수 있는 JSON-RPC 응답으로 정확히 매핑하고, 원시 토큰이 응답·`stderr`·감사 어디에도 남지 않게 한다.

## 2. 파급 범위와 무영향 근거
- **변경**: `internal/mcp/errors.go` [신규], 어댑터 로깅 경로.
- **무영향**: PEP의 `Reason`/ExitCode 체계는 변경하지 않고 읽기만 한다. 감사 이벤트 스키마도 그대로다.

## 3. 세부 명세
1. 매핑 표: 종료 코드와 `Reason`을 `tools/call` 결과의 `isError: true` 응답과 `data.reason`, `data.exit_code`로 노출한다. 허용은 `isError: false`와 도구 결과 내용으로 응답한다.
2. 알 수 없는 종료 코드나 자식 비정상 종료는 `ExitInternalError` 계열 거부로 처리한다(Fail-Closed).
3. 오류 메시지에는 토큰 원문과 내부 경로 상세를 포함하지 않는다.
4. 운영 로그(`slog`)에는 `jti`, `trace_id`, 도구 이름, 판정만 기록한다.
5. 모든 오류 경로가 응답을 정확히 1개 반환하도록 단일 출구 구조로 만든다.

## 4. 인수 테스트 시나리오

| TC-040-05 | 로그 레벨 변경 | 감사 이벤트 누락 0건 |

## 5. 4층위 검증 기준

2. JWT 정규식 유출 검사 PASS
3. `audit verify` `VALID`
4. `go test ./...` 회귀 0건
