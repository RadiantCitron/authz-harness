## 1. 목적 및 배경
어댑터 입구를 통한 정상·부정 호출을 하네스의 기존 Quad-Assertion 판정에 편입한다. 시나리오 기대값은 구현이 아니라 본 명세에서 독립적으로 도출한다.

## 2. 파급 범위와 무영향 근거
- **변경**: `internal/harness/catalog/g8_mcp_adapter.go` [신규], 카탈로그 메타데이터(총 시나리오 수 갱신).
- **무영향**: `E2E-01`~`E2E-32`의 판정 기준은 변경하지 않는다.

## 3. 신규 시나리오 명세
| ID | 시나리오 | 기대 Exit | 핵심 증거 |
|:---:|---|:---:|---|
| `E2E-33` | 읽기 토큰으로 `file_read` 정상 호출 | 0 | 내용 반환, `pep.allow` 감사 |
| `E2E-34` | 읽기 토큰으로 `file_write` 시도 | 12 | 스코프 부족 사유, 파일 무변화 |
| `E2E-35` | 만료 토큰 호출 | 11 | 만료 사유, 파일 무변화 |
| `E2E-36` | `../` 경로 탈출 시도 | 13 | Jail 거부 코드, 파일 부작용 0 |
| `E2E-37` | Grant 회수 후 호출(토큰은 미만료) | 12 | 실시간 PDP 거부 |
| `E2E-38` | `_meta.authz_token` 누락 | 14 | 자식 프로세스 미기동, 감사 사유 일치 |
| `E2E-39` | 알 수 없는 도구(`shell_exec`) 호출 | 14 | 자식 프로세스 미기동 |

> 정확한 종료 코드 숫자는 구현 착수 전 `domain` 종료 코드 정의와 대조해 이 표를 확정한다. 확정 전에는 임의로 채우지 않는다.

모든 시나리오는 Quad-Assertion(종료 코드, 파일 무변화, 감사 사유 코드, 출력 비오염)과 해시 체인 `VALID`를 만족해야 한다.

## 4. 인수 테스트 시나리오

|:---:|---|---|

| TC-050-02 | 시나리오 결과를 의도적으로 뒤집는 mutation(허용↔거부) | 해당 시나리오 `FAIL` (동어반복 방지) |

## 5. 4층위 검증 기준
1. 시나리오 단위 테스트 PASS
2. `run --scenario E2E-33..39` 100% PASS
3. 감사 해시 체인과 workspace 무변화 확인
4. 기존 32대 회귀 0건
