## 1. 목적 및 배경
어댑터 구현 전에 도구 이름과 도메인 액션의 매핑, 프레임 스키마, 금지 의존 경계를 코드로 고정한다. 이후 단계가 이 명세 밖으로 나가지 못하게 AST 가드레일을 먼저 세운다.

## 2. 파급 범위와 무영향 근거
- **변경**: `internal/mcp/protocol.go` [신규] (프레임·도구 매핑 타입), `internal/harness/architecture_test.go` (`TC-090-01` 추가).
- **무영향**: 기존 패키지 공개 계약 변경 없음. 신규 패키지는 아직 어디에서도 호출되지 않는다.

## 3. 세부 명세
1. 도구 화이트리스트: `file_read` → `domain.ActionFileRead`, `file_write` → `domain.ActionFileWrite`. 그 외는 `ErrUnknownTool`.
2. 인자 스키마: `path`(필수, 문자열), `data`(`file_write`에서만 필수). 알 수 없는 필드는 거부한다.
3. 토큰: `params._meta.authz_token` 필수. 누락이면 거부한다.
4. 프레임 크기 상한과 JSON-RPC 필드(`jsonrpc == "2.0"`, `id`, `method`) 검증 규칙을 정의한다.
5. AST 가드레일 `TC-090-01`: `internal/mcp`는 `os`(파일 함수), `internal/authz/pdp`, `internal/authz/pip`, `internal/jail`, `internal/authn/keys`를 import하지 않는다.
