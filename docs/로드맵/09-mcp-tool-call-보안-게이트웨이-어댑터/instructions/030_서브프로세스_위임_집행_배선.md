## 1. 목적 및 배경
`Executor` 구현체가 `tools/call`을 기존 `orchestrator.SubprocessSpawner`로 위임해, 어댑터 프로세스가 아닌 격리 자식 프로세스에서 PEP를 통과해야만 파일 I/O가 일어나게 한다.

## 2. 파급 범위와 무영향 근거
- **변경**: `internal/mcp/executor.go` [신규], `internal/cli`의 `mcp serve`에서 [`internal/app/builder.go`](../../../../internal/app/builder.go) 합성 루트를 통해 Spawner 주입.
- **무영향**: `SubprocessSpawner`와 `subagent worker`의 프로토콜은 변경하지 않는다. 신규 집행 경로를 만들지 않는다.

## 3. 세부 명세
1. `tools/call` 인자와 `_meta.authz_token`을 `SubagentRequest`(TraceID, Token, Action, FilePath, Data)로 변환한다.
2. `TraceID`는 요청마다 생성한다. 호출자가 지정한 값은 신뢰하지 않거나 검증 후 사용한다.
3. 자식 프로세스의 `SubagentResponse`와 종료 코드를 수거해 040 단계의 매핑 입력으로 전달한다.
4. 자식 환경변수는 기존 `SanitizeEnv`를 그대로 적용한다.
5. 어댑터 프로세스는 workspace와 Zone A/B에 대한 읽기·쓰기 경로를 갖지 않는다(`TC-090-01`로 유지).

## 4. 인수 테스트 시나리오
| ID | 입력 | 기대 결과 |
|:---:|---|---|
| TC-030-01 | 유효 읽기 토큰 + `file_read` | 자식이 파일을 읽고 내용 반환, 종료 코드 0 |
| TC-030-02 | 읽기 토큰 + `file_write` | 자식 종료 코드 12, 파일 무변화 |
| TC-030-03 | 5개 동시 `tools/call` | 단일 `audit.jsonl` 해시 체인 유효 |
| TC-030-04 | 어댑터 프로세스 파일 접근 추적 | workspace 직접 I/O 0건 |

## 5. 4층위 검증 기준
1. `go test -race ./internal/mcp ./internal/orchestrator` PASS
2. `audit verify`로 해시 체인 `VALID`
3. `go test ./internal/cli` 파이프 통합 PASS
4. `go test ./...` 회귀 0건
