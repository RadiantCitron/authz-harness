## 3. 사전 점검 (Pre-Mortem)

| 위험 | 방어책 |
|---|---|
| 문서의 코드 설명이 실제 파일 경로·함수명과 어긋남 | 모든 코드 참조를 상대경로 마크다운 링크로 작성하고 링크 유효성 및 실제 시그니처 일치 여부를 전수 검사 |
| 설명이 피상적인 요약에 그쳐 깊이 있는 코드 분석에 도움이 안 됨 | 각 패턴마다 ① 해결하려는 문제(Without Pattern), ② 실제 코드 구조(With Pattern), ③ 핵심 불변식 및 테스트 포인터를 함께 수록 |

## 4. 4층위 검증 설계

| 층위 | 대상 | 방법 |
|:---:|---|---|
| 1 | 링크 및 경로 무결성 | `docs/교보재/*.md` 내 모든 상대경로 링크 대상 파일 실존 검사 |
| 2 | 시그니처 일치성 | 교보재에 인용된 인터페이스·함수명이 실제 Go 코드와 100% 일치하는지 대조 |
| 3 | 상태 무변화 | `git diff -- "*.go"`가 0줄임을 확인 |
| 4 | 전체 통합 확인 | `go test -race ./...` 통과 유지 |
