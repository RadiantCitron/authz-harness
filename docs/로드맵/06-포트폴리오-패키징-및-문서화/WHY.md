## 1. 왜 이 로드맵을 하는가? (Why)

아무리 정교하고 강력한 엔진을 만들었더라도, **"문서가 없거나 읽기 힘들어서 1분 안에 시연을 돌려보지 못한다면"** 세상의 어떤 면접관이나 테크 리드도 그 진가를 알아챌 수 없습니다.

바쁜 테크 리더들은 수많은 포트폴리오와 코드를 검토합니다. 그들에게 코드를 한 줄씩 뜯어보며 설계를 추측할 여유는 없습니다. 그들이 원하는 것은 분명합니다:
1. **"이 프로젝트는 도대체 왜 만들었는가? 어떤 문제를 풀기 위함인가?"**
2. **"클론해서 바로 실행해볼 수 있는가? 결과가 한눈에 보이는가?"**
3. **"왜 이렇게 설계했는가? 어떤 공격과 경계 상황을 막기 위해 이런 구조를 택했는가?"**

만약 최상위 `README.md`가 텅 비어 있거나, 장황한 설명만 있고 정작 `run` 명령 한 번에 시나리오가 돌아가지 않는다면 수백 시간 동안 구현한 보안 아키텍처는 침묵 속에 묻히고 맙니다.

본 06번 로드맵은 우리가 00번부터 05번까지 피땀 흘려 쌓아 올린 모든 아키텍처적 가치(OAuth 2.1, 최소 권한 축소 위임, 3-Zone 상태 격리, 감사 증거 무결성, 30대 공격 방어 하네스)를 **누구나 1분 안에 직관적으로 이해하고 눈앞에서 재현할 수 있는 완벽한 패키지**로 완성하기 위해 시작합니다.

## 2. 왜 화려한 미사여구 대신 '관찰 가능한 증거'를 전면에 내세우는가?

소프트웨어 엔지니어링 포트폴리오에서 가장 경계해야 할 것은 "자화자찬"과 "공허한 주장"입니다.
- "엔터프라이즈급 완벽한 보안 시스템을 구축했습니다"라는 말은 아무것도 증명하지 못합니다.
- 반면, **"토큰 변조, 권한 회수 경합, 디렉터리 탈출 등 30가지 공격을 퍼부었을 때 단 1바이트의 비인가 수정 없이 표준 종료 코드와 감사 사유로 방어 성공했음을 120ms 만에 전수 검증했습니다"**라는 문장은 강력한 기술적 설득력을 가집니다.

우리는 추상적인 설명 뒤에 숨지 않습니다.
- 터미널에서 실제로 출력되는 6단계 관문 상태 다이어그램,
- 4가지 보안 질문을 동시에 통과해야만 PASS를 주는 Quad-Assertion 판정표,
- 감사 장부의 해시 도장(Hash Chain)이 변조를 적발해내는 실제 로그를 가감 없이 전면에 배치합니다.

이를 통해 읽는 사람이 문서를 읽는 순간 "아, 이 개발자는 요구사항과 현실의 차이를 알고, 말뿐이 아닌 실제 테스트 증거로 보안을 증명하는 엔지니어구나"라는 확신을 갖도록 만듭니다.

## 3. 왜 '1분 퀵스타트'와 '부정 테스트의 역설'을 강조하는가?

1. **1분 퀵스타트 (1-Minute Quickstart)**:
   - 복잡한 Docker 컨테이너를 띄우거나, 클라우드 계정을 만들거나, 무거운 데이터베이스를 깔아야만 돌아가는 프로젝트는 실행 단계에서 탈락합니다.
   - 단 하나의 Go 명령어(`go run ./cmd/authz-harness run --scenario all`)만으로 30개의 복잡한 인증·인가·격리 시나리오가 단 1초도 안 되어 일괄 완주되는 경험을 선사합니다.
2. **부정 테스트의 역설 (Paradox of Negative Testing)**:
   - 보안 시스템의 진정한 가치는 "정상 요청을 통과시키는 것"보다 **"비정상적이고 악의적인 요청을 의도된 이유로 정확히 거부(Deny)하는 것"**에 있습니다.
   - 초보자는 프로세스가 에러 코드(11~15)를 뱉고 종료하면 "테스트가 실패한 것 아닌가?"라고 오해하기 쉽습니다.
   - 우리는 시각적인 6단계 관문 파이프라인과 친절한 한국어 해설을 통해 **"왜 이 실패가 시스템을 지켜낸 성공인가"**를 명쾌하게 설명합니다.

## 4. 왜 딱 이 정도 범위까지만 하는가? (Why this scope)

본 06번 로드맵은 코드베이스에 새로운 기능이나 복잡한 모듈을 더 이상 추가하지 않습니다.
- 이미 00번부터 05번까지 핵심 엔진과 30대 시나리오 하네스가 100% 견고하게 완성되어 있습니다.
- 이제 필요한 것은 기능을 더 늘리는 것이 아니라, **이미 완성된 구조를 가장 정직하고 투명하게 보여주는 최상의 문서화와 시연 가이드, 그리고 전 계층 테스트(L1~L5)의 최종 무결성 결산**입니다.
- 기능을 더 덕지덕지 붙이는 것은 아키텍처의 단순성과 명료함을 해칠 뿐입니다.

이번 06번 로드맵의 완성은 **"누구나 복사해 실행할 수 있는 명령어 한 줄로 시작하여, 시스템의 신뢰 경계와 30가지 방어 증거를 5분 안에 납득할 수 있는 포트폴리오의 최종 완성"**입니다.
