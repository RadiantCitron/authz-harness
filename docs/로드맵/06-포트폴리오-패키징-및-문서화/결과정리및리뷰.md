## 2. 5대 핵심 아키텍처 성과

### 1) NIST SP 800-162 기반 인가 분리 (PAP / PIP / PDP / PEP)
- **결정(PDP)과 집행(PEP)의 물리적 분리**: 정책 결정 엔진(`pdp`)은 상태와 요청만을 받아 오직 `Allow/Deny + Reason`만을 반환하는 순수 함수적 설계를 달성하였으며, 파일 I/O 및 디스크 쓰기 부작용은 집행점(`pep`)이 전담합니다.
- **실시간 활성 권한 대조 (Anti-TOCTOU)**: 토큰 서명이 유효하더라도 I/O 실행 직전 Zone B `grants_state.json`의 실시간 활성 여부와 Subject Epoch 번호를 파일 잠금(`flock`) 하에 원자적으로 재검증하여 권한 회수 무력화 공격을 0.001초 만에 방어합니다.

### 2) OAuth 2.1 & RFC 8693 수학적 최소 권한 축소 위임 (Downscoping)
- **부분집합 불변식 ($S_{child} \subseteq S_{parent}$, $exp_{child} \le exp_{parent}$)**: 팀장이 자식 에이전트에게 권한을 위임할 때 부모의 범위를 초과하는 스코프나 수명을 요구하면 토큰 교환기(`exchange`)에서 즉시 차단합니다.
- **위임 계보 추적 (`act` 클레임)**: 자식 토큰에 부모의 `sub`를 Actor 클레임으로 각인하고 최대 위임 깊이(`max_depth = 2`)를 강제하여 무분별한 다단계 재위임을 통제합니다.

### 3) 3-Zone 물리·논리 상태 격리 토폴로지
- **Zone A (`0600` Private)**: 서명 개인키(`signing_keys.priv.json`)와 자격증명을 하위 워커로부터 완전히 은닉.
- **Zone B (Public Read-Only)**: 서명 검증 키 링(`jwks.pub.json`), 활성 권한 원장, Replay 블랙리스트를 파일 잠금(`flock`)으로 관리.
- **Zone C (Sandboxed Jail)**: `./workspace` 디렉터리 내에서만 파일 읽기/쓰기를 허용하고, 상대경로(`../`) 및 심볼릭링크 탈출 시도를 원천 차단.

### 4) Clean Env & Stdin JSON 파이프 기반 OS 서브프로세스 격리
- 고루틴(Goroutine)의 힙 메모리 공유 위험을 배제하고, `os/exec`를 통해 자식 OS 프로세스를 완전히 독립된 가상 메모리 공간으로 기동합니다.
- 부모의 민감한 환경변수를 일체 상속하지 않는 Clean Env 상태에서 오직 `stdin` 단일 JSON 프레임으로만 토큰을 안전하게 주입합니다.

### 5) 관측성의 삼분 (Tri-Separation) & Strict Fail-Closed 해시 체인
- **Stdout**: 초보자용 6단계 관문 상태도 및 한국어 역설 해설.
- **Stderr**: 개발/운영 디버깅용 정밀 구조화 로그 (`log/slog`).
- **Audit JSONL**: 이전 이벤트의 SHA-256 해시값(`prev_hash`)을 체이닝하여 단 1행의 변조도 사후 적발하며, 감사 디스크 기록 실패 시 파일 쓰기를 즉각 중단하는 Fail-Closed를 완벽히 준수합니다.

## 3. 5계층 테스트 피라미드 및 Quad-Assertion 실증 결과

본 프로젝트는 단순히 기능이 돌아가는 것을 넘어, **"의도된 실패가 정확한 종료 코드와 감사 사유로 실패함"**을 5계층 피라미드로 증명했습니다:

| 층위 | 테스트 스위트 | 주요 검증 내용 | 실측 결과 |
|:---:|---|---|:---:|
| **L1** | 단위 테스트 (`internal/...`) | 테이블 주도 PDP 결정표, 클레임 파싱, 부분집합 검증 | **100% 통과 (0.1초)** |
| **L2** | 보안 경계값 테스트 | Workspace Jail 경로 정규화, 토큰 헤더 변조 방어 | **패닉 0건, 탈출 0건** |
| **L3** | 동시성 경합 테스트 (`-race`) | 17개 전 패키지 동시 I/O, TOCTOU 권한 회수 경합 | **Data Race 0건** |
| **L4** | 블랙박스 CLI 계약 테스트 | 컴파일된 바이너리(`bin/authz-harness`) 표준 종료 코드(0, 11~16) | **100% 일치** |
| **L5** | 30대 E2E 시나리오 하네스 | 7대 그룹 30개 전 시나리오 Quad-Assertion 4중 불변식 판정 | **30/30 PASS (86.3ms)** |

### Quad-Assertion 4중 불변식 검증 결과
- **Exit Code Assert**: 30개 시나리오 전 항목 기대 표준 종료 코드(`0`, `11`~`15`) 100% 일치.
- **File Mutation Assert**: 거부(Deny) 시 대상 파일 시스템에 단 1바이트의 비인가 수정도 발생하지 않음(0-Mutation) 증명.
- **Audit Reason Assert**: 감사 장부에 기록된 `Decision` 및 `Reason` 코드가 의도된 도메인 상수와 100% 일치.
- **Hash Chain Assert**: 감사 로그 체인 무결성 사수 및 원시 토큰 비노출(Zero-Leakage) 증명.

## 5. 향후 확장 가능성 (Future Scope)

본 하네스는 로컬 단일 머신 환경에서의 완전한 권한 분리를 증명하였으며, 향후 대규모 엔터프라이즈 환경으로 다음과 같이 자연스럽게 확장될 수 있습니다:
1. **분산 중앙 IdP 연동**: Zone A의 Ed25519 서명 키 저장소를 HashiCorp Vault 또는 AWS KMS와 결합하여 네트워크 기반 원격 토큰 발급 지원.
2. **eBPF 기반 커널 레벨 Jail 강화**: macOS/Linux의 사용자 공간 파일시스템 경로 정규화(`filepath.EvalSymlinks`)를 넘어, eBPF LSM(Linux Security Module)을 통한 커널 레벨 시스템 콜 인터셉트 적용.
3. **분산 감사 머클 트리 (Merkle Ledger)**: 단일 파일 SHA-256 해시 체인을 분산 머클 트리로 확장하여 멀티 노드 감사 증적 상호 검증 지원.
