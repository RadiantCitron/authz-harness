## 1. 목적 (Context & Why)

본 지시서는 면접관, 수석 아키텍트, 기술 평가자 앞에서 **5분 안에 시스템의 문제의식과 설계 청사진을 명쾌하게 전달하고, 8대 핵심 라이브 CLI 시연을 통해 보안 불변식이 실제로 작동함을 증명하며, 심층 기술 질문에 완벽히 방어할 수 있는 공식 시연 가이드(`docs/DEMO_GUIDE.md`)**를 작성하는 작업이다.

보안 및 포트폴리오 불변식에 따라:
1. **5분 엘리베이터 피치 (5-Minute Elevator Pitch)**:
   - "왜 만들었는가? (배경)" $\rightarrow$ "어떻게 풀었는가? (아키텍처)" $\rightarrow$ "무엇으로 증명했는가? (30대 시나리오)"의 3단 논법으로 면접관의 관심을 즉시 사로잡는다.
2. **8대 핵심 라이브 CLI 시연 시나리오 (Live Demonstration)**:
   - 단순 자동 스크립트 외에, 면접관이 보는 앞에서 직접 터미널에 입력하고 관찰할 수 있는 8단계의 결정론적 시연 흐름을 명령어와 기대 출력으로 제시한다.
3. **5대 심층 아키텍처 질문에 대한 방어 논리 (Rigorous Q&A Defense)**:
   - "왜 PDP/PEP 분리인가?", "왜 OS 프로세스 격리인가?", "왜 해시 체인 기반 감사인가?", "왜 RFC 8693 축소 위임인가?", "TOCTOU 경합은 어떻게 막는가?"에 대해 NIST SP 800-162 및 RFC 표준 기반의 깊이 있는 답변을 집약한다.
4. **실제 CLI 동작과의 100% 일치 (Zero Discrepancy)**:
   - 가이드에 적힌 모든 명령어(`keys`, `grant`, `token`, `pep`, `run`)는 실제 바이너리 및 Go 코드와 완전히 일치하여 복사-붙여넣기 시 즉시 재현되어야 한다.

## 3. 세부 챕터별 작성 명세

### 3.1 5분 엘리베이터 피치 (Elevator Pitch)
- **1분 (배경/위기)**: LLM 멀티 에이전트 환경에서 오케스트레이터가 자식 에이전트에게 전체 권한을 넘기거나, 중간에 권한이 회수되었는데도 탈취된 토큰으로 I/O를 수행하는 엔터프라이즈 보안 사각지대 설명.
- **2분 (아키텍처)**: OAuth 2.1 워크로드 인증, Zone A/B/C 3-Zone 상태 토폴로지, NIST SP 800-162 PAP/PIP/PDP/PEP 4대 분리, RFC 8693 최소 권한 축소 위임 해법 설명.
- **2분 (증명/하네스)**: 단순히 "돌아간다"가 아니라, 토큰 변조·키 폐기·시간 만료·디렉터리 탈출 등 30대 공격을 퍼부었을 때 파일 0바이트 무변화와 표준 종료 코드로 방어함을 Quad-Assertion으로 증명한 하네스 성과 소개.

### 3.2 8대 핵심 라이브 CLI 시연 시나리오
실제 CLI 바이너리로 즉시 실행 가능한 순차적 시연 명령어와 기대 출력을 수록:
1. `keys rotate`: 새 Ed25519 서명 키 생성 및 이전 키 보존 (`key-v1` $\rightarrow$ `key-v2`).
2. `grant create` & `token issue`: `worker-01` 주체에게 `file:read,file:write` 권한 부여 및 서명된 Bearer 토큰 발급.
3. `pep write`: 발급된 토큰으로 `./workspace/report.txt` 파일 쓰기 성공 및 감사 이벤트 기록.
4. `token exchange`: 원본 토큰을 `file:read` 전용으로 축소 위임(Downscoping)한 자식 토큰 생성.
5. 축소 위임 위반 시도: `file:read` 자식 토큰으로 `pep write` 시도 $\rightarrow$ Exit Code `12` (`EXIT_AUTHZ_DENIED`, `TOKEN_INSUFFICIENT_SCOPE`) 즉각 차단.
6. `grant revoke`: 중앙에서 원본 Grant 회수 $\rightarrow$ 기존 토큰으로 I/O 시도 시 Exit Code `12` (`GRANT_REVOKED`) 즉각 차단.
7. 경로 탈출 공격: `../../etc/passwd` 상대 경로로 쓰기 시도 $\rightarrow$ Workspace Jail이 감지하여 Exit Code `13` (`EXIT_PATH_VIOLATION`) 차단, 파일 부작용 0바이트 유지.
8. 자동 하네스: `run --scenario all` 및 `--output-format explain`으로 30대 시나리오 1초 완주 화면 시연.

### 3.3 5대 심층 아키텍처 Q&A (Technical Defense)
- **Q1. PDP와 PEP의 물리적 분리**:
  - PDP는 순수 상태 기반 결정기(`Request -> allow/deny + reason`), PEP는 실행 직전 문지기.
  - PDP에 파일 I/O나 개인키가 침투하면 단일 책임 원칙(SRP)이 깨지고 테스트 격리가 불가능해짐.
- **Q2. OS 프로세스 분리 vs 고루틴**:
  - 멀티 에이전트 환경에서 비신뢰 서브에이전트 코드가 메모리를 공유하면 전역 변수 변조, 힙 메모리 스누핑, 개인키 탈취 위험 존재.
  - OS 서브프로세스 분리와 `stdin` JSON 프레임 전달로 완벽한 메모리 격리 달성.
- **Q3. 해시 체인 감사 원장 & Strict Fail-Closed**:
  - 일반 로그는 사후 변조가 쉬워 법적 책임 회피 가능. SHA-256 `prev_hash` 연결로 단 1행의 변조도 적발.
  - 감사 로그 쓰기 실패 시 I/O를 허용(Fail-Open)하면 감사 없는 비인가 작업이 발생하므로, 즉시 중단(Fail-Closed) 사수.
- **Q4. RFC 8693 수학적 부분집합 축소 위임**:
  - $S_{child} \subseteq S_{parent}$ 및 $exp_{child} \le exp_{parent}$ 불변식을 교환 시점에 엄격히 검증하여 부모보다 큰 권한 위임을 원천 차단.
- **Q5. TOCTOU (Time-of-Check to Time-of-Use) 방어**:
  - 토큰 유효성만 보고 I/O를 허용하면 회수된 권한을 막을 수 없음. PEP가 I/O 직전 Zone B `grants_state.json`의 활성 여부와 Subject Epoch를 파일 잠금(`flock`) 하에 원자적으로 재확인.
