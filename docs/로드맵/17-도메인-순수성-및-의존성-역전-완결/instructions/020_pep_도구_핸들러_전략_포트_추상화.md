## 1. 목적 및 배경

Phase 16에서 추가된 3종 도구 가드(`jail`, `netguard`, `execguard`)와 실행 로직을 소비자 소유 전략 포트 인터페이스(`pep.ToolHandler`)로 깔끔하게 추상화한다.
이를 통해 [`internal/authz/pep/gateway.go`](../../../../internal/authz/pep/gateway.go)는 도구 종류가 늘어나도 파이프라인 코드가 바뀌지 않는 **개방-폐쇄 원칙(OCP)과 전략 패턴(Strategy Pattern)**의 모범 구조를 갖추게 된다.

---

## 2. 파급 범위와 무영향 근거

- **변경**:
  - `internal/authz/pep/handler.go` [신규]: `ToolHandler` 인터페이스(`ValidateAndNormalize`, `ExecuteIO`) 및 기본 핸들러 어댑터(`FileToolHandler`, `NetToolHandler`, `ExecToolHandler`) 정의
  - `internal/authz/pep/gateway.go`: Gate 2c 및 Stage 5에서 등록된 `ToolHandler` 전략을 호출하도록 단순화(`TC-060-04` 단일 `return` 유지)
- **무영향**:
  - 기존 `pep.Config{Jail: ..., NetGuard: ..., ExecGuard: ...}`로 생성해도 내부에서 기본 `ToolHandler` 맵으로 자동 래핑되므로 기존 호출부는 100% 호환된다.

---

## 3. 세부 명세

1. **`ToolHandler` 인터페이스**:
   - `ValidateTarget(rawResource string, data []byte) (canonicalResource string, safeTarget string, err error)`: Gate 2c 경계 및 스키마 검증 수행.
   - `Execute(ctx context.Context, safeTarget string, data []byte) (outData []byte, bytesRead int, bytesWrote int, err error)`: Stage 5 실제 도구 실행 수행.
